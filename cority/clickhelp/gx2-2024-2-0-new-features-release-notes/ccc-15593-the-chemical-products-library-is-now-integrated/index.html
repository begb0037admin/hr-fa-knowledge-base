CCC-15593 : The Cority 'Chemical Products Library’ is now integrated with 3E through API

Opt-In

The integration enables users to create new, and update existing, Chemical Product records (single or in bulk) with SDSs through requests made to the Cority 'Chemical Products Library', or if necessary, to 3E.

The changes made in order to support this integration include:

  • Updates to the functionality of the Cority 'Chemical Products Library'
  • New fields added to applicable data and look-up tables
  • Updates to the Cority REST API

Client instances of GX2 will be connected to the Cority 'Chemical Products Library' by use of a microservice. The 'Chemical Products Library' will connect to 3E through API. Client instances will not connect directly to 3E. (This might not be necessary for the docs.)

Clients pay through a subscription. The microservice keeps track of our chemical management clients and the products in which each are interested (keeps track of each total subscription). Updates to the Cority 'Chemical Products Library' get pushed to each client instance based on their subscription. Clients are charged per SDS for our chemical management service. 
Note: A single product in more than one language will be charged for each language (see sourcing and indexing below). (This whole thing might not be necessary for the docs.)

The Cority 'Chemical Products Library' integration with 3E will improve the quality of our chemical products data, because 3E is a provider that specializes (is a leader) in chemical product content management. (This might not be necessary for the docs.)

The integration will also provide faster sourcing and indexing times.
sourcing - locating the data (and sheet)
indexing - parsing the data into records within the library

Higher-quality, more accurate data along with faster sourcing and indexing will reduce issues and Support calls.

Updates to 3E content will get pushed to the Cority 'Chemical Products Library', for any records that have been linked between the two.

Workflows

Searching the library - If you need to locate a chemical product, you would first search your own library simply by using Cority standard list view search tools in your Chemical Products list view.
If you do not find the product there, you can then search the Cority 'Chemical Products Library' from the same list view using the 'Search Library' action.
Note: That action can be restricted from a user by not granting the user's role the chemproduct.searchlibrary security action and/or by not providing a value for the 'GUID for SDS Library' system setting.
Clicking the action will open the 'Search Library' dialog box for entering chemical product search criteria. The dialog box is not configurable.
The more criteria you are able to specify, the narrower the search will become. At least one criterion is required.
The search will provide a list of items or a single item, based on the search criteria provided.
From the search results list, you can preview an SDS (if available), open a product in a fixed layout (from which you can also preview the SDS), or using the Actions menu, refine the search, clear it, perform another new search, or add the product to your own Chemical Products library.  The latter will first add the product to the queue, if there are others, and then add and synch it with your library.
'Request Product' is also an action on this dialog box's Actions menu. If you are a client who needs your Chemical Product additions to go through a change request process, then you should disable the 'Add Product' action on the dialog box (by not granting the chemproduct.searchlibrary security action to any of your users) and instead use the 'Request Product' action only, which will open a 'Chemical Product (MOC) Request' record pre-populated with the relevant product details. On that record, you would then add the location (for example) for which you want the chemical product approved and click Save. That will initiate your MOC approval process. The system will then only add the chemical product to your library if/when the MOC request is approved. If it does not get approved, it will not get added to your library.

Now the recommended Chemical Product Change (MOC) Request workflow though is slightly different. You should instead always start from the Chemical Product record within the Chemical Products module.
First search your own library from your Chemical Products list (see above). If the product is in your library and approved at one location (geographic location or facility, for example) but not approved for the location you require, then you would open the Chemical Product record itself, verify that the information is correct, and click the 'Start Request' button on the record. That will open a pre-populated Chemical Product (MOC) Request. On that Request record, select the location (geographic location, facility, whichever) for which you want approval and click Save. That will initiate your MOC approval process.

We also have a workflow you can use to communicate your need for a Chemical Product record (and SDS) and trigger the process to acquire it:

If product does NOT exist in your Chemical Products library or in the Cority 'Chemical Products Library', then you have to initiate a sourcing and indexing request, which will get sent to 3E. You do that by selecting the new 'Chemical Product (Source SDS)' layout (simplified for this workflow), creating a new Chemical Product record from that layout, adding at minimum the required information, saving the new record, and then clicking the 'Send to Cority' button on the record.
Note: There is a Language field. You'll need to create a separate request for each language in which you want the product because every language has its own product record with unique ID.
If you have the SDS, you can add it too, prior to clicking the 'Send to Cority' button.
While waiting for the sourcing and indexing request, you can kick of the MOC approval process using the 'Start Request' button from the same record (if, for example, you already have the SDS for approval). If you cannot kick off the approval process while waiting, due to your internal process requirements, you can simply wait for the sourcing and indexing to be completed. Sourcing and indexing can be fairly quick if 3E has the product in its library. If not, the process will take longer. 
Note: This process should only be used for requests that include a small-to-medium number of products. If you have a larger number of products in your request (1000, for example), please contact Cority Support for assistance.

Important: The new 'Chemical Product (Source SDS)' layout for sourcing and indexing requests has two Manufacturer fields, one that opens the existing look-up table (linked to the Cority 'Chemical Products Library'). If the manufacturer does not yet exist there, you will need to select the hard-coded '**** NOT FOUND IN LIST ****' value from the top of the list for that field, instead of a look-up value. You will then also have to provide the Manufacturer's name to the other 'Manufacturer (if not found)' field. 

When complete, the sourcing and indexing request will add the record to the Cority 'Chemical Products Library' and to your (the client's) library. Both records will be given the same unique identifier (ID). When the generated ID is added to the record, you will then know that the sourcing and indexing request is complete, the product is added to your library and synced with the Cority and 3E libraries, and the product record will receive any available updates going forward.

Note: It will only be updated going forward if it meets the criteria for auto-sourcing. If it meets the criteria for auto-sourcing, the record will automatically be marked for that using its 'Auto Source' check box.
The criteria for auto-sourcing is assessed and managed by a backend business rule, which ensures the following:
1) If a manufacturer's name was entered manually in the 'Manufacturer (if not found)' field (see above) and is not valid, then a valid one needs to be added by Cority to the Cority 'Chemical Products Library' (using a look-up table entry) and the the request submitted again manually by Cority. The record will not be marked valid for auto-sourcing until that is done and the indexing sourcing completed. This process is not visible to the client.
2) The product will not be published for public search in the Cority 'Chemical Products Library' if it is proprietary to the company.

If the client provided an SDS on the newly created Chemical Product record prior to the sourcing and indexing request, if available, the request will add a newer SDS to the record as well and mark the new one the default. 

As the Cority library grows, there will of course be less need for sourcing and indexing requests.

None of this above is available in myCority.

Chemical Products layouts (therefore records) now have extra fields to accommodate the breadth of data 3E will provide.
Note: The Ingredients field (Ingredients %, Low %, and High %) values are populated in the most conservative way for the associated calculations.
