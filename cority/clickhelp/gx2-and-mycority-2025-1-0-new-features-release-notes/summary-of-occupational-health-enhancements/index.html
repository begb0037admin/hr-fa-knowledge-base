Summary of Occupational Health Enhancements

The table below lists smaller design improvements we have made in the Occupational Health cloud. The items are organized by component and the components are arranged in alphabetical order. Descriptions of larger features follow the table.

ItemComponent(s)Description
CCC-9897Clinic Visit

On a Clinic Visit layout, in the 'Employee SEGs and Clearance' section/sublist, the 'Clearance Expiration Date' column now supports inline edit.

If a new 'Clearance Expiration Date' is provided there, the equivalent date will be updated accordingly in all other locations (on the corresponding 'Exposure Clearance' record, for example). If 'Clearance Expiration Date' is left blank (empty), the system will calculate the clearance expiry date, as expected.

'Clearance Expiration Date' has also been added to the 'SEG Clearance' modal box, so that it can also be edited while adding the clearance.

 

CCC-9208Clinic Visit

The following two new fields can now be added to custom versions of all 'Clinic Visit' layouts:

  • Clinic Visit To Be Reviewed By
  • Second Practitioner

Each field has a look-up selector to the Users table, filtered to Practitioner = True.

The look-up table has the following views:

  • Practitioners: All Active
  • Practitioners: All Active Internal
  • Practitioners: All Active Outsider
  • Practitioners: All Inactive
  • Practitioners: All (Default view)

The 'Clinic Visit To Be Reviewed By' field will not impact the existing Lock/Unlock functionality.

For each field, the equivalent column can be added to custom 'Clinic Visit' list views.

Similar to the Clinic Visit 'Practitioner' field, these fields cannot be prohibited through role configuration. However, they will not display if you do not add them to Clinic Visit layouts and views.  

Each is available as a merge field for Letters of the 'Clinic Visit' entity.

The fields can be reported on using Query Builder and Report Writer, are available for use in business rules and display rules, and can be populated/updated by import.

 

CCC-19911
Clinic Visit, Clinical Testing
In the Clinical Testing module (for 'Clinical Testing Sample', 'Drug Testing Sample', and 'Clinical Test Sample Battery'), users can now create/generate a barcode and print the corresponding label(s) with code to attach to the sample being shipped/submitted. 

To support this, a new 'QR/Barcode' field and 'Generate QR/Barcode' action can now be added to custom versions of the following layouts:
  • ML-000292
  • ML-000278
  • ML-000271
  • ML-000291
If the field is present on the layout and the new action is performed, the QR/barcode will auto-populate the field.
Beside the field, a read-only text box will show the previously configured linked task(s). 'Edit' and 'Print' buttons will also be provided. Note: The 'Print' button is disabled this release. That capability will be made available in a future release.
The new field can be used in Form Mapper (under the 'Clinic Visit' module), business rules, letters, and display rules.


Also, three new look-up table UDFs are now available for adding to custom versions of the 'Clinical Test Sample Battery' layout (ML-000278).
The equivalent columns can be added to corresponding list views.
The fields can be reported on using Query Builder and Report Writer, and are available for use in business rules and display rules.
For information on working with custom layouts, custom list views, or look-up tables, see the GX2 User Guide.

CCC-19620Clinical Testing

For the 'Clinical Test Trending Analysis Cross Tab' report, the clinical tests list in the results now respects the 'Test Sequence' set in (order they were added to) the battery in the 'Clinical Test Battery' look-up table, with any numbers in ascending order.

 

CCC-19154Medical Monitoring – Employee Diagnosis

A user of the Employee Diagnosis functionality can now capture more organization-specific data for reporting and data analysis.

 

To support this, the following new fields can now be added to custom versions of the Employee Diagnosis layouts (ML-000957):

  • 6 new alphanumeric (nvarchar, 1000 characters long) UDFs, numbered 1 through 6
  • 6 new date/time UDFs, numbered 1 through 6
  • 6 new flag (bit) UDFs, numbered 1 through 6
  • 6 new look-up table UDFs, numbered 1 through 6

Each of the new look-up table fields has a corresponding new look-up table. The look-up tables each have a default list view and layout with appropriate columns/fields, and each function as a typical GX2 look-up table.

 

For each new field, the equivalent column can be added to custom Employee Diagnosis list views.

The fields can be used in business rules, display rules, and workflows, and can be reported on using Query Builder and Report Writer.

Each of the new fields can be prohibited from user roles.

Values for the fields can be imported and are supported by the REST API.

CCC-14131Medical monitoring – Vital Signs

A user of the Vital Signs functionality can now capture more organization-specific data such as body fat mass, body fat percentage, skeletal body mass, triglycerides, glucose, basal metabolic rate, etc. for reporting and data analysis.

 

To support this, the following new fields can now be added to custom versions of the Vital Signs layout (ML-000785):

  • 8 new alphanumeric (nvarchar, 1000 characters long) UDFs, numbered 1 through 8
  • 6 new number UDFs, numbered 1 through 6
  • 6 new date UDFs, numbered 1 through 6
  • 6 new time UDFs, numbered 1 through 6
  • 6 new flag (bit) UDFs, numbered 1 through 6
  • 8 new look-up table UDFs, numbered 1 through 8

Each of the new look-up table fields has a corresponding new look-up table. The look-up tables each have a default list view and layout with appropriate columns/fields, and each function as a typical GX2 look-up table.

 

For each new field, the equivalent column can be added to custom Vital Signs list views.

Values for the fields can be imported and are supported by the REST API.
