CCC-15396: Published documents can now be archived

Opt-In

A user can now remove all the published versions of a controlled document with the new, single 'Archive Published Documents' action. 
The action can be added to custom versions of 'Document Control' layouts. 
To use the new action, the user's role must be granted the Documentcontrol.archive security action.
Otherwise, the action will be disabled.
If the user's role is granted the security action, but there are no published documents in the 'Doc Control Approval History' of the record, then the 'Archive Published Document' action will be visible but disabled. 
The action is available for use when at least one of the document status in 'Doc Control Approval History' is published and none of the documents has a status of archived.
The 'Archive Published Document' action is still available though, even if there are one or more documents in the 'Doc Control Approval History' with status of neither published nor archived. This occurs when version one of a document is published, but version two is still in the approval process and has not yet been published.
For the action to be available for use though, there must be at least one document in the 'Doc Control Approval History' that is both published and not archived.

There is a new, associated business rule for 'Document Control' named 'Archive Published Documents'. It will archive when the action is selected. Its method is 'ArchiveDocument'.
When triggered, all the versions of the published document (including any that were migrated) will be unpublished from My Favourites > Published Documents. After that, no user will be able to access the published documents associated with that record on either GX2 or myCority.
When triggered, a confirmation pop-up will display that reads, "Are you sure you want to archive this record? This action cannot be undone."

If the user clicks 'Yes':
  • The document will be archived.
  • Its 'Archived Date Time' will be set to the current UTC time and 'Archived By' will be set to the current user.
  • The document's status will be updated to 'Archived'.
    • In the 'Approval History' section, there will be a new entry for every published version, each with a status of 'Archived'.
    • The record history will be updated accordingly.
    • The following fields in 'Approval History' will be copied for the 'Archive Status' entry: Document Name, Revision Number, Publish Date, and Document Data Format. 
      • The following fields will be empty: Reason for Revision, Review Data, and Review Comments.
      • The following fields will be updated: Revision Date will be today ( the date of archiving), Reviewer will be the current user (the user archiving the document), and the Status will be 'Archived'.
  • The correct attachment(s) will be downloaded from the archived record in Approval History.
  • If the 'Archive Date Time' is set:
    • The workflow chevron on the top will be updated to 'Archived', regardless of whether or not it has been configured as part of the workflow.
      • This is only applicable when a workflow is configured in the layout. If a workflow is not configured, then there is no visual change to the layout. 
  • The record is locked.
    • On the main form a record archived message is displayed with the user name, date, and time (format determined by the 'Short Date Style' and 'Time Format' system settings).
  • Even after the record is locked, users with access to the Document Control record will be able to download and access the documents in the Approval History section, and view the approval history and all the metadata of the record.
    • Users with the permissions to access the record will be able to use the following buttons and actions:
      • New
      • Send Email
      • Actions
        • Print Form
        • Save Layout
        • Show Record History
        • Edit Layout
    • Users cannot use the following buttons or actions (they will be disabled):
      • Save
      • Delete
      • Begin Review
      • Update
    • And, on the 'Document Control Approval History' form:
      • Publish Document
    • And, on the 'Supporting Documents' sublist:
      • New
      • Delete
    • And, on the 'Supporting Documents' form:
      • New
      • Save
      • Delete
      • Lock Record
      • Unlock Record
  • Create, Update, Save, and Delete are also blocked/disabled for the Rest API and Import Utility.
When the document is archived, all expected updates will be made without requiring a manual refresh.

For bulk archiving, the user can create a business rule that calls the 'ArchiveDocument' method action and specifies multiple document control record IDs for archiving.
For time-based archiving, the user can create a business rule that calls the 'ArchiveDocument' method action, specifies one or more multiple document control record IDs, and has a time period set (either number of days or a specific date) for archiving the document records.

Also, a 'Revision Number' field has been added to the default 'Published Document' layout (ML-001261) and list view, so the user can now easily view the revision number of the published document through 'My Favorites'. The field cannot be reported on or imported.
