CCC-19486: Enhancements have been made to the applicability reassessment functionality

Opt-In

Enhancements have been made to the applicability reassessment functionality.

The functionality will pull Enhesa content into an applicability reassessment when:

  • A major change has been made to an applicable Enhesa requirement since the start date of the parent assessment.
  • A previously not applicable or unanswered Enhesa requirement was made applicable (and remains applicable) back to the start date of the parent assessment. 

The functionality allows clients to flag and monitor changes in applicability assessments, avoiding the need to re-run a full applicability assessment.

With the enhancements, the functionality will enable organizations to conduct major assessments on a schedule (for example, every three years) and periodic reassessments in between.

To support this, the following fields are now available for adding to custom versions of 'Single Question' look-up table layouts:

  • Enhesa Version - numeric
  • Enhesa Research Date - date/time
  • Enhesa Publication Date - date/time
  • Enhesa Change Type - enum, with the following potential values:
    • 0 - No Change
    • 1 - New Development
    • 2 - Explicit Regulatory Change
    • 3 - Repealing Change
    • 5 - Implicit Regulatory Change
    • 6 - Editorial Change that does not impact meaning
    • 7 - Improved Guidance / Analysis
  • Enhesa Change Description - nvarchar

The fields are read-only and will populate when a refresh of Enhesa requirements is initiated.

Also, the logic has been improved so that reassessments no longer generate duplicate questionnaires.

Note: The enhancements have not changed the workflow. Users will run applicability reassessments the same way they did prior to these updates.
