Form Designer

The Form Designer is available for all Advanced Workflows (WAB), including IncidentApp, and all Advanced Workflows (WAB)-based custom apps. The Form Designer allows you to edit the design of the forms used on each of the workflow steps, including:

  • Fields to display on the form for each step
  • Action buttons available at each workflow step
  • Conditions applied to fields and buttons which may change their state based on form inputs

The same underlying Form Template may be used at different steps in the workflow, with a different form design. In this way you can include or exclude fields, add initiators, edit action buttons, and modify conditions for each step, even if they share the same template.

 To access the Form Designer you must have Manage Workflow rights for all workflow types and be a member of the App Role FormsDesigner. Membership in this role is set in Apps Manager (Setup > Apps). Select the Role Memberships tab for the App.

To use Form Designer:

  1. Select Designer from the main menu button.

  2. Select the Form Type.
    The form types shown in the drop-down list correspond to the underlying Workflow Types.

    Status Settings: Optional. Configure custom color-coding for workflow tabs and status indicators. Status setting can be set individually for each workflow type. See Status Indicator Settings. Click Save to save settings. It is not necessary to load a form to apply the status settings.

  3. Select the Workflow Step to open a form for editing.

    The Form for the step will be loaded in edit mode.

Header Fields

The Header fields names in the right pane are the read-only informational fields that are displayed in the form header in the App.

Below see the header fields as they appear to the end user. Click the Info button   to hide/show header fields.


You can customize the header with fields of your choosing and specify default values for them, using macros to take values from other fields.

To define header fields:

  1. Drag a field you want to use onto the Header fields pane and drop it onto one of the four header field boxes.

  2. Select the plus (+) to show the field properties.

  3. In the Default Value field, type "{" to see the list of fields available to be used as macros. Select a macro for a field you want to use.
    You can concatenate macros to define the default value.

    For example, the default value for the Incident Name field can be concatenation of the Facility selected from the object selector, the Incident Type and the Incident Date:

    {Field::Object Selector}.{Field::EII-IncidentType}.{Field::EII-IncidentDate}

Fields

When the form is first opened in Designer it will include all the fields on the Form Template associated with the step. You can remove fields you want to hide, and add other types of fields and form components. By default, the first section is called "Form Fields".


The Fields that can be added to the form are shown in the left pane. Click the arrow on each category to view the fields.

  • Object Selector: The "Add and View Associated Objects" field allows users to associate a system model object with an item, or view associated objects as read-only. Select the field once it is on the form and then enable the appropriate object types.
  • Workflow includes the standard fields for workflows plus the form fields associated with the step. All fields on the form template are initially added to the form by default. Click the (x) to remove any fields you do not want to be on the form.

  • Object Fields (Division, Facility, Unit, POI, Requirement): Standard and custom fields for the objects associated with a workflow may be included on the form. The fields for each object type include all standard fields and any custom fields applied to that object type in the system. Fields are in read-only mode on the form. After being added to the form, the fields may then be used in Conditions.

  • Documents: The "Add and View Documents" field will place a Document upload button on the form, allowing users to upload documents. Uploaded documents are limited to 200 MB. Users must also have Edit permission on the document folder for the app. The location of the documents is defined in the App configuration file.

Search for components by name using the Search text box at top. The components are automatically filtered as you type.

To add an item to the form. drag and drop it onto the form where you want it, or click the plus sign to add it to the bottom of the form. See Add Field(s) for more information.

Add Section

Multiple sections can be created in a single form in Form Designer. Click Add Section to add a new section to the form. You can edit the section name by clicking the pencil icon. The section name can be up to 50 characters. You can change the order of the sections by moving them up and down in the Field Section.

Add Field(s):

Below see the Section Selector with section names as they appear to the end user.

To see a section in the Section Selector, the section must contain fields.

This feature allows users to access a list of sections and quickly navigate to the desired section. Click on the drop-down arrow to see all sections or select the desired section. You can also use side arrows to select the desired section.

You can add fields to a section by clicking Add Fields in the desired section.

To move fields from one section to another:

  1. Click Add Fields. The Add Field(s) window opens.
  2. Click the drop-down arrow in the left pane and select the desired section from the drop-down list of available sections.
  3. Click the drop-down arrow in the right pane and select the desired section from the drop-down list of available sections.

  1. In a pane, select a field that you want to move, or click Select All to move all fields in the pane.
  2. Use the right/left arrows to move the selected fields.

  3. Click Apply to apply changes without making them permanent. You can revert to the previously unsaved settings by clicking Reset.

  1. Click Save when you are done.

Select the plus (+) on the field button to view properties for the field.


Field properties include:

  • Label: The "caption" of the custom field is the default label value. You may edit the label by clicking the pencil icon.
  • Label size: Small, Medium, Large
  • Label color: Select from list of colors.
  • Help Text: Alt text that will appear on hovering over the field or selecting the help button. Use this to provide inline instructions or information for users.

  • Default Value: Default value displayed on loading. May be edited. Some macros are available to use in this field. Type "{" to see a list of fields on the form that may be used. Macros include {Today} for date fields, {Now} for time fields, and {Username}, as well as the values of other fields on the form. Values may be concatenated, subject to length restrictions.
  • Process default value when field is hidden: Allows default field value to be inserted in field even if field is hidden on the form. For more on hidden fields, see Using Hidden Fields.
  • Maximum Text Length: Maximum number of characters that can be entered. (May be less but not more than the allowable field type.)
  • Text pattern: You can use this field to impose a format validation. Some examples include:
    • Phone no (format 123-456-7890): ^[0-9]{3}-[0-9]{3}-[0-9]{4}$
      • Help text: "Please enter in 123-456-7890 format"
    • Phone No format (123) 456-7890: ^\([0-9]{3}\)\s[0-9]{3}-[0-9]{4}$
      • Help text: "Please enter in (123) 456-7890 format"
  • Read Only: Fields marked read-only will not be editable for users. (Note: This will override field permissions granted through the workflow type.)
  • Required when saving: When selected for fields in designer mode, the fields must be completed on the form to save the form.
  • Required when transitioning: When selected for fields in designer mode, the fields must be completed on the form to select an action that moves the workflow to the next step.
  • Required to close: When selected for fields in designer mode, the fields must be completed on the form before closing the workflow.

Closing a workflow is a status change and not a Workflow step transition. If "required when transitioning" is selected a user can still close a workflow without completing that field, unless "required to close" is selected. 

  • Reprocess on Source Field Value Change: When selected for fields in designer mode, Required for each field where default values can be updated in the WAB and need to be reprocessed (computed, recomputed, and written to the workflow). Conditions can be applied to this function see Defining Conditions for Forms.

Field values not retrieved from the server (offline, connective, etc), will not be reprocessed. 

The checkbox in front of the Reprocess on Source Field Value Change will be greyed out until Read Only is selected. .


Once Read Only is selected the checkbox in front of Reprocess on Source Field Value Change can be checked.

If the Default field value is empty, there will be an error message "The Default Value is empty. There is nothing to process for this field." Ensure a value is inputted in the Default value field.


  • Associated Object Type: When you add an object field to the form, you can choose the object type from which the value will be pulled. This is useful when there is more than one object type, such as the Facility and the employee POI used in the Incident App.

  • Enabling the GPS collection: To enable GPS collection, place two numeric fields on the Form Template then use the macros {GPS::Latitude} and {GPS::Longitude} in the Default Value field of the Form Designer.

Actions

Actions that can be added to the form are shown in the Actions section. Click the arrow to expand the Action section to display possible actions.

If you do not want a particular action to be an option on the form, you can remove it by clicking the (x) on the button.

You can edit the text on the button and choose the method to be used to assign the action from the Action properties. Select the Action to view and edit the properties from a sliding window.

Assignment Method

This method determines whether the user executing the action will be prompted to assign the destination step or if it will be automatically assigned.

Calculated: Prompts the user only if the user is not a role member of the destination step's role.

Automatic: Automatically assigns the user to the next action step. Select the destination user from one of the options:

  • Executing User: A destination step is assigned to the current user.
  • User That Completed Step: Select the step from the drop-down list. The step is assigned to a destination user associated with this step. If the selected step hasn't yet been completed, the user is prompted to select an assignee from the destination step's Role Members.
  • All Role Members: A destination step is assigned to all resolved Role Members for this step.
  • Specified Role: Select a Role from the drop-down list. A destination step is assigned to any role associated with the workflow type, even if the role is not associated with the destination step.

Manual: Manually assigns the user to the next action step according to the user's role:

  • All Role Members: The destination step can be assigned to all resolved Role Members.
  • Specified Role: Select a Role from the drop-down list. A destination step is assigned to any role associated with the workflow type, even if the role is not associated with the destination step.

For the Calculated and Manual assignment methods, additional settings are available:

  • Must Select Users Only: Only individual users can be selected, including from the expanded User Group.
  • Must Select One Entity Only: Only one User or one User Group can be selected.
  • Users may select any User in the system: Any user in the system can be selected, including those that are not in the workflow process.
  • Users may select any User Group in the system: Any Group in the system can be selected, including those that are not in the workflow process.

You can also create Conditions to control visibility of Action buttons. See Defining Actions.

Conditions

Conditions allow you to define conditional behavior for the form, based on selected field values. See Defining Conditions for Forms.

Editing the step names in the Workflow Type or changing the workflow name may cause you to lose previously designed forms in Form Designer.
