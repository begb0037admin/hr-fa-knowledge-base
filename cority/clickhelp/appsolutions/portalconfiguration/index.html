Portal Configuration

The purpose of the Portal is to make access to data and to data entry tasks easy and natural for different types of users. The Portal is comprised of Page Sets and Pages, which are designed to present a snapshot of relevant data stored in the database, targeted to users with different needs. Careful thought should be put into the way that you organize your Portal.

The type of data being presented and the needs of users will determine the way that you set up your Page Sets and Pages in the Portal.

Page Sets and Pages should not reflect the hierarchy that already exists in the system model (for example, a Page Set for each Division and Page for each Facility). Best Practice and the supported approach is to use Page Sets and Pages to represent a logical combination of programs and processes for the set of users who will be accessing them. For your end users, familiarity with the system hierarchy should not be necessary and may be confusing.

The system model hierarchy is represented, viewed, and navigated through the Page and Panel Object selectors. The Object Selectors are to used by designers but may be hidden or the hierarchy may be only partially visible to users. Cority strongly discourages any reproduction of the hierarchy in the form of Page Sets and Pages and does not intend to produce functionality to better support such a configuration. Enhancements relative to the hierarchy will continue to be made to the Object Selector.

The basic steps to configuring the Portal include:

  • Set up Portal Pages in the Page Library.
  • Configure the pages by deciding what data each page will use and how it will be presented to the user.

  • Add and configure the panels on each page which display the data.

    The data type determines the type of panel and the configuration options. These panel types are currently available:

    Numeric Data panels are used for presenting the data parameters and calculated data stored in the system. Both data viewing and data entry are supported.

    Workflow panels can be used to view and complete workflows and monitor workflow progress.

    Event panels can be used to view and complete event instances and monitor any related tasks.

    Task panels can be used to view and complete all types of tasks, including those not associated with workflows or events.

    Quick Links panels can be used to contain links to reports and other types of data, and to external resources.

 A user must be a member of the app role Portal Administrators to manage portal pages. Additionally, in order to edit and save pages they must have the Manage Portal right if they are not in the Administrators group.
