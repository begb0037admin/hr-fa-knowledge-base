Incident Process

The Incident report and monitoring process is modeled on a typical incident logging process in an organization. It includes several different types of incidents and allows for collecting the information appropriate to the incident type. In addition to collecting details of an incident, an investigation and root cause analysis can be performed and appropriate corrective actions can be created.

The IncidentApp process relies on a set of underlying workflows that describe the typical incident logging and follow-up process.

The basic order of events are:

  1. Log Incident: An individual logs an incident in the IncidentLog and identifies the basic incident type.

  2. Collect Details: According to the type of incident logged, a set of forms is available for collecting further details of the incident. The default forms provided include the following. Additional incident types and forms may be added.

    • Fire
    • Injury or Illness
    • Potential Hazard or Near Miss
    • Spill: Includes the ability to create an immediate Corrective Action.
    • Theft or Property Damage
    • Vehicle
    • Witness Details

  3. Investigation

    • Root Cause
    • Corrective Actions
    • Log Lost or Restricted Time for incident type Injury or Illness
  4. Review
