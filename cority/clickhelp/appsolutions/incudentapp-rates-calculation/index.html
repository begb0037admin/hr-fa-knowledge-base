IncidentApp Rates Calculations

OSHA safety rates are a highly important metric tool for evaluating your company’s safety program. One of the most important safety rates, used by nearly all Safety Managers, is the OSHA Incident Rate, more commonly called the Total Recordable Incident Rate (TRIR). Other important safety rates are: Lost Time Case Rate (LTCR); Days Away, Restricted or Job Transfer (DART) Rate; and Severity Rate (SR).

You can use charts to evaluate the rates' data from the IncidentApp. The charts are out-of-the-box non-configurable visualizations of these rates. The X axis is based on a quarterly aggregation of the Incident Date (UDF "EII-IncidentDate"). For more information on charts, see Charts. These charts are created based on formulas that are used in the App. Below are formula explanations for calculating the OSHA safety rates.

OSHA Incident Rate or Total Recordable Incident Rate (TRIR) Calculation

The OSHA TRIR is computed as follows: OSHA = ({Number of OSHA Recordable Cases} x 200,000) / {Number of Employee labor hours worked}

{Number of OSHA Recordable Cases} is the number of workflows, where: Workflow Type Name = 'EII-Incident' and UDF "EII-OSHARecordable" = TRUE 

{Number of Employee labor hours worked} is based on the calculation in the system model called "EII-Total Employee Hours (monthly)", which is usually computed using an input parameter called "Employee Hours". These calculations are found under each Facility and are aggregated in the charts.

Lost Time Case Rate (LTCR) Calculation

The LTCR is computed as follows: LTCR = ({Number of Lost Time Cases} x 200,000) / {Number of Employee labor hours worked}

{Number of Lost Time Cases} is a subset of the {Number of OSHA Recordable Cases}. Specifically, it only counts recordable incidents where the employee missed time at work as a result of the incident.

{Number of Lost Time Cases} is the number of workflows where the following conditions are met:

  • Workflow Type Name = 'EII-Incident'
  • UDF "EII-OSHARecordable" = TRUE
  • There exists an "EII-LostRestrictedTimeSummary" child workflow where the UDF "EII-MedicalStatus" = 'Lost Time' 
  •  There exists "EII-LostRestrictedTimeLog" (child workflow of the "EII-LostRestrictedTimeSummary") where the UDF "EII-MedicalStatus" = 'Lost Time'

For more explanation of how this data is entered in the flow of the IncidentApp, see Log Lost or Restricted Time.

Days Away, Restricted or Job Transfer (DART) Rate Calculation

The DART rate is computed as follows: DART = ({Number of DART Incidents} x 200,000) / {Number of Employee labor hours worked}

{Number of DART Incidents} is a superset of the {Number of Lost Time Cases}. Specifically, in addition to cases where the employee lost time at work as a result of the Incident, it also includes time where the employee had restricted duties or had to be transferred to a different job as a result of the Incident.

The number of Lost Time Cases is the number of workflows where the following conditions are met:

  • Workflow Type Name = 'EII-Incident'
  • UDF "EII-OSHARecordable" = TRUE
  • There exists "EII-LostRestrictedTimeSummary" child workflow, where UDF "EII-MedicalStatus" = 'Lost Time' or UDF "EII-MedicalStatus" = 'Restricted Time'
  • There exists an "EII-LostRestrictedTimeLog" (child workflow of the "EII-LostRestrictedTimeSummary") where the UDF "EII-MedicalStatus" = 'Lost Time' or UDF "EII-MedicalStatus" = 'Restricted Time'

Severity Rate (SR) Calculation

The SR is computed as follows: SR = {Total number lost workdays} / {Total number of recordable incidents}

This rate is different than the first three rates. It does not only compare Incidents that meet a particular criteria against the number of hours worked but goes deeper into the average number of lost days per recordable incident. 

The number of lost workdays is determined by the child workflows of the workflow type "EII-LostRestrictedTimeSummary". Each child workflow is given a medical status and an effective date. If the first child workflow has a medical status of "Lost Time", each day between its effective date and the next effective date where the record is no longer "Lost Time" is counted. If there is not a newer record, each new day that passes until today is included in the calculation.

For more explanation of how the number of lost days and number of restricted days are computed, see Lost Time Form.

The App saves these values to numeric custom fields in the background, but these values are not kept in sync (i.e., as time passes and no status updates are made, a value is not added to "Number of Lost Days"). The charts do not rely on these values, so they should be ignored. The App also properly displays them when the user loads the screen, so this is only an issue if those values are reported in the background. It is a best practice to ignore those values.
