System Model Associations

App Items may be associated with System Model objects. Object association is not required, but may be enabled and configured as needed.

The Primary Workflows can be associated with any Division, Facility, Unit or POI with the "Include" field set to true. The recommended implementation uses Facility objects to represent facilities. The "Include" field is defined in the App Config file. It is a true/false field with a typical name like "EIA-IncludeInMyApp" and a label like "Include in My App?".

To use system model associations, you will need to 1) add the object selector to the primary App Item form in Form Designer, and 2) in the main application enable the objects you want to use by applying the "Include" custom field and setting the value to true.

The default configuration for the App includes object association at the Facility level on creation of the workflow. You will only need to enable the system model objects with the custom field. 

To add the object association field to the form:

  1. In Form Designer, select the Form Type and the Step Name. Usually this will be the first step in the workflow, when the item is created.

    Adding the object selector to the initial step allows the selection to be made when a App Item is created (although it may be added at another step).

  2. In the left pane, among the Standard Fields, drag the Object Selector field to the form.

  3. Select the field to view the options in the right pane:

    Check the object type(s) the field is enabled for (Division, Facility, Unit, POI).

    Check Required to Save if you want the App Item to always be associated with an object. If object association is optional, uncheck the field.

    To allow multiple objects to be associated with a App Item, check Allow Multiple.

    If you want to be able to select objects based on hierarchy – for instance select a Facility and then a POI under that facility – you will need to add two object selectors to the form, one for the parent object (Facility) and one for the child object (POI). To ensure that only child objects for the selected parent are shown, check Enforce Hierarchy.

In order to be visible in the App, a system model object must have the "Include" field set to true. The field can be added to any custom field template.

To enable a system model object for the App:

  1. Select the object in the system model tree. Right click and choose Properties > Edit.

  2. In the custom fields section, check the box for Include in [name] App?.

  3. Click Save, then Confirm.

To remove a system model from use in the App, the "Include" field only needs to be disabled on the object properties. When the field is disabled, the object will not be visible for selection in the App. However, any records already created for the object will be preserved.

If the object is deleted from the system, all workflow records for that object will be deleted, too. If you want to preserve the workflow records, but no longer need the object for other uses, you can mark the object inactive using the Inactive Date field on the facility properties. The system model tree display will indicate it is no longer active.

To remove a system model object from visibility in the App:

  1. Select the object in the system model tree. Right click and choose Properties > Edit.
  2. In the custom fields section, uncheck the box for Include in [name] App?.
  3. Click Save, then Confirm.
