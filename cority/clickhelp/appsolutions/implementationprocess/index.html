Implementation Process

A summary of implementation process is provided below:

  1. Determine which incident types you need.
  2. Determine what fields you need for the forms for each selected incident type.
  3. Design the forms for each Incident Type, starting with the default forms provided.
  4. In Template Manager, edit the forms and create/add the new custom fields desired.
  5. Update the workflows to use the new version of any form templates you have edited. You will need to update the associated workflow/step, as well as the parent workflow to associate the new child workflow version.
  6. Delete or disable the child workflows you don't need.
  7. In Form Designer in the App, edit each form. Add the new custom fields you created. Add or edit conditions for display as desired.
  8. Add or delete the action buttons to be displayed for users.
  9. Configure the system objects (Facilities and POIs) to be used with the IncidentApp.
  10. Set up Users and User Groups to associate with Roles.
  11. Configure workflow Role overrides for each facility as appropriate.
