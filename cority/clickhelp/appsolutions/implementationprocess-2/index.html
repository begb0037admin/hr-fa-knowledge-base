Implementation Process

The following is a summary of the typical implementation process:

This summary is provided below as a guide.

  1. Determine what fields you need for the forms for each step of the main workflow and the child workflows (including child and grandchild workflows).
  2. In Template Manager, create the forms and custom fields for each step in the workflows.
  3. Create or update the default definition workflow types, associating the appropriate form templates to each step.
  4. Add initiators for the child workflows. Delete or disable any child workflow initiators you don't need.
  5. Contact Customer Support with the name of the application.
    The naming convention of the application must conform to following:
  • No spaces
  • No special characters, except for dashes and underscores. 
  1. In Form Designer in the App, edit the form for each step.
  2. Add or remove custom fields, and set display options for custom fields.
  3. Add or remove action buttons to the form.
  4. Set conditions on fields and action buttons as required.
  5. Configure the optional system objects to be used with the App.
  6. Set up Users/User Groups to associate with Roles.
  7. Configure Workflow Role Overrides for each facility as appropriate, if system model associations are to be used.
