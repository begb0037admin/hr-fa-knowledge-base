Email Notification Links to Portal Forms

Links to the Cority EMS, Apps can be configured in Notification Templates and used in email notifications to let users go directly to forms to complete assignments for tasks, events, and workflows. When tasks are associated with workflows or events (or both), all associated fields are presented on the form.

The valid formats for a email notification link with the notification macros are:

  • {url::basePath}Portal/index.html?route=form&path=/PageSet/Page/Panel/&uniqueid={flow::unique id}
  • {url::basePath}Portal/index.html?route=form&path=/PageSet/Page/Panel/&taskID={task::id}&taskDueDate={task::due date param}
  • {url::basePath}Portal/?ForceDefaultLogin=true/index.html?route=form&path=/PageSet/Pages/Panel/&uniqueID={flow::unique id}

AppLinkMaker Tool

Details of the link format and syntax are described below, for information or debugging. The AppLinkMaker tool will build these formats automatically for you.

Link Syntax Details

The first part is the {url::basepath} macro followed by "Portal/index.html"

"Portal" is case-sensitive.

{url::basePath}Portal/index.html

The variables to navigate directly to a form are:

route = Values are "form" or "platform"

platform: goes to the Management System.

form: goes to the form in the Portal, using either the workflow unique Id or the task Id and due date:

uniqueiD

taskId

taskDueDate

path = PageSet/Page/Panel (insert name of Pageset, Page and Panel). Names are case-sensitive and must be url-encoded for spaces and special characters. (i.e., My%20Pageset%20Name).

uniqueId= unique ID of workflow. In a notification template use the macro substitution {flow::unique id}

The generic "form" variable, which works the same for Workflow, Event and Task panels, replaces the former "formByTask" variable. The "formByTask" variable remains valid but "form" is now preferred.

No https:// prefix is required, as the URL basepath macro link resolves to: https://go.enviance.com/goto/{SystemID}/

Example 1: Go to Portal form using workflow unique Id

To complete the form, click the link below:

{url::basePath}Portal/index.html?route=form&path=/PageSet/Page/Panel/&uniqueid={flow::unique id}

Note: The Panel name in the string above may be a Workflow Panel, an Event Panel (where event has associated workflow), or a Task Panel (where task has associated workflow). The syntax will be the same.

Example 2: Go to Portal form using task Id

To complete the form, click the link below:

{url::basePath}Portal/index.html?route=form&path=/PageSet/Page/Panel/&taskID={task::id}&taskDueDate={task::due date param}

The Panel name in the string above may be a Workflow Panel (where workflow has associated task), an Event Panel (where event has associated task), or a Task Panel (where task may have event, workflow, both, or no associations). The syntax will be the same.

To show text for the link in place of the url string: In the notification editor, click the Source button to open the html editing window. Edit the text to add the link with the correct html syntax like this:

Example 3: Link encoded for html

<p><a href="{url::basePath}Portal/index.html?route=form&path=/PageSet/Page/Panel/&uniqueid={flow::unique id}">To complete the Change Request form click here.</a></p>

Be sure to remove any extraneous html in the link code that may have been added by the editor. Be careful that no html tags or extra spaces are inside the URL.

When using the {url::basePath} macro, do not include "http://" in the link, as it is already specified in the macro.

All links must be URL encoded (i.e., use %20 for spaces and encode special characters). See: http://www.w3schools.com/tags/ref_urlencode.asp

Sample email text formats with pre-configured links are also available for download. See Sample Email Notifications.

The URL basepath macro and other macros are for use in Notification Templates only for system-generated emails. To create a link to the app from an external web page or to share as a saved link in a browser, see Links to Enviance Apps.
