CCC-13333: UDFs have been added to Employee Demographics and Clinic Visit ‘Employee Risk’

  • Six new user-defined, free text fields (UDF_Text_1 through UDF_Text_6) can now be added to custom versions of the 'Employee Demographics' layout. Each will accommodate a maximum of 2000 characters.
  • This will make it easy to store, and for a practitioner to access, information such as a list of all an employee's supervisors (if more than one).
  • Six new user-defined date/time fields (UDF_DT_1 through UDF_DT_6) can now be added to custom versions of the 'Employee Demographics' layout.
  • This will make it easier to capture, through business rules, information such as last visit date or last appointment date, which are important for a nurse to know before booking the next visit or appointment for an employee.
  • A new UDF look-up table (LU_GLB_EmployeeRiskUDF1) with tree capabilities has been added. The new table is associated with 'Employee Risk', which is accessible from within the 'Clinic Visit' module.
  • The look-up table layout has the following fields:
    • ID
    • Code
    • Description
    • Inactive
    • Parent
    • Lineage
  • The Parent field allows the user to specify a parent from within the look-up table itself.
  • The corresponding new EmployeeRiskUDF1 field has a tree-picker (similar to that of organizational hierarchy fields) to the new look-up table. This will allow you to define and track hierarchy-based values, such as risk categories, on custom versions of the 'Employee Risk' (ML-003331) layout.
  • To use the new field and look-up table, the user's role must have access to the 'Employee Risk' security module (categorized under 'Clinic Visit'), and the new field must be added to a custom version of the 'Employee Risk' layout. 
  • All fields described above are available in Query Builder and Report Writer, and for use in business rules, business rule actions, and display rules.
  • The prohibited fields functionality applies to the new fields.
  • Values for the fields can be imported using the Import Utility and the Cority Data Integration Engine.
