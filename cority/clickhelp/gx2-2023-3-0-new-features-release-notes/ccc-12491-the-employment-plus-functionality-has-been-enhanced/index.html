CCC-12491: The pre-placement functionality has been enhanced

  • This will improve the overall user experience.
  • The email functionality for recruiters has been expanded.
  • In order to allow the recruiter to send the applicant notification email to the appropriate email address, the ‘Employee Email Address’ field can now be added to custom versions of the ‘myCority Questionnaire Response Header’ (ML-003605) layout.
    • The field will auto-populate from the Employee data table when the employee is selected in myCority.
    • The equivalent column can be added to custom ‘Public Questionnaire Inbox’ list views.
    • The field can also be added to custom versions of the ‘Public Questionnaire Inbox’ (ML-000734) layout.
  • Also, a new ‘Resend Email’ action has been added to the ‘My Applicants’ (ML-003683) layout.
    • When the action is selected, the Email modal box will open, and the recruiter can enter a new email address.
    • When the email is re-sent, a success message will be displayed, and the event will be logged in the Email Log.
    • If a different email address is entered during the ‘Resend Email’ action, the Employee data table will not be updated with that new email address.
  • There is a new ‘Received Date’ field in the ‘Employee Job Position’ data table.
    • The field will be auto-populated with the date the questionnaire was submitted by the applicant.
    • Clinicians require a dedicated field for when the questionnaire was actually received so they can distinguish between that and other dates (for example, the job position start date).
    • Note: If the process breaks down at some point, for example the applicant did not use the <<Applicant Starter Questionnaire URL>>, and filled out another questionnaire for which job position ID is not retained, the ‘Received Date’ field will remain blank (empty).
    • The 'Received Date' field in the ‘Employee Job Position’ data table will be auto-populated when the ‘Applicant Starter Questionnaire’ is submitted.

  • In myCority, applicants can now bypass the registration process.
  • This will make is simpler for applicants to acquire the Starter Questionnaire they must all fill in prior to receiving clearance from the clinicians.
  • To support this, there is a new system setting 'Allow myCority Applicants to Bypass Registration Screen'. By default, it is not selected. This is a global system setting that cannot be changed to a User setting.
    • It is categorized under the Portal/myCority module.
    • The setting enables applicants to bypass the ‘Applicant Registration’ screen and process by automatically creating a myCority user account for them.
    • When the system setting is selected, and the recruiter creates an employee record using the ‘Applicant Demographics’ layout:
      • A myCority user ID is auto-generated for the newly created employee
      • The Login ID will match the employee number
      • A password, based on the system setting configured password complexity rules, will be generated
      • The User data table will be updated with the new ID
      • The Portal Only checkbox will be selected on the User record
      • The out-of-the-box Portal role will be assigned to the user
      • The email address, first name, and last name (as entered on the ‘Applicant Demographics’ form) will be added to the User record
  • An additional business rule and list view column have been added.
  • A new BR-100641 (with accompanying BRA-100641) has been added that will email the applicant a link to the Starter Questionnaire when bypassing myCority registration.
    • The business rule is categorized as myCority and uses the MedicalPublicQRH entity.
    • The email will be sent to the Email address identified on the questionnaire response header, with appropriate subject and body.
    • The temporary password will be sent in a second email, with appropriate subject and body.
      • This is accomplished through BRA-100642, which is attached to BR-100641, and also uses the MedicalPublicQRH entity.
    • The second email will not be recorded in the Email Log.
    • Once the applicant has logged in, he or she will be prompted to and must reset the password.
    • Once the password is reset, if the user has followed the email instructions correctly, he/she will land on the ‘Applicant Starter Questionnaire’ screen.
    • Note: The password sent in the secondary email during the bypass registration process is not stored in the Email Log. If the applicant/user is ever unable to log in, a GX2 administrator will have to reset the password.
  • Existing business rules have been updated.
  • Due to the implementation of the features allowing the applicant to bypass the registration process, changes had to be made to the existing BR-100583 and BR-100584.
    • BR-100584 now has an additional condition for when the 'Allow myCority Applicants to Bypass Registration Screen' system setting is not selected (that is, false) and an additional condition for when the method ‘Employee Has Existing User and No Email Log’ is false.
    • BR-100583 now has an additional condition for when the method ‘Employee Has Existing User and No Email Log’ is false.
    • If you have cloned and changed the above Cority-Created business rules, you must ensure the new condition is added to your custom version(s) so that the pre-placement workflows continue to function properly.
    • The conditions were added so that the applicant only receives one email, from either BR-100583, BR-100584, or BR-100641.
  • Also, updates had to be made to two existing business rule actions: BRA-100595 and BRA-100596.
    • The ‘To’ field in the BRA Email Action is now ‘Employee Email’ (pointing to the new field on the ‘myCority Questionnaire Response Header’ record), as opposed to ‘Email’ (which pointed to the ‘Employee Demographics’ record).
    • If you have cloned and changed the above Cority-Created BRAs and you would like the emails to be driven from the ‘Questionnaire Response Header’, you must ensure the ‘To’ field is updated with ‘Employee Email’.
  • The Letters functionality for the pre-employment feature set has been enhanced.
  • All the fields in ‘Employee Job Position’ data table that can be queried, along with other applicable related fields, are now available as merge fields that can be included in letters.
    • The data will be driven by the selected ‘Employee Job Position ID’ held against the record, such as Clinic Visit.
    • This will reduce any need for the use of subqueries to pull data into the letters.
  • Some clients do not have the ability to extract from ZIP files, so the letters sent from GX2 can now be configured to be password-protected when emailed.
    • To support this, a new Password Protected checkbox can now be added to custom versions of any Letter layout, regardless of cloud.
    • If used, the letters ‘Email’ action will result in two emails, one with a password-protected PDF file, and a second with a system-generated password to be used for opening the PDF.
    • Both email events will be saved in the Administrator ‘Email Log’ and in ‘My Email Log’ for the user who sent the email.
    • If the Password Protected checkbox is not selected, only a single email will be sent.
    • Note: The letters ‘Email’ action does not function when Draft is selected. Also, a letter that is not draft cannot be edited, which includes the new Password Protected checkbox. However, if the user’s role is assigned the 'Revert to Draft' action, that can be used to unlock the letter and mark it 'Password Protected'.
