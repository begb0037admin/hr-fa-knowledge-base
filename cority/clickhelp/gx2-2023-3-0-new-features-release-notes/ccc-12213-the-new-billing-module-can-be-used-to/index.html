CCC-12213: The new Billing solution can be used to bill and invoice for medical services

  • A license key is required to access the solution.
  • In GX2, the Billing solution has its own menu item at the cloud level.
  • This solution can be used, for example, by a hospital who is contracted by companies to provide medical services for their employees.
  • The hospital would then have the GX2 system with the Billing solution and Clinic Visit module and manage pools of employees from the different companies.
  • There is a new system setting ‘Employer for the Billing Module’. Before using this functionality, a GDDLOFB node must be repurposed and used as the value for that setting.

  • The Billing and Invoicing Workflow:
    1. On the Clinic Visit record, navigate to the Procedures tab and click New.
      This opens a Clinic Visit ‘Billing Item’, which serves as a bill.
      All fields on this layout, even the calculated ones, are reportable.
    2. Provide the fee.
      The Fee field opens a modal box, which has the ‘Costs Associated to a Fee Schedule’ list view. The view lists the fee schedules from the ‘Fee Schedules’ look-up table.
      Note: This modal box also enables you to create a fee schedule to be added to both the look-up table and the bill.
    3. Provide a Payer Type and a Payer.
      The Payer Type field is a picklist to the ‘Payer Types’ look-up table. Its entries must be created beforehand, and can be an insurance company, an employer, an employee, etc.
      The Payer field is a picklist to the Payers look-up table. Its entries must be created beforehand, and can be the specific insurance company, the specific employer, the specific employee, etc.
    4. Add a Modifier, if applicable.
      A modifier is a picklist to the Modifiers look-up table. Its entries must be created beforehand, and account for anything out of the ordinary or additional (additional add-on hours, additional jurisdictional taxes, etc.). At present, only a single Modifier can be added.
    5. Add a Discount Type, if applicable.
    6. Save the record.
      The system will now calculate the total fee.
    7. If the user selects the ‘Coding Complete’ check box and saves the record, that indicates the practitioner or coder has completed his or her part, sends the bill to the Billing solution, and ends the Clinic Visit portion of the workflow.
    8. Open the Billing solution.
      The Billing solution has a number of modules, one of which is the ‘Un-invoiced Items’ module.
      As part of the initial configuration for this functionality, you will need to create custom views for this module. For example, it is best practice to create a custom ‘Un-invoiced Items’ view for each employer and/or payer. You might, for example, for a single billing item or clinic visit, have two separate bills with a different payer for each.
    9. From the ‘Un-invoiced Items’ view, click the ‘Generate Invoices’ action.
      The ‘Generate Invoices’ modal box will open. It can be used to generate one or more invoices (all for an entire month, for example). Different invoices will be generated automatically by the system for the different employers and different payers.
    10. Populate the ‘Generate Invoices’ modal box with the required information, and then click the ‘Generate Invoices’ button.
      After generating, the modal box will report the outcome.
      Generated Invoices will be listed on the Invoices list view.  All individual billing items will be grouped under a single invoice number.
      Invoices will have one of the following statuses: Null, Submitted, Pending, Disputed, Partially Paid, Fully Paid, and Written Off
      For this list view, it is also best practice to create a custom view for each payer.
    11. From the Invoices Letters tab, add the letter template that is flagged as an Invoice.
      Adding but not sending it to an employer will change the invoice status to ‘Pending’.
    12. Once the letter is no longer marked Draft, send the invoice (letter) to the employer by clicking the ‘Submit to Employer’ action.
      A front-end email modal box will then display for reviewing the recipient and sender information.
      When the invoice (letter) has been submitted successfully, its status will change to ‘Submitted’, and a copy of it will automatically be added to the Documents tab of the Invoice record. The description will contain the invoice number and the date/time of submission.
  • A person in the Finance Department can monitor invoice statuses using views.
  • Payment can be applied directly to invoices once the status of the invoice is ‘Submitted’.
    • The values entered into the ‘Amount Received ($)’ field will be deducted from the ‘Outstanding ($)’ amount.
    • If the ‘Outstanding ($)’ amount is greater than zero, the status of the Invoice will be ‘Partially Paid’.
    • If the ‘Outstanding ($)’ amount is less than or equal to zero, the status of the Invoice will be ‘Fully Paid’.
    • The ‘Outstanding ($)’ amounts for the individual billing items within an invoice will continue to adjust accordingly when applicable until they all reach ‘Fully Paid’.
  • All calculated fields on an invoice are reportable using Query Builder.
  • An invoices (and/or individual billing items) can be disputed using the ‘Dispute’ action. That will change the status of the invoice and/or item to ‘Disputed’.
    • Once the required adjustments are made, the dispute can be cancelled by selecting the ‘Cancel Dispute’ action.
      Note: The ‘Dispute’ action must be granted explicitly to the user's role.
    • Once a dispute has been cancelled, the invoice status will revert to the one it had prior to the dispute.
  • Note: Rather than starting from the Clinic Visit module, an alternate workflow is to start within the Billing solution and create an un-invoiced item directly from the ‘Un-invoiced Items’ module.
  • The following new look-up tables, with accompanying layouts, have been added:
    • Payer Type
    • Payer
    • Fee Schedule
    • Fee Schedule Cost
    • Modifier
  • The following additional new layouts have been added:
    • Clinic Visit Billing Items
    • Un-invoiced Billing Items
    • Invoiced Billing Items
    • Invoice Letters
    • Invoice Documents
  • The Clinic Visit Billing Items  and Un-invoiced Items layouts have the following calculated fields:
    • Total ($) = Fee Cost * Units + Modifier
    • Adjusted = Total – DiscountTotal
    • Outstanding = Adjusted – Received – WrittenOff
  • For reporting, the following new entities are now available:
    • Billing.Invoice – For reports on the invoice, including invoice total and invoice outstanding
    • Billing.InvoicedBillingItem – For reporting on individual billing items, including costs, totals, discounts, modifier
  • The following new security modules have been added, and must be granted to users' roles accordingly:
    • Billing
    • BillingDocuments
    • BillingLetters - The following actions, if required, must be granted specifically:
      • billingletter.confirmsubmittoemployer - For 'Submit to Employer'
      • letter.submittoemployer - For 'Submit to Employer'
      • invoice.dispute
      • invoice.canceldispute
    • BillingEmployer (For Employer roles) - The following actions, if required, must be granted specifically:
      • employeebillingimport.importfile - For Demographics importing and re-processing
      • employeebillingimport.reprocess - For Demographics importing and re-processing
    • LookupTablesForBilling
  • For Employer Management, a new ‘Import Demographics’ action is now provided. It is grouped under the Demographics module. The new action will enable employers to manage their employee list within GX2 directly. The GX2 Administrator will need to provide the employer with the import template. The import logic will respect both site and role security configuration.
  • For information on working with look-up tables, custom list views or layouts, calculated fields, reporting, or security configuration, see the GX2 User Guide.
