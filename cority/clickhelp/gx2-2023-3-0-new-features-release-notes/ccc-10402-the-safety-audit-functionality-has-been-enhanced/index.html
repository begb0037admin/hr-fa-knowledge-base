CCC-10402: The Safety Audit functionality has been enhanced

  • In support of audit findings, ‘Why Tree’ and ‘Root Cause Analysis’ sections (sublists) can now be added to custom ‘Findings & Actions’ layouts and used for audit data reporting.
  • For consistency, these have been added to all clouds that use findings and actions.
  • Note: Respiratory Fit findings are excluded, even if created from within the Safety or IH clouds, because Respiratory Fit findings use Medical Findings instead.
    • The 'Why Tree' is editable only when the parent Finding record is not locked or read-only. 
    • The 'Why Tree' is exportable as an image or PDF. It can also be populated and updated using the Import Utility.
    • The 'Why Tree' is not currently supported for Inspections or Finding/Action assignment using myCority because only the Actions portion is available within myCority.
    • There are two new security actions for the 'Why Tree'. The whytree.allowunmarkasrootcause action allows users without delete permissions to deselect a 'Why Tree' entry as a root cause. The whytree.drawedit action, when not granted to the user's role, sets the 'Why Tree' to read-only.
    • The 'Root Cause' sublist has a new 'Finding Cause' layout (ML-003806) with applicable fields and actions. It functions like a typical GX2 layout.
    • Finding 'Root Cause' can be used in business rules, populated and updated using the Import Utility, and reported on using Query Builder.
    • To the Incident Root Cause, Cause Category, Cause Type, and Cause Contribution Level look-up tables, the following cloud checkboxes have been added: Safety Finding, Environmental Finding, Ergonomics Finding, Quality Finding / CAPA Metrics Finding
  • Also, the Audit Calendar scheduling features have been enhanced.
  • The new 'Audit Calendar Schedule' sublist can be added to custom version of Audit layouts.
    • The sublist has the following default columns: Date, Start Time, End Time, Time Zone, and Remont/Onsite
    • Time Zone populates with the value in the user’s Time Zone system setting.
    • This sublist does not require a layout. It can be populated/updated using inline edit. It cannot be populated/updated using the Import Utility.
    • 'Audit Calendar Schedule' entries inherit the GDDLOFB of the parent Audit record.
    • The new sublist allows for calendar schedule invitations over multiple days (for example, for an audit that spans a number of days).
    • BR-100638 (and accompanying BRA-100638) have been created for sending email invitations with an ICS file for the schedule entry.
      • The BA and BRA can be cloned to modify the criteria, text of the email, etc.
      • For an invitation that spans multiple days (more than one row/record), an email with ICS file will be sent for each record.
    • When an 'Audit Calendar Schedule' entry is deleted, an email with ICS for removing the entry will be sent. That is handled by the new BR-100637 (with accompanying BRA-100637).
    • For BR-100639 (and accompanying BRA-100639), additional conditions have been added to ensure that if a user updates and saves an 'Audit Calendar Schedule' entry, an update email is only sent to the invitees if they need to know about the update(s).
    • The 'Audit Calendar Schedule sublist and default view have a 'Meeting Details' text field (column) that accommodates a maximum of 2000 characters. 
    • The 'Audit Calendar Schedule' is available for use in BRs and BRAs, and can be reported on using Query Builder.
