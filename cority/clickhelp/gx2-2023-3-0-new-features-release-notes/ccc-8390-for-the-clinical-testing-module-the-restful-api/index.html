CCC-8390: For the Clinical Testing module, HL7 file data can now be acquired from different sources

  • To support this there is a new ’HL7 Mapping’ (LU_GLB_HL7Mapper) look-up table, categorized under the Demographics module.
  • The default list view for the table has the following columns:
    • Code
    • Description
    • Module
  • The look-up table layout has the corresponding fields.
  • The table contains the following hardcoded, Cority-created Clinical Testing standards:
    • Gamma Dyna Care
    • LabCorp
    • Oxford
    • Source ASTM88 Lab File
    • Source ASTM94 Lab File
    • Source HL7v22 Lab File
    • Source HL7v23 Lab File
    • Source HL7v23_2 Lab File
      • The out-of-the-box standards cannot be altered through import.
      • You can import additional (user-created) standards directly into the 'HL7 Mapping' look-up table by providing a comma-separated CSV import file with four columns. You cannot do this using the Import Utility.
      • The standards can be reported on using Query Builder or Report Writer
  • The look-up table has two views: Cority-Created and User-Created
  • The out-of-the-box standards are listed under the former and imported standards under the latter.
  • Either a Cority-created or user-created standard can be selected for the ‘Clinical Testing Import Standard’ system setting value.
  • The new look-up table has a Mapping sublist, which accepts a maximum of 100 data rows.
    • Its default list view has the following columns: Segment (PID, OBR, OBX, NTE, or MSH), Pipe (Numeric), Caret (Numeric), Mapped Field Name (Technical Name of Cority Field in Text)
    • The layout for the sublist has the corresponding fields.
    • The user can make modifications to the sublist data by inserting, modifying, and/or deleting rows.
    • Similar to the look-up table entries, you can import new row values into a look-up table record's Mapping sublist using an import file.
    • Your import file can have a maximum of 100 rows. A single CSV file to many rows is a characteristic of this sublist.
    • The Mapping sublist rows can be reported on using Query Builder or Report Writer.
  • Also, through the existing RESTful API endpoint, users can now import their own custom HL7 mappings to support labs that use HL7 standards other than those GX2 provides out of the box.
    • The POST endpoint is [https://corityurl/api/ClinicalTestImport/import].
    • This functionality requires that the user’s role be granted the ClinicalTestImport.apiwrite security action.
    • The endpoint will accept the data, the Standard (previously an enum value, but now a look-up table value that is either Cority- or user-created), the Laboratory (a look-up table value), the Health Center (a look-up table value), and the Practitioner (from the User data table). The data must be an HL7 file that is first converted to base64.
    • The import will function similarly to all other RESTful API imports.
  • New UDFs are provided as well.
    • The following new UDFs can be added to custom versions of the ‘Clinical Test Battery’ layout:
      • UDFText1 through UDFText4
      • UDFDate1 and UDFDate2
    • The following UDFs can be added to custom versions of the ‘Clinical Test Results’ layout:
      • UDFText1 through UDFText10
      • UDFDate1 through UDFDate3
      • UDFFlag1 and UDFFlag2
    • The date fields will use the format specified in the Date Format system setting.
    • The new UDFs can be used in business rules, business rule actions, and in display rules.
    • They can be reported on using Query Builder and Report Writer.
  • For information on working with the Clinical Testing module, look-up-tables, the Import Utility, the RESTful API, custom layouts, and/or UDFs, see the GX2 User Guide.
