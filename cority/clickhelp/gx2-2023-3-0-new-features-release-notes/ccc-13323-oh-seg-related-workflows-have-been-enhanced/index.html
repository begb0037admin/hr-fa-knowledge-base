CCC-13323: OH SEG-related workflows have been enhanced

  • To support this, a new ‘Employee Active SEGs’ field can now be added to custom versions of the ‘Exam Activity’ layout. The equivalent column can be added to custom versions of the ‘Exam Activity’ sublist.
  • The field is a picklist from which the user can select one or more of the employee’s active SEGs. Multiple values can be specified for the field on the layout or in the column (through inline edit) on the list view.
  • Any SEGs added to the field for an activity will not be added to the recall definition .
  • This field will enable the user to specify any active SEGs with which the exam activity is associated, which will identify any ad-hoc activity completed that satisfies one or more of employee’s active SEGs.
  • The new field addresses two main requirements:
    1. For activities that are already part of surveillance programs (through the Recall Definition tab on the Exposure Group look-up table), the field displays (in read-only format) the names of one or more SEGs associated with the activity. This helps the user identify easily the SEG(s) the activity is satisfying.
    2. If the clinician/physician deems it necessary for an ad hoc activity/test to be performed, the new field enables that person to document the SEG the ad hoc activity satisfies, without having to change the requirements of the SEG for everyone. In this case, the field is editable and allows for multi-selection if appropriately configured. For example, if the physician deems it necessary that a vision test be completed for an employee, this will enable the physician to specify any active SEGs for the employee that the test satisfies, without the test being added to the recall definition. The test is not likely to be required for everyone. When reporting, this will also make possible a count of any particular type of test for SEG X.
  • The new field does not require a value.
  • Note: The field will populate automatically with an active SEG for each of the employee’s activities that are in the ‘Exposure Group Recall’ data table, meaning they were already identified as requirements for certain SEGs. For example, if the active Flu SEG has Flu Vaccine and Flu Questionnaire listed in the data table, and the active Hearing SEG has Audiometric and Audio Questionnaire listed in the data table, the Flu and Hearing SEGs will populate. Such values will be read-only (locked) on both the layout and the list view.
  • The new field can be used in business rules, business rule actions, populated/updated using the Import Utility, and reported on using Query Builder.
  • The Job Position sublist can now be added to any custom Medical Chart layout. This sublist functions the same as the Job Position sublist in the Demographics module.
    The only exception is that the ‘Set as Primary Job Position’ action is not available on the Medical Chart version of the sublist. That action can only be performed in the Demographics module.
    To access and use this sublist, the user’s role must be granted both the Demographics and Medical Chart security modules.
  • To be able to view the full history of SEG enrolment, in the Clinic Visit ‘Employee SEGs and Clearance’ sublist, for an employee enrolled in the same SEG twice (or more), one enrolment with an end-date and the other currently active, the inactive one will now display in a newly added list view called ‘SEGs Linked to Individual Employee’. The same view is already accessible from the Demographics and Medical Chart modules.
