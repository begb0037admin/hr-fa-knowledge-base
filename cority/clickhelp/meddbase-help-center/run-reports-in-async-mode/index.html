What's the Context?

In some instances when using the URL of a report within a GET Data Platform, such as PowerBI, Excel Power Query, or Tableau, executing larger reports can take longer to run than an HTTP connection timeout allows. In environments where the connection timeout cannot be changed, these reports can fail before the report is completed. 

To prevent failed reports in these environments, an asynchronous report execution can be submitted which separates the report execution from the HTTP request connection timeout. 

What is the Purpose of This Article?

This article will describe how to submit an asynchronous report execution to prevent connection timeouts. 

How to submit an asynchronous report

    When entering the URL from the report in the Report Server, add async=true to the URL parameters. For example:

    https://featurec-dataserver.meddbase.com/Default.aspx?u=[user]&p=[pass]&k=5159&async=true

    Filters, aliases, sort, and order work the same. 

    When submitted, a JSON is returned with the jobID of the report execution. You can check the status of the report using the jobID URL parameter. For example:

    https://featurec-dataserver.meddbase.com/Default.aspx?&jobId=123456789&u=[user]&p=[pass]

    The status of the report will be either Running or Complete. When completed, the Result URL will include the final report. The final report opens the same as a report run without asynchronous and the results can be saved in XML.
