2025 Maintenance Release Ongoing Release Notes

Here you'll find an up to date list of all changes made during Maintenance releases in 2025.

22nd December Release 

Main Application

  • Fixed an issue where documents that were automatically attached to a referral were not appearing when creating a report. 
  • Improved the performance of the Start Page by improving how Work Profile counters are calculated.
  • Updated billing rules configuration to indicate when a site used for the rule has been deleted.
  • Fixed an issue where patients could still be added to a deleted charge band.
  • Added a new billing rule to specify an amount that a patient pays towards an appointment type.

Enterprise API

  • Added new endpoints for getting details of services in modules.

Main Application

  • Updated Lab results so that when pathology results are returned with missing units, results still come through.
  • Updated Lab System reprocessing error message for clarity.
  • Fixed an issue where charge bands with a name set by the system were not appearing in drop-down lists.
  • Fixed an issue where assigned pathways were appearing twice in the filter.
  • Updated the available appointment lengths to be specific to a chamber, allowing customers to set their own appointment lengths in a new Common Catalogue
  • Fixed an issue where incorrect validation warnings were occurring when building questionnaires.
  • Fixed an issue where birthday reminders were being sent to patients who had birthday reminders turned off.

 Enterprise API

  • Added the ability to allow amending discharged appointments.
  • Fixed some design inconsistencies in the API.

 Data Warehouse

  • Fixed an issue where an error was occurring in the table when a new questionnaire field is used.
  • Update the Profile table to move the Last Login Date column to a separate table to improve stability.

17th November Release

Enterprise API – Search Issue

  • When searching for a clinician’s address, if there is a space in the postal code, any applicable search results will now be generated and displayed.

Enterprise API – Person Endpoints

  • As part of the ongoing EAPI work, minor changes have been made to the person endpoints, including formatting improvements, the updating of some flexible filter sets, and the addition of a new GET call for next of kin.

Enterprise API – Additional Clean-up

  • Department Code has been moved to resource/service-department-code, and flexible filters have been added to it.
  • Location ID has been moved to resource/site/location/{id}.
  • Location Search has been moved to resource/site/location/search.

Pathology

  • Issues with the Pathology Results dialog box, which is accessed from the side-by-side schedule, have been fixed.

Pathology

  • Previously, the order datetime for a pathology request could only be the appointment datetime. Now it can remain the appointment datetime, or be configured to instead display the order raised datetime. This is particularly useful for customers who order pathology that is not part of an appointment directly (for example, a follow-up pathology order that you want associated with the original appointment).

Pathways

  • If you have a lot of pathways in your worklist and have a pathway filter set by parameter, when you open the Pathway drop-down field it will now remain open for use until you select an option within it.

Import Layer

  • The MP (Medical Person) policy can now be updated through import.

Billing Rules

  • The activity displayed for billing rule intervals has been improved. Some unnecessary details have been removed, and it is now better organized overall.

Conditional Chart Display

  • You can now set a chart to display only if a value for the field that populates it is specified (recorded)  in the associated appointment. If the new hideIfNoValueInAppointment setting is true, the chart will not display unless a value is added to the meta field that is driving the chart view. For example, you might not want to see a BMI chart if you did not enter BMI today.
