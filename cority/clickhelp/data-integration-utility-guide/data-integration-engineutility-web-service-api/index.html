void

GetModelProperties(string username, string password, out Dictionary<string, IList<string>> dataDictionary, string model, out IList<string> selectedProperties, out IList<string> availableProperties, out IList<string> uniqueKeyProperties, ref bool skipAudioRecords, ref bool isAudiometricTest, ref bool softKeyOptions);

This method retrieves the available and selected fields for a specific user and import table.

Parameters:

  • string username – the username to log in for imports
  • string password – the password to log in for imports
  • out Dictionary<string, IList<string>> – dataDictionary
  • string model – the model associated with the selected fields. For example, if the user wanted to import to Entity AbsenceStatus, the model name would be “Lookups.Demographics.AbsenceStatus”.
  • out IList<string> selectedProperties – the list of selected fields/properties for the specified user and model
  • out IList<string> availableProperties - the list of available fields/properties for the specified user and model
  • out IList<string> uniqueKeyProperties - the list of unique fields/properties for the specified user and model
  • ref bool skipAudioRecords – needs to be initialized but will be set within the function to true if the System Setting "Classify Audiometric Test Records that have the same date and different times as the same record" is true and the model is of type AudiometricTest
  • ref bool isAudiometricTest – needs to be initialized but will be set within the function to true if the model is of type AudiometricTest
  • ref bool softKeyOptions – needs to be initialized but will be set to true if model is assignable from IHasSoftUniqueKey

Return Value: Void

IList<Data Integration Utility.CorityModelTable>

GetTables(string username, string password);

This method retrieves the Cority Data and Look-up tables available for importing.

Parameters:

  • string username – the username to log in for imports
  • string password – the password to log in for imports

Return Value: Returns a list of tables. Each list item (CorityModelTable) contains five string fields describing the table entry. These fields are Description, Entity, TableName, Module, and Model.

For example, a CorityModelTable entry for AbsenceStatus would look like:

  • Description = “Absence Statuses”
  • Entity = “AbsenceStatus”
  • Module = “Demographics”
  • TableName = “LU_GLB_AbsenceStatus”
  • Model = “Lookups.Demographics.AbsenceStatus”

This method saves the selected fields for the specified user and model.

string

DoImport(byte[] data, string importFormat, string currentModel, string username, string password, bool updateExistingRecords, bool autoInsertBaseTableValues, bool insertMultiple, bool alwaysInsert, bool containsHeaderRow, bool xmlFile, string dateFormat, object customLogicParam);

This is the main method for the Cority Data Integration Web Service. Calling this method will begin the import process.

Parameters:

  • byte[] data- This is the data to be imported. The import file should be a comma-delimited text file with one record per line or XML File. The file should be read into a byte array and then compressed into a gzip stream for upload.
  • string importFormat - the comma-delimited string of the selected fields being imported. For example, if the user was importing a file with Code and Description values, then importFormat = “Code, Description”.
  • string currentModel - the model to import data to. For example, if the user wanted to import to Entity AbsenceStatus, the model name would be “Lookups.Demographics.AbsenceStatus”.
  • string username – the username to log in for imports
  • string password – the password to log in for imports
  • bool updateExistingRecords – If true, and a record that already exists is imported, this record will be updated with the values in the import file. If false, and a record that already exists is imported, the record will be rejected and statement explaining that returned.
  • bool autoInsertBaseTableValues – If true, automatically inserts code/descriptions for look-up tables (if they do not already exist), instead of rejecting the record.
  • bool insertMultiple – Different businesses have different criteria which identify a unique record for a specific table. For such situations, Cority does not enforce a database constraint for uniqueness. If ‘updateExistingRecords’ is True, and this setting is also True, a new record will be inserted.
  • bool alwaysInsert – if true, will always create and insert a new record
  • bool containsHeaderRow – if true, the first row of the import file contains a header row and will be ignored
  • bool xmlFile – if true, the import file is of type XML
  • string dateFormat – the date format used in the import file
  • object customLogicParam – CustomDoImportLogicDelegate. For example, used for tree to specify format tree type.
  • object customLogicString - used to provide a replacement customLogicParam. (for example, <med:customLogicParam i:type="b:int" xmlns:b="http://www.w3.org/2001/XMLSchema" xmlns:i="http://www.w3.org/2001/XMLSchema-instance">-2</med:customLogicParam>) If provided, it overrides customLogicParam. If omitted, the Data Integration Utility will function as normal.
  • bool bypassBR – if true, will ignore any business rules activated in the front end on manual import. Should be only applicable to the TreeMaster, JobPosition look-up tables and the SafetyRASJobList data table.

Return Value: Returns a string representing the import log containing details of the performed import

bool

ValidateUserDataIntegrationUtilityPermission(string username);

This method verifies that the user has permission to run imports by checking if the user has an admin role or is granted the “Data Integration Utility.Import” action.

Parameters: string username – the username to check for Data Integration Utility permission

Return Value: Returns true if the user has Data Integration Utility permission; else false

void

This method validates both login credentials and Data Integration Utility Permission by calling ValidateUserLogin and ValidateUserDataIntegrationUtilityPermission.

Parameters:

string username – the username to log in for imports and check for Permission

Return Value: Void. If you do not have correct login credentials or permission to run the Data Integration Utility, and exception similar to one of the following will appear:
