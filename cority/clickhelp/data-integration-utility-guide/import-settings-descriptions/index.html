Import Settings Descriptions

SettingDescription
Login UsernameThe Cority username used to run the Data Integration Utility.
Login Password

The Cority password used to run the Data Integration Utility.

The password is encrypted before it is saved to the ini file. The encryption depends on a key that is user/machine specific. This means that one user cannot decrypt the password from an ini created by another user. This is an important point to keep in mind when configuring Data Integration Utility to run automatically/silently.

URLThe URL of the Data Integration Utility web service.
Proxy UsernameThe username used when connecting to the web proxy.
Proxy DomainThe domain used when connecting to the web proxy.
Proxy Password

The password used when connecting to the web proxy.

The password is encrypted before it is saved to the ini file. The encryption depends on a key that is user/machine specific. This means that one user cannot decrypt the password from an ini created by another user. This is an important point to keep in mind when configuring Data Integration Utility to run automatically/silently.

Proxy URLThe URL of the web proxy.
Import FileThe filename of a comma delimited file or XML file that contains the data you wish to import into the Cority application.
Date FormatDate format used in the import file.
Automatically insert non-existing base tables valuesAutomatically inserts code/descriptions for lookup tables (if they do not already exist), instead of rejecting the record.
Import file contains header rowSpecifies if the import file contains the header row with column names. If this is checked, the first row will be ignored in the import.
Classify records that have the same date and different times as the same recordThis is specifically used for the audiometric import. If this is checked and a record is imported where an audiometric test already exists for that employee on the same date (and time does not match), it will update that record. If this setting is false, it will insert as a new record.
Update existing recordsIf this is checked, and a record which already exists is imported, this record will be updated with the values in the import file; otherwise, the record will be rejected stating that the record already exists.
Insert a new record if multiple records are foundDifferent businesses have different criteria which identify a unique record for a specific table. For these situations, Cority does not enforce a database constraint for uniqueness. If ‘update existing records’ above is checked, and this setting is also checked, a new record will be inserted.
Always insert as a new recordThis option is to be chosen as an alternate to ‘update existing records’ and will automatically create records for all data in the import file.
Bypass Business RulesBecause this is only applicable to the TreeMaster and JobPosition look-up tables and the SafetyRASJobList data table, the Data Integration Utility will ignore any standard business rules when inserting these records manually.
‘Add Roles to Users’ and ‘Remove Roles From Users’This is only available when importing into the Security table. There are two radio buttons: ‘Add Roles to Users’ and ‘Remove Roles from Users’. ‘Add Roles to Users’ is the default. If ‘Add Roles to Users’ is selected, the role(s) in the file will be added to the users defined. If ‘Remove Roles from Users’ is selected, the role(s) in the file will be removed from the users defined.
Enable Delta ImportIf selected, it will save the next successfully imported file with a “previous” suffix. And on the next import of a new file, only the deltas (added or updated records) will be imported rather than the full file being imported every time.
