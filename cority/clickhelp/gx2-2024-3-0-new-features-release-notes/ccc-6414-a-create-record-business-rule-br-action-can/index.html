CCC-6414: A ‘Create Record’ business rule (BR) action can now add multiple new records to a sublist based on the results of a subquery

The following is an example workflow:

1. The saving of an OH ‘Risk Assessment’ record with a specific location triggers the business rule.

2. The business rule adds all supervisors associated with that location to the OH ‘Risk Assessment’ record’s Assessors sublist.

3. The ‘Create Record’ BR action uses the following subquery to populate the Assessors sublist:
a Query Builder subquery for all employees who are supervisors, filtered by the location on the OH ‘Risk Assessment’ record

To support this, on the ‘Create Record’ BRA screen, for a right-side value a subquery column can now be used if the left-side value is an accepted object.

The following are accepted objects:

  • Data Tables (for example, Employee.EmployeeNumber)
  • Look-up Tables (for example, ‘Clinic Visit’ Reason.Code)

For the records to be created, the subquery must contain one of the following as the first column:

  • A look-up entry value (for example, the 'Risk Definition' field) – to match by look-up entry code or ID
  • A tree node (for example, the 'Location' field)- to match by TreeMaster code or ID
  • A data table picklist:
    • An employee-type field value (for example, User.Employee) – to match by employee number or employee ID
    • A User field value (for example, ClinicVisit.Practitioner, Case.CaseManager) – to match by user login name or user ID
    • Values for other data fields (for example, Equipment) – to match by an ID in the corresponding data table

You can only save a Create Record BRA with a subquery in a right-side column when the execution type is ‘Scheduled’. If you try to save it as an ‘Immediate’ Create Record BRA, an informative error message will display.

You can only save with one subquery in any single right-side field of a Create Record BRA. If you try to save with more than one subquery, an informative error message will display.

Note: To avoid a potential infinite loop, do not configure the BRA to create one or more records of an entity to which the subquery is pointing.

When the business rule with ‘Create Record’ BRA that has one or more subqueries runs, if the left side is an accepted look-up or data table object (for example, RAS.MedicalRiskAssessmentAssessor.Employee) and the right side is a subquery, then on execution all records found by the subquery will be added to the corresponding sublist.

The subquery can be filtered (for example, RiskAssessment.Location filters the subquery to employees from a certain location only).

The ‘Create Record’ BRA will only create the top 20 records.

  • Duplicates records will not be created, therefore will not be counted as part of the 20. Failed creation records will be counted.
  • If the system has to be prevented from creating a duplicate record or fails to create a record (for example, for not having values for all required fields or if the subquery has been altered), a notification will be recorded in the Event Log.
