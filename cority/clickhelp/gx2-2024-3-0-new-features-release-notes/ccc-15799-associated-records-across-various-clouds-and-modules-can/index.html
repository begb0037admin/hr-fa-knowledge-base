CCC-15799: Associated records across various clouds and modules can now be linked and reported upon easily and efficiently

This feature set will enable organizations that want integrated QEHS systems to establish bidirectional connections between associated records across the platform. That will allow for more comprehensive data reporting and analysis, for example to identify links across many different functions.

The changes made to support this functionality include:

  • A new ‘Linked Records’ tab (sublist) can be added to applicable layouts (Ergonomics ‘Audits’ and Ergonomics 'Findings').
    While adding the sublist using the Layout Editor, the Administrator will configure, using a tree of clouds and solutions/modules, the records that can be linked.
    To configure and add this tab to a layout, the user must be granted either the Administrator or Layout security role, or the user’s role must be granted the     <record type>.linkedrecordsconfig action.
  • A new ‘Link Record’ action can be added to applicable layouts.
    The action can be configured and added in the same manner as any other action.
    The action will display a pop-up from which the user can select the records to be linked. The records that can be linked will be organized by cloud and solution, according to the configuration (through the Layout Editor) of the associated ‘Linked Records’ tab.
    To use this action, the user must have write access to the linking record. The user must also have the     <record type>.linkrecords action granted to his or her role. To unlink records, the user must have the <record type>.unlinkrecords action granted. To edit comments for linked records, the user must have the <record type>.editcommentlinkrecords action granted. All other standard security configuration applies for navigating to, unlinking, and/or editing linked records.

This will help you leverage Query Builder for enhanced reporting and data analysis across your organization. For information on using Query Builder, see the GX2 User Guide.
