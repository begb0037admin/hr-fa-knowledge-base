Application Setup

  1. Install the IIS rewrite module: https://www.iis.net/downloads/microsoft/url-rewrite

  2. Install the .NET Core Windows Server Hosting bundle (version 6.0.8). The bundle is available on the Microsoft website: https://dotnet.microsoft.com/download/ or via direct link

 You may need to restart your computer once the installation is complete. If you can’t restart your computer, open a command prompt in administrator mode and type the following commands to stop and start IIS: net stop was /y net start w3svc

To access administrator mode, right-click the cmd.exe file and select Run as administrator. If you do not run the command in administrator mode, an “Access is denied” message will display: 

  1. Extract the myCority.zip file.
  2. Copy the application to the web server.
    Only the “package” folder is needed. Ensure it is the root folder of the web server.
  1. Under the root folder, there is an appsettings.json.sample file. Copy this file and rename it appsettings.json.

  1. Create an application pool.

  1. Create the application using the path of the package and application pool created in the previous step.
  2. The “Execute” permission is needed in order for the site to load. If the site functionality does not work, or if no logs are generated upon loading the site, you may need to grant permissions to the application pool so it can read and create files in the folder directory.
    If you used ‘ApplicationPoolIdentity’ as the identity for the application pool, enter ‘IIS AppPool\’ followed by the application pool name you created (for example, ‘IIS AppPool\myCority-api’).
  1. Click Check Names to ensure the application pool can be found.
  2. Click OK.

If site functionality still does not work, there may be a problem with the web.config file. Some servers have a default web.config file, and this conflicts with myCority. The default web.config file is located at \web.config. The following may need to be removed from the file:

<customHeaders>
<add name="Strict-Transport-Security" value="max- age=31536000" />
<add name="Content-Security-Policy" value="default-src 'self' 'unsafe-inline' 'unsafe- eval' data: https://online.swagger.io:* https://online.swagerapp.pendo.io:* cdn.pendo.io:* pendo-io-static.storage.googleapis.com:* kendo.cdn.telerik.com:* fonts.gstatic.com fonts.googleapis.com
maxcdn.bootstrapcdn.com cdnjs.cloudflare.com https://api.mdguidelines.com http://tablet.sigwebtablet.com:* blob: http://tablet.sigwebtablet.com:*" />
<add name="X-Content-Type-Options" value="nosniff" />
<add name="X-XSS-Protection" value="1" />
</customHeaders>

  1. In the package\config folder, there is a file named ‘utils.config.sample’. The file contains a sample key. You must create a new ‘utils.config’ file with the actual key.
    Note: This key will be provided by Cority Support.
  2. To recycle the web publishing service and IIS, open a command prompt as an administrator and enter the following commands:
    • net stop was /y
    • net start w3svc
    • iisreset
  3. Locate the site’s root folder and create a new folder titled ‘Logs’. This is the folder where log will be created.
  4. Open the “package\web.config” file change the “stdoutlogenabled” value to true from its default “false”.
