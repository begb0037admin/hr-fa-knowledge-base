Data Tags

The data that is transferred from the Management System to TRI Reporter is stored in parameters on the EMS tree. The tags for these requirements follow the pattern of the location tags.

Facility Data Tags

The facility data tags are built by concatenating the following:

'E:TRI_' Facility Code '_' TRI Section '_' CasNo

An example stream tag is

E:TRI_GV_5.2_N020

Dioxin Tags

Dioxins were previously stored as percentages and then allocated in Schedule 1 according to the percentage values. They can now be calculated by more accurate means in the Management System and the values transferred into TRI Reporter. The speciation values are pulled directly into Schedule 1 without further manipulation.

Calculation Method: There is one requirement for Dioxin with the standard requirement TRI tag and one requirement for each speciated dioxin chemical with the following tag scheme:

'E:TRI'_'Facility Code'_'TRI Section'_'CasNo'_'[01-17]'

An example dioxin tag is:

'E:TRI'_'DM'_'5.2'_'N150'_'01'

If these tag values are present and tagged, they will be used to populate Schedule 1. If they are not present, the previous methodology leveraging the percentages will be used.

For percentage calculations: There is one requirement for Dioxin with the standard requirement TRI tag. Custom fields on the requirement are used for speciation percentages, and the values are used to allocate the dioxin percentage per release for Schedule 1. The custom fields TRI DIOXIN Pct [01-17] are associated with the TRI Dioxin custom field template on each chemical.
