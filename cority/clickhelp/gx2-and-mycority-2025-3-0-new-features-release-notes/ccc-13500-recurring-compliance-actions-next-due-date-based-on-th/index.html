CCC-13500: A user can now set up recurring compliance actions that have the next due date based on the previous completion date

Opt-In

To support this, on the Recurrence Settings screen, there is now a new ‘Based Off Completion Date’ check box. The check box will only be available if the Daily ‘Every <N> Day(s)’ recurrence pattern is used. It can only be used with that recurrence pattern.

When the user sets up a recurrence pattern of ‘Every <N> Day(s)’ with the new check box selected, the initial action will be created but no future actions. The due date for the initial action must be set to today or later.

When an action is completed early (for example, the Completion Date is provided before the Due Date), then the next action will be created as part of the daily Hangfire Service. The due date of the newly created action will be the prior action’s Completion Date plus the number of days specified in ‘Every <N> days’.

When an action is not completed early (for example, there is no Completion Date populated and the Due Date is Today), then the next action will be created as part of the daily Hangfire Service and the Due Date for the new action will be the prior action’s Due Date plus the number of days specified in ‘Every <N> days’. This will prevent a recurrence series from prematurely ending due to failure of an action being completed.

Any fields that are configured to copy will carry over to all future actions that get created.

When the End Date of the recurrences will arrive before the Completion Date of the last action plus the number set in ‘Every <N> Day(s)’, a new action will not be created, and the latest one completed will be the last.

All configured role security for recurring compliance actions will apply to, and work in conjunction with, this functionality.

The ‘Next Action Due’ check box will always be selected on the currently due action and deselected on all completed actions.

The ‘BasedOffCompletionDate’ field will be available for use in the Import Utility and Cority Data Integration Utility for importing recurring compliance actions.

As with other recurring actions, these will also be tracked by the ‘Recurring Actions Services Log’.
