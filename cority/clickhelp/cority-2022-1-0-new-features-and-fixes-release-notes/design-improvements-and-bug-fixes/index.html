CCC-6700Case Management – Occupational Health

The 'Audit Note Type' field can now be added to custom versions of the following two layouts:

  • To Do Activity (ML-000070)
  • Case Activity layout (ML-000071)

The field is a picklist of the entries in the 'Audit Note Type' look-up table.

The field can be prohibited from a user's role.

The field is available for use in Query Builder and Report Writer.

The corresponding column can now be added to custom versions of the following Case Management list views:

    • Incomplete (Closed) To-Do Records for This Case
    • Complete To-Do Records to This Case
    • To-Do Records for This Case
  • Case Notes (including Clinic Visit Notes)
    • Activities for This Case
    • Activities and Complete To-Do Records for This Case
    • Activities and Incomplete To-Do Records for This Case

On those list views, it can be used for criteria and sorting.

CCC-6126 and 5973Chemical Management

A public chemical product link can now be appended so that it takes the user to a GX2 Chemical Product list view. Simply adding the list view's ID (<ID>) to the public chemical product link (for example, URL.../publicchemproduct/publiclogin.rails?view=<ID>) will accomplish that.

This enables organizations to provide publicly accessible, pre-filtered, chemical product lists (configured with only relevant columns) to chemical handlers, giving them barrier-free access to relevant SDSs.

Any GX2 Chemical Product list view used must first be designated Standard by its creator for others to access it.

Note: All Chemical Product records with the 'Exclude From Public Links' check box selected will be excluded from such list views.

Also, you can now configure saved chemical labels to be viewable and printable from these public Chemical Product list views.  

To support that, the new 'Public Label' field can now be added to custom versions of the 'Chemical Product Label' (ML-003622) layout.

  • The new field is a check box that makes a saved label both viewable and printable from a public Chemical Product list view.|
  • The new field cannot be imported using the Import Utility.

In addition, a new action named 'View/Print Labels' has been added to the Actions menu on such public Chemical Product list views.

  • The new action will open a list view containing all 'Chemical Product Label' records for which the 'Public Label' check box is selected. That view cannot be cloned or edited.
  • From that view, if the user selects a record and clicks the action, the corresponding label will bypass the label preview step and download as a printable PDF file.

CCC-5027Industrial Hygiene

To satisfy the requirements of the European EN 689 workplace exposure standard, on the 'Risk Assessment Decision Analysis' layout (ML-000946), an industrial hygienist can now:

  • Acquire the 70% upper tolerance limits (UTLs) for both the normal and lognormal distribution 95th-percentile exposure estimates.
  • Perform an exposure compliance test between both the normal and lognormal UTLs and the OEL, for exposure profile acceptability.
  • Perform a dataset-screening test when running a data analysis, as per the EN 689 standard. This includes whether any data points exceed the OEL.
  • Perform a U-test for group compliance of the dataset when running SEG data analysis.
  • View the results of required EN 689 calculations clearly displayed in the new 'EN 689 Compliance Statistics' subsection.

These are all run and calculated using existing I.H. decision / data analysis features and functionality. For information on how to work with that functionality, see the Cority GX2 User Guide.

CCC-4001Platform - Administrator

The existing 'Authentication Method' system setting now has the new 'Mixed Mode (SSO SAML 2.0 and UserID/Password)' option.

When that option is selected, the default GX2 login screen will request the user's username and password.

  • In addition, the default GX2 login screen now has the new 'Login with SSO' button.
    • If that button is clicked, the user will be directed to your organization's IDP SSO login screen (as defined in the 'SAML Key' look-up table record that is set to 'Default for Main Application').
  • When mixed-mode authentication is on, if you want your users to be taken directly to your IDP's login screen without having to click the 'Login with SSO' button, your administrator must modify your GX2 URL to include the additional, required URL parameter. For example:
    • https://client.cority.com/security/login.rails|https://t1.
      coritydev.io/security/login.rails will take users to the default GX2 login screen, where they can enter their username and password or click the 'Login with SSO' button to be taken to your IDP's login screen.
    • https://client.cority.com/security/login.rails?
      idp=GX2_A|https://t1.coritydev.io/security/
      login.rails?idp=GX2_A will take users directly to the GX2_A IDP login screen (as defined in the 'SAML Key' look-up table record that has the code that equals to GX2_A).

Note: When in mixed-mode, users can only log in with their username and password if the 'Allow Mixed Mode Authentication' setting is selected in their user profile.

For standalone links, if mixed-mode is specified, users will only have the option to log in with username and password (not with SSO).

 

CCC-3772Platform – Administrator, End-User

For users who rely on the 'Employee Contacts' table to email information to an employee's contacts, there is a new BR-100552 business rule for updating that table with any contacts for the employee that have been entered ad-hoc on an Employee letter.

The business rule works in conjunction with the new BRA-100553 business rule action, which will check the table for duplicates to ensure only those not already in the table get added.

For a contact entered ad-hoc on an Employee letter, only the email address is provided, so when such a contact is added to the 'Employee Contacts' table using the new business rule, the new table entry will have an email address only (no other information).

Any new 'Employee Contacts' table entries can be updated with other information after the business rule is run.

If the email address for an entry in the 'Employee Contacts' table is changed manually afterwards:

  • No change will be made to any of the letters that used that contact email address prior to the change.
  • The change will not be made to the add-hoc contact email address on the Employee letter.

 

CCC-2368Platform – Administrator

You can now configure a business rule that has the 'Create Record' business rule action (BRA) to provide a redirect to the newly created record.

To support this, the 'Create Record' BRA layout now has the new 'Prompt for Redirect' check box.

Warning: Only one 'Create Record' BRA with redirect can be added to a business rule, and only one should be added. We strongly recommend you do not change the configuration in order to add another BRA to the business rule. Also, the prompt for redirect feature is not intended for use with, therefore should not be added to, scheduled BRAs.

When the new check box is selected and the BRA is triggered, a dialog box with the following message opens: "A new record has been created by a business rule action. Navigate to that record?"

  • If the user clicks Yes, the dialog box will close and the newly created record will open.
  • If the user clicks No, the dialog will close and the screen will remain as it was when the BRA triggered.

Note: The redirect will not open the record if the user's role does not have the necessary security configured.

For 'Findings and Actions', if several Action records are created, the redirect will open the first one created.

If more than one business rule with a 'Create Record' redirect are triggered seemingly at once, the redirect will open the record created by the first business rule that triggered.

This redirect feature with dialog box is currently not functional for:

  • Event Report records
  • Incident records
  • Change Request records
  • Applicability Assessment records
  • Equipment records
  • Respirator Fit records
  • Any records within myCority

That will all be added in the near future.

 

CCC-1067Platform - Administrator

A scheduled business rule (SBR) can now be configured to run, regardless of whether or not its condition(s) have changed since it was scheduled.

To support this, when the execution type for a business rule is 'Scheduled', the new 'Do Not Check BR Conditions On Run' check box is now provided. By default, the check box is not selected.

Note: The check box is editable, regardless of condition type.

If the check box is selected:

  • The SBR will run at its specified execution time, regardless of whether or not its condition(s) are still valid.
  • The 'until BR conditions fail' recurrence option will be disabled.

If the check box is not selected:

  • The SBR's condition(s) will be checked again right before execution time, and the SBR will not run if the condition(s) are no longer valid.
  • The 'until BR conditions fail' recurrence option will be enabled.

CCC-5832,5538, 5228, and 4682Platform – Interfaces

A GX2 administrator can now obtain a list of roles for a user and update/assign a user's granted roles through the RESTful API.

Note: This does not support the creation of roles, only the ability to update a user's role(s).

To support this functionality, there is a new GET and POST endpoint for roles and GET and POST endpoint for security:

  • <virtualdirectory>/api/role
  • <virtualdirectory>/api/security

 

Also, for any data values saved by the RESTful API through a POST/PUT call (for example, <script>confirm(1)</script>), on GET those values will be encoded so that there are no pop-ups. This ensures that saved potential cross-site scripting (XSS) values are not output through GET calls.

As well, when a user of business rule (BR) API actions makes an API call to a token endpoint that returns an access token in text/plain format, that token can then be mapped in the response body to the GX2 API Token look-up table (therefore, you are not limited to the application/JSON and multipart/form-data formats).

In addition, a user of BR API actions can now map multiple records from the received RESTful API response.

Finally, a number of UX enhancements have been made so that the importing of Tree Master records and data with the RESTful API is now more user-friendly.

For information on working with BR API actions, see the Cority GX2 User Guide. For information working with the RESTful API, see the Cority RESTful API Guide.
