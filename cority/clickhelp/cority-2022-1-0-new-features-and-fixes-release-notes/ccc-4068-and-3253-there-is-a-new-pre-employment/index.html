CCC-4068 and 3253: There is a new pre-employment, recruitment process

  • The workflow is as follows:
  • An applicant reaches out to a recruiter when applying to a job within his or her current organization or when applying to a job with another organization.
  • The recruiter will log into myCority and start an application on behalf of the applicant.
  • In myCority, on the recruiter’s ‘Create New’ screen, there is now the ‘New Employment Registration Form’. This is a Cority-created questionnaire that resides within GX2.
    • On the form the recruiter has to add, or if the employee is not already in the system, create an employee for the application, and then finish filling out the rest of form.
    • The Employee field is empty by default. On the picklist, a new list view can be created from the default list view. This enables your administrator to restrict recruiters from seeing certain or potentially sensitive employee (applicant) information. The picklist will also be appropriately restricted by security configuration.
      • Whether or not the employee is already in the system, the recruiter must click the + icon at the top right of the picklist. That will open the new ‘Applicant Demographics Portal’ layout, which is used for adding a new employee to the Employees table.
      • If you have site security requirements, we recommend you create and use a custom version of the layout, and on that version make the secured GDDLOFB field(s) required so that recruiters must specify something for any new employee’s GDDLOFB. This will make the process more secure and make it easier for the resulting data to be accessed and viewed.
      • Once a new employee is saved in the ‘Applicant Demographics Portal’, a corresponding new Employee record will be created in the Demographics module, a notification email will be sent automatically to the email address that was entered for the new employee (the applicant), and the job position specified will be added to the Job Positions tab of the new Employee record. However, if the email address is already provided on an Employee record within the system, instead of creating a new Employee record, the system will update the existing one. Note: On any such Employee record, new or existing, the first new job position will be marked Primary and given the date of application submission for its Start Date. Additional job positions will not be marked as such, but will still have the application submission date for their Start Date.
        • Note: Because recruiters do not need to know a lot about an applicant, and to limit the amount of data they need to enter about each applicant, we recommend you use the out-of-the-box Applicant Demographics Portal layout (if no site security is required) or a slightly modified custom version of it and refrain from adding any employee fields that do not have a counterpart on the Job Position tab (for example, Date of Birth).
    • The last question on the ‘New Employment Registration Form’ (‘Select a Starter Questionnaire’) is required and is a subquery to a filtered picklist of all public questionnaires in GX2 that are marked as Medical. The subquery, which is Cority-created and resides in GX2, is named ‘Applicant Starter Questionnaire’. When answering the last question, the recruiter is selecting the questionnaire the applicant must fill out to start his or her application process. You can refine the ‘Applicant Starter Questionnaire’ subquery to further filter the available questionnaires.
      Note: You can choose to have your Cority Administrator create the questionnaire the applicant will be submitting for medical clearance. That must be done using the Questionnaire look-up table and new tab in that table named ‘Auto-Clearance Choices’. The new tab can be added to any custom questionnaire question layout. For information on how to build questionnaires in GX2, see the Cority GX2 User Guide. The new tab links to any question that has valid choices set up, so any question type that supports the valid choice structure will be provided as an option on the tab. Your administrator could set up a questionnaire name Pre-employment, for example, with Yes or No valid choice questions such as Do you have heart disease? Do you have asthma? Do you have Diabetes? etc.
  • Once the recruiter has completed and submitted the ‘New Employment Registration Form’, an email will be sent automatically to the applicant. The email contains a link the applicant will use to register and a link to the questionnaire the recruiter specified.
    • The applicant is instructed in the email to register first—open the form, add some contact information, and create myCority login credentials. Note: On the registration form, the applicant must use the same email address he or she provided the recruiter.
    • Once the registration form is submitted, the system will send the applicant an email with a verification code and a separate email with a link for entering that code. When verification is successful, the applicant can then open the original email, click the link to the questionnaire, log into myCority with his or her new credentials, and then fill out the questionnaire.
    • When the applicant submits that questionnaire, a Cority-created business rule will then trigger and use the new, auto-clearance configuration (which is to be created by your Cority Administrator using a questionnaire) to assess whether or not the questionnaire response matches the necessary criteria. Note: By default, auto-clearance is designed to clear the applicant for the job position if all of the answers to all of the questions in his or her questionnaire response pass.
      • For branch questions (questions with children), a pass within the branch will pass the entire branch.
        • Example:
          Do you smoke? Yes (No is the pass)
          How many cigarettes per day? 2 (2 or less is the pass)
          For this example, the entire question branch would pass.
      • If no auto-clearance configuration is provided, the default is a fail and the applicable fields would have to be filled in manually.
    • If the entire questionnaire response matches (passes), the new Auto-Cleared check box on the applicant’s Employee record will become selected automatically, and the new ‘Fit For Duty Clearance Status’ and ‘Fit For Duty Clearance Date’ fields will become populated automatically.
    • If the questionnaire response does not pass, the clinician can then decide if the applicant requires further evaluation, more testing (perhaps in person), etc. If that is the case, the clinician can update the ‘Fit For Duty Clearance Status’ and ‘Fit For Duty Clearance Date’ fields manually.
  • Once the applicant submits the starter questionnaire, the recruiter can use the new My Applicants module in myCority to track and manage his or her applications only. The new module has Not Cleared and Cleared lists, which filter the application records accordingly.
    • Both lists can be filtered by either Submitted or Cleared (depending on list) in the last 7, 30, 60, 90 days. If 90 days has passed, the record will not be available in the myCority My Applicants module, but will still be available in GX2.
    • Not Cleared lists the records for applicants who have not yet been addressed, did not clear automatically, or cleared automatically but the status was manually changed afterward to a not cleared status.
    • For deciding which statuses populate the Not Cleared or Cleared list, the new ‘Clearance Status Type’ drop-down field (with explanatory hover-over) can now be added to  custom versions of the Clearance Status look-up table layout. Your Administrator must select either Not Cleared or Cleared for that field on every entry in that look-up table as required set-up for the auto-clearance functionality. For example, if the Cleared With Restrictions entry has the Cleared value selected for the new field, then Employee Job Position records with that clearance status will be listed in the Cleared list in the myCority My Applicants module.
    • To support the auto-clearance process, the following new fields can now be added to custom versions of the Employee Job Position layout:
      • Delay Reason – A picklist to the Delay Reason look-up table from which multiple reasons can be selected. The reasons will be concatenated and displayed for the record in the appropriate list of the myCority ‘My Applicants’ module.
      • Restriction – A picklist to the Restrictions look-up table from which multiple values can be selected. The restrictions will be concatenated and displayed for the record in the appropriate list. Note: This new Restrictions field is not in any way linked to the existing Restrictions tab in the Demographics module.
      • Recruiter – A read-only text field that auto-populates with the name of the recruiter who in the beginning inserted the Employee record along with the job position.  
      • Cleared By – A picklist to the Users look-up table.
    • Any data not available on an Employee Job Position record, will not be simply not be displayed for the record in the myCority My Applicants module.
  • In case you want to exclude a particular job position from the auto-clearance process (for example, the job is particularly safety-sensitive), the new ‘Exclude From Auto-Clearance’ check box can now be added to custom versions of the Job Position look-up table layout. Note: Since the job position will bypass the auto-clearance process, any associated fields that would become auto-populated as a result of that process will then have to be populated manually once an applicant has been evaluated in person.

Important: If you want to modify any component of this process for use in another way, we recommend you contact your Cority Professional Services Consultant or Success Manager first for assistance because you risk altering it adversely, complicating or breaking the workflow, and generating bad data.
