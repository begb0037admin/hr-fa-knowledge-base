CCC-3924 and 3923: Foundational integration between the Cority GX2 and EMS platforms is now complete

  • This will enable (for examples):
    • Cority Professional Services personnel to explore, test, and configure integrated solutions across the two environments without having to make any, often tedious manual changes.
    • Cority Implementation Consultants and/or Solutions Managers to easily test and port integrated configurations during implementations without having to make modifications to the base URL for EMS pages in embedded mode or make modifications to the API URL, username, or password for business rules that call the EMS API.
    • Such personnel to easily create relationships between the Cority Organizational Tree nodes and the EMS Compliance Object table (Locations and Programs on the UI).
  • As well, the GX2 Equipment Management functionality has been enhanced to support EMS requirements.
    • The following two fields can now be added to custom versions of the 'Equipment Type' look-up table layout:
      • EMSTemplateCOID - a text field
      • EMSTemplateCOType - a drop-down list with Unit and POI options
    • The new EMSCOID text field can be added to custom versions of the Equipment layout.
    • Once an EMSTemplateCOID value has been specified for an Equipment Type, for Equipment records of that type:
      • The record cannot be saved unless a Level 2 or Level 3 node has been specified for the 'EMS - Controlling Org Tree' for the Equipment Type when the EMSTemplateCOType value is POI.
      • The record cannot be saved unless a Level 2  node has been specified for the 'EMS - Controlling Org Tree' for the Equipment Type when the EMSTemplateCOType value is Unit.
      • The description must be 100 characters or less.
      • No two records can have the same description and 'EMS - Controlling Org Tree' node.
    • Once an EMSTemplateCOID value has been specified for an Equipment Type, the creation of a new Equipment record of that type will result in:
      • The new record existing where appropriate in GX2 and a linked (IDs saved in both systems) compliance object being created in EMS.
      • A new business rule action record (BRA-100601) being added to the BRA queue for processing.
      • The Cority Equipment ID being written to the 'Cority ID' field in EMS.
      • A RESTful API call to the EMS for which the response will write the ID of the newly created compliance object to the EMSCOID field in GX2.
    • Changes to the description of an Equipment record in the 'Controlling Org Tree' will result in:
      • The renaming of the linked compliance object in EMS.
      • A new BRA record (BRA-100601) being added to the BRA queue for processing.
    • Changes to the 'EMS - Controlling Org Tree' value of an Equipment record will result in:
      • The relocation of the linked compliance object in EMS.
      • A new BRA record (BRA-100601) being added to the BRA queue for processing.
    • Deletion of an Equipment record will result in:
      • A new BRA record (BRA-100601) being added to the BRA queue for processing.
  • In the Emissions Inventory 'Asset Management' module, you can now add the new, filterable 'EMS Requirements' tab (sublist) to custom versions of Asset layouts.
  • This is accompanied by the new 'EMS Requirements Data View Per Layout' look-up table. The out-of-the-box layout for the look-up table has the following two fields:
    • Layout - a searchable drop-down list of all layouts in the GX2 system
    • EMS Data View - a drop-down list populated by a RESTful API call to the EMS EQL service

  • When the user opens the 'EMS Requirements' sublist on an Equipment record, its list will be retrieved and populated by the RESTful API call.
    • Each record in the sublist will have a hyperlink to the EMS 'Edit Properties' page of the requirement.
    • Each record in the sublist that is a numeric requirement will also include a Graph action, which will graph the requirement using the EMS 'Calc Graph Visualizer'.
