CCC-10401: You can now assign questionnaires from a record within any solution (or module) that uses questionnaires

  • To support this the following fields can now be added to custom versions of Questionnaire Header layouts.
    • Assigned To [Employee] - a picklist that uses the Employees look-up table picklist field
    • Assigned To [Team] - a picklist, filtered by cloud, that uses the 'Groups and Teams' look-up table
    • Notify on Submit - a picklist that uses the Employees look-up table
    • Due By - a date field
    • Submitted Date - a read-only date field that populates automatically
  • The fields are available in Query Builder and Report Writer.
  • They are available for use in business rules, business rule actions, and display rules.
  • They can be populated/updated using the Import Utility or the Cority Data Import
  • Utility.
  • The corresponding columns are available for adding to custom versions of applicable list views.
  • Specifically, the layouts that support this are:
    • Environmental: ML-001444 and ML-001443
    • Ergonomics: ML-001446 and ML-001445
    • I.H.: ML-001442 and ML-001441
    • Quality: ML-003185 and ML-003184
    • Safety: ML-001000 and ML-000715
    • Training: ML-001934 and ML-001933
    • myCority: ML-003605
  • The initial rollout does not include Medical (O.H.) questionnaires due to additional security considerations.
  • When the 'Assigned To [Employee]' or 'Assigned to [Team]' fields are completed on a supported Questionnaire record, the record will become accessible in myCority for assignee(s) using the Questionnaires icon in the 'Filter by' section.
  • Note: Only one of the 'Assigned To [Employee]' or 'Assigned to [Team]' fields can be populated.
  • A business rule (BR) can be created to notify assignees, remind them as the Due Date approaches and/or when a questionnaire becomes overdue.
  • Another BR could be configured that upon submission of a questionnaire from myCority notifies the appropriate stakeholder(s). That BR could pull from the Questionnaire Header or from the parent record, which would require a distribution list.
  • The general QuestionnaireResponseHeader entity should be used:
    • When triggering the BR/BRA to send an email to 'Notify On Submit' from myCority, regardless of the initial parent/source record.
    • When triggering assignment emails from solutions within a particular cloud, except for those assigned directly from a particular questionnaire solution within any given cloud.
  • The <cloud>QuestionnaireResponseHeader entity should be used for questionnaires assigned directly from the corresponding questionnaire solution.
  • Please note the following limitations:
    • From the Questionnaires sublist, the user cannot inline add a new questionnaire and then assign it to a team or inline edit a questionnaire to alter the 'Assign To Team' selection. Those specific changes can only be made from the layout.
    • From a particular questionnaire solution list view, the user cannot add a new questionnaire or inline edit to alter the 'Assign to Team' selection. Those specific changes can only be made from the layout.
  • For information on working with questionnaires, business rules, or distribution lists, see the GX2 User Guide.
