EQLQueries

A type of EMS App Item with special handling is the EQL Query Item.

Any EMS App Item with the extension ".eql" will be handled as an EQL Query.

EQL Queries must have JSON content with the following properties:

eql The EQL query that defines the view. EQL queries may be parameterized using named parameters with an @ sign before them (see the example below). Allowed characters for parameter names are letters, digits and underscores only ([_0-9a-z]). Parameter names are case INsensitive. Parameter values are replaced as TEXT in the EQL query, regardless of the actual value type. See the example below where a list of integers (years) is parameterized as a single text replacement.

cacheMinutes This property is reserved for future use.

keepWarm This property is reserved for future use.

EQL Query Item Example JSON

{

"eql": "select

d.Value,

YEAR(d.Collected) as [Year]

from DataPoint d

join Requirement r on d

where r.Name = @Name and YEAR(d.Collected) in (@Years)"

}

Unlike other EMS App Items, EQL Queries are executed on the server.

To execute an EQL Query, you must issue an HTTP POST or GET request to the Item URL relative to the EMS App root.

A POST request must be a JSON literal with the following properties:

parameters A JSON dictionary of parameter name to value mappings.

Parameter names should NOT be specified with the @ sign preceding them.

Parameter values cannot contain the following character sequences:

quotes (")

tick marks (')

double dashes (--)

slash-asterisk (/*)

asterisk-slash (*/)

page The page number within the entire result set to return.

pageSize The number of records for each page. Maximum page size is 1000. If no page size is specified, the "page" parameter is ignored (if specified) and the entire result set will be streamed in one response.

A GET request may specify parameters to the query as standard URL query parameters, including the "page" and "pageSize" parameters. Parameter names and values should be URL encoded.

Note:  Unlike other EMS App Items, EQL Stored Query Items support the HTTP Basic Authentication protocol.

Example EQL Query POST Request

POST /2012Data.eql HTTP/1.1

Content-Type: application/json; charset=UTF-8

 

{

"parameters": {"Name": "BOD5 Daily Mass", "Years": "2011,2012" },

"page": 1,

"pageSize": 50

}

 

HTTP/1.1 200 OK

Content-Type: application/json; charset=utf-8

 

[

{

"columns":[

{"name":"Value","dataType":"Double","size":-1},

{"name":"Year","dataType":"Int32","size":-1}

],

"rows":[

{"values":["2011", 231.678]},

{"values":["2012", 86406.76]}

]

}

]
