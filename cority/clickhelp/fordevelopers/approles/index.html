App Roles

App Roles are the method for mapping Users and Groups to a level of access or functionality within an EMS App. App Roles may be used to represent any category of User functionality such as "Administrator", "Data Entry", "Inspector", "EHS Manager".

App Roles offer a layer of abstraction from System-specific Users and Groups, such that conditional behavior of an EMS App can be designed without knowledge of the Users and Groups that will be present in a System.

App Roles are maintained separately for each EMS App, such that an "Administrator" Role for one EMS App may not have the same mappings and permissions as an "Administrator" Role in another EMS App.

App Roles are not managed directly through the Management System UI. Instead, the package manifest of an EMS App must be used to create and remove App Roles during development and upload of the EMS App package.

The Administrators of the System are then responsible for mapping concrete Users and Groups to the Roles.

App Roles are automatically hosted as unique URLs under the root of the EMS App, within the virtual App folder "/_PkgRoles".

For example, a GET request to the URL "/_PkgRoles/Administrator" will return "204 No Content" if the current User has been mapped directly or indirectly to the Administrator App Role, otherwise a "403 Forbidden" will be returned.

Additionally, a simple GET request to the URL "/_PkgRoles" will return a list of all Roles, to which the current User has been mapped directly or indirectly.

There are methods in the EMS Apps JavaScript SDK that simplify checking for User Role membership from EMS App pages.

Everyone Role

The App Role "Everyone" is pre-defined for every EMS App, and does not need to be specified in the EMS App manifest.

The "Everyone" Role always maps to every User of the App, and cannot be modified.

Using the "Everyone" Role, you can easily grant or deny access to all Users, current and future, without worrying about Group and User mappings.

Using App Roles

App Roles may be used in one or both of the following ways:

  1. Allow or Deny access for a Role to one or more EMS App Items or App Data keys in the EMS App manifest. This method ensures that any User or Group mapped to the Role, will (or will not) be able to load the Item from the server when using the EMS App. This approach is a strict approach in the sense that permissions are checked on the server and if a User does not have access to an EMS App Item or Data key, the server will respond with a "403 Forbidden".
  2. Use the provided EMS App Javascript Library methods to dynamically determine Role membership at run time and enable or disable functionality appropriately on the client side.

Note:  With either approach, all Permissions and Rights assigned to the User either directly or through Group memberships in the Management System will be strictly enforced when calling the REST APIs.
