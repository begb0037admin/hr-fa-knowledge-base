App Item Permissions

As part of configuring an EMS App, you may specify Role-based permissions for Items within the EMS App.

Permissions are mapped to any valid Item path by a "match string", and all Item paths that match the string are granted the specified permissions. Match strings are matched to paths with a trailing wildcard (i.e. "string*"). If two or more permissions match the same path, "longer" (more specific) match strings take precedence over "shorter" match strings.

For example, the following is a list of permissions and resulting access for successively "deeper" paths:

/Audits/Create

Auditor: Allow

Result: Members of the Auditor Role are granted access to any Items under "/Audits/Create".

/Audits/Review

Manager: Allow

Result: Allow Members of the Manager Role are granted access to any Items under "/Audits/Review".

/Audits/Review/Close.html

Manager: Deny

Result: Deny Members of the Manager Role are denied access (regardless of their membership in other Roles) to the Item "/Audits/Review/Close.html".

For each match string, you may specify a list of one or more allowed App Roles, and you may also specify a list of one or more denied App Roles.

Tip:  You can allow or deny access to the "Everyone" Role to allow/deny all Users (other than Administrators).

Unless specified otherwise, the root (and therefore all Items with an EMS App) default to being allowed for the "Everyone" Role.

When enforcing permissions for a User and Item, Allow and Deny settings are calculated as follows:

  1. The set of all Roles in which the User is a member (either directly or through a Group membership) is collected.
  2. All permission sets which match part or all of the Item path are collected.
  3. The single permission set with the most specific (longer) match string that matches all or part of the Item path is used.
  4. The permission sets are filtered for those Roles in which the User is a member.
  5. If any Role is denied for the Item, the User has no access.
  6. Else, if the User is allowed for the Item at least once through any Role, the User is allowed access.
  7. Otherwise, the User has no access.

EMS Administrators always have access to all Items within all EMS Apps.

Note:  if an application is run outside of the EMS App runtime environment (i.e. non-hosted), permissions cannot be checked and instead all files will be available to the User.
