Permissions Editing Tool

The Permissions Editing Tool allows a system architect to add and edit users and user groups, as well as user permissions. The following functions are available with this bulk tool:

  • Add users
  • Add user access (for users from other Systems)
  • Edit users
  • Delete users
  • Add/edit user groups
  • Edit user group memberships
  • Edit permissions for System Model objects
  • Edit permissions for Citations
  • Edit permissions for Documents
  • Edit permissions for Reports
  • Generate Time Sensitive link email (time sensitive link is sent in the form of an email to user whose password has been reset)

The following function is NOT available:

  • Restore user access for deleted or expired users

The Permissions Editing Template file contains 10 worksheets. Each worksheet can be processed independently.

Users and groups must be created first, then permissions may be assigned. Pay attention to the order of the worksheets when processing.

New Users

When creating new users, a random password will be generated and an email notification may optionally be sent to each user with the password for logging in. If Reset Password is Yes, users will be required to reset their password on first login.

Note:   If the system is not yet ready for users, you can supply a dummy email address to prevent any notifications from being accidentally sent from the system. Also, you can suppress any premature login information by selecting No for the Email Password option. When the system is ready to go live, use the Edit Users tool to edit the user emails, enable the Reset Password option, and select Yes for the Email Password column to send an email notification with the default password.

Security and password options for new users include:

User password does not expire column (column Z): Enter "yes" to keep password from expiring. (This overrides the optional security setting for maximum password age, which expires system passwords after a specific time period.)

User's account is locked column (column AA): To lock the user account so login is disabled, enter "yes". You can use this setting to prevent login during setup, then clear the setting when you edit user accounts to go live.

Email Password (column BA): Enter "no" to suppress automatic emails to users when accounts are created to prevent premature logins. Default behavior is to automatically email new users when an account is created but it may be desirable to suppress emails until users have been trained and/or system is ready to go live. Use the Edit Users worksheet to change emails and reset passwords to activate logins later. (See security and password options for Edit Users.)

Note: This is not the most secure approach. It is recommended to use the "Generate time sensitive link email" column.

During system setup, you may want to set false emails for users to prevent notifications (task and workflow notifications, data warnings, etc.) while the system is being tested. You can also disable login temporarily.

Generate time sensitive link email column (column BC): To reset the user password, enter "yes". The system will send an email to the user with a time sensitive password reset link. When the user clicks the link, the user will be taken to a log in page with two fields to fill, one to put in a new password the other to confirm the new password. If the field has "no" or is blank, no password reset link is sent to the user.

Optional information fields are also available.

To assign user rights (blue column labels, AB-AY), enter "yes" or "no" (or leave blank). Note that user rights are best assigned through user groups.

New User Access

Enter the username (user login) as set up in the home system. This is the only required field.

After new user access has been created, the user may be added to groups on the User Group Memberships worksheet and/or granted permissions on the permissions worksheets.

Edit Users

You can edit user login name, email, personal information and user rights from this worksheet. The current username is the id. All other fields are editable.

Security and password options also allow you to edit "go live" information for users once the system is completely setup. If user accounts have been given with invalid email addresses for configuration purposes, you will need to edit the emails first. Then activate user logins by selecting the Reset Password option to send an email notification with the default password. (Two passes with the upload are required so that the email goes out to the new email address.)

Security and password options for editing users include:

Reset Password column (column C): To reset the user password, enter "yes". The system will generate a random password and send email notification to the user with the new password. If "no" or blank, no change is made to the existing password.

Reset password with time Sensitive Link Email column (column BF): To reset the user password, enter "yes". The system will send an email to the user with a time sensitive password reset link. When the user clicks the link, the user will be taken to a log in page with two fields to fill, one to put in a new password the other to input the new password again to confirm the new password. If the field has "no" or is blank, no password reset link is sent to the user.

Expire user account column (column H): To expire the user access, enter an expiration date.

Lock/unlock user account column (column AE): If user account is locked, enter <clear> to unlock. To lock account, enter "yes".

Require user to change password column (column AB): To require that the user change the password at next login, enter "yes" . Enter <clear> to remove this requirement.

User password does not expire column (column AD): Enter "yes" to keep password from expiring. (This overrides the optional security setting for maximum password age, which expires system passwords after a specific time period.) Enter <clear> to remove this option.

Delete Users

To delete users, the only required field is the Username (user login).

Deleting a user will mark the user as deleted in the system and remove all permissions. Past user history in the system will not be deleted.

User Groups to Add or Edit

To create a new user group, enter user group name. Use the next worksheet (User Group Memberships) to add users to the group.

To edit the name of an existing user group, enter current name in column A and new name in column B.

To assign rights (blue column labels C-X), enter "yes". Use <clear> to remove an existing right from the group.

User Group Memberships

One user or group per row. Multiple users/groups per cell are not allowed.

In Action column enter Add to add user to group, or Remove to remove user from group.

Users are identified by username (user login).

Object Permissions

One user or group per row. Multiple users or groups per cell are not allowed.

To grant a permission enter "yes". Use <clear> to remove an existing permission.

To add a user or group to the permissions on the object, at least one Permission column must be "yes".

If user has an existing permission on an object, and the column is left blank, the existing permission will not be changed. To remove an existing permission for a user, enter <clear>.

Citations Permissions

Enter the path to a Citation folder or Citation in the format:

\FolderName or \FolderName\Citation

Enter one user or group per row. Multiple users or groups per cell are not allowed.

To grant permission to a Citation, enter "yes" in the appropriate permission column (in blue). Enter "no" or use <clear> to revoke an existing permission.

When path is to a folder, to apply the same permission to all child folders and citations, enter "yes" in column F.

Documents Permissions

Enter the path to a Document folder or a Document, in the format:

\FolderName or \FolderName\Document.ext (include file-type extension).

Enter one user or group per row. Multiple users or groups per cell are not allowed.

To grant permission to a Document, enter "yes" in the appropriate permission column (in blue). Enter "no" or use <clear> to revoke an existing permission.

When path is to a folder, to apply the same permission to all child folders and documents, enter "yes" in column F.

Reports Permissions

Enter the path to a Report folder or Report in the format:

\FolderName or \FolderName\ReportName

Enter one user or group per row. Multiple users or groups per cell are not allowed.

To grant permission to a Report, enter "yes" in the appropriate permission column (in blue). Enter "no" or use <clear> to revoke an existing permission.

When path is to a folder, to apply the same permission to all child folders and reports, enter "yes" in column F.
