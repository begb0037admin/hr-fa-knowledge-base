Using the REST API

The EMS REST API allows you to build applications that interact with EMS in more complex ways than the integrations provided out of the box.

Basics

The Web API consists of HTTP RPC-style methods, all of the form:

https://api.enviance.com/version/service/method

All methods must be called using HTTPS. Arguments can be passed as GET or POST params, or a mix. The response contains a JSON object, which will always contain a response code status, indicating success or failure.

Every REST API request must be authenticated by providing a bearer token, which identifies a single user. This token is also referred as session ID.

A token can be acquired by first calling the authenticate session API:

POST /ver2/AuthenticationService.svc/sessions

HTTP/1.1 Content-Type: application/json; charset=UTF-8

{

userName: "username",

password: "pass111"

}

Response Content:

"8d679d4e-32d8-4864-8754-6f3f9bd27235"

The session token can then be utilized on all subsequent API calls, as demonstrated below by performing an EQL query :

POST /ver2/EqlService.svc/query HTTP/1.1

Host: api.enviance.com

Content-Type: application/json

Authorization: Enviance 8d679d4e-32d8-4864-8754-6f3f9bd27235

Cache-Control: no-cache

Postman-Token: 81434362-7896-2861-3528-bab31f6059fe

{

"eql": "SELECT f.name from Facility f",

"page": 1,

"pageSize": 10,

"format": "json"

}

Response headers:

cache-control : no-cache

content-type : application/json; charset=utf-8

date : Wed, 04 Oct 2017 18:56:19 GMT

envapi-eql-ecucall : 0.014

envapi-eql-ecuperiod : 0.445

envapi-remaining-calls : 995

envapi-remaining-interval : 103

envapi-version : 2.0

expires : -1

pragma : no-cache

server : Microsoft-IIS/8.0

transfer-encoding : chunked

x-aspnet-version : 4.0.30319

x-powered-by : ASP.NET

Note that every REST api call returns specific “envapi-xxx” response headers. They are informational headers that may include information about api usage and limits :

envapi-remaining-calls : Indicates how many API calls current session can still execute for the current period of time (interval, below) .

envapi-remaining-interval : Indicates how many minutes are still left for the current time period, until all counts/limits are reset.

envapi-version : Indicates the version of EMS API.

envapi-eql-ecucall : EQL-specific response header. Indicates how “heavy” your EQL call was. It's a count of how many resources ( in aggregate) your query consumed.

envapi-eql-ecuperiod : Count of how many ECUs have been consumed across the system for the current time period.

About envapi-remaining-calls and envapi-remaining-interval

How does that work?

We have a limit on the number of calls (for instance, 5k) for a given period of time (for instance, 60 minutes). As you make API calls, the remaining calls decreases. As the time passes by, the remaining interval period decreases.

Once remaining calls limit reaches 0, you cannot make more calls.

Once the remaining interval reaches 0, we reset both limits back to default( 5k for calls, 60 for periods). So you can resume making your calls.

Does that work in a way where as long as I have remaining calls, and the interval hasn't reset, I can keep calling?

Yes.

Also, is the count different for each service that we call? For example, can the query response process more requests than say the EventService?

Yes.
