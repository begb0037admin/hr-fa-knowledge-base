Error Handling

After sending a command to the EMS Web Services, you need to monitor and handle any errors that may occur. Error handling in web services depends on whether calls are synchronous or asynchronous.

Most EMS APIs are synchronous, unless "async" is indicated in the name. You often have an option to use the synch or "async" version, according to your purposes.

Synchronous calls: Once a command is sent, other processing stops until the transaction is complete or fails. An error is generated and the process stops. You must then capture the response and handle the error before continuing.

Asynchronous calls: Calls are made asynchronously, which means that the command is queued and the client can continue with other processing in the meantime rather than wait for the response. For asynchronous calls, you will need to get the command ID and poll the command status until it is complete or errors.

To get the command status with the REST APIs, use GET/Command/{commandId}

Example:

GET /ver2/CommandService.svc/commands/08fc5438-a0d8-4bf9-9141-12dd98e7ce80/ HTTP/1.1

If you are using SOAP web services, you can use the function:

CommandStatusCode GetBatchStatus(GUID batchID)

located in DataService.asmx. See DataService.
