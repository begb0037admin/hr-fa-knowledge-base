App Data Storage

In cases where data needs to be persisted for the User across multiple executions of an EMS App, and cookies are not an option for various reasons (security, being tied to a browser, data size), the EMS App Data Store may be a better option.

The EMS App Data Store allows setting arbitrary key-value pairs of data (the data should be JSON encoded), for the current User, or for all Users of the EMS App.

There are methods in the EMS Apps JavaScript SDK that simplify using the EMS App Data store from EMS App pages.

Note:  If an application is run outside of the EMS App runtime environment (i.e. non-hosted), the EMS App Data Store cannot be used. JavaScript shims can be used to simulate this storage locally however.

User Data

User data is always private to the current User, so two Users will never see the same data, even if the same key is used to identify that data. To save, get and delete User data, use the user data functions in the EMS App SDK.

User data can also be automatically deleted (but not created or updated) when updating an EMS App using the EMS App package manifest.

App Data

App data is potentially available to any User of the EMS App, depending upon their permissions.

App Data keys are unique for each EMS App, and saving data with a given key will overwrite any existing data for the same EMS App and the same key.

To save, get and delete App data, use the app data functions in the EMS App SDK.

Keys can have their access restricted by Role for permissions management in the package manifest.
