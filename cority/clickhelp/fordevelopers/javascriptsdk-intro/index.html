Requirements

The EMS JavaScript SDK depends upon the following third party libraries:

Core AJAX/DOM Handling: jQuery , jquery.1.8.3.min.j

JSON Serialization/Deserialization: json2 , json2.js

These libraries are hosted on the Management System under "/Packages/Libs" for your convenience.

Quick Start

If you choose to use the EMS JavaScript SDK in a custom application, follow these steps for best results.

First, include the library dependencies for the EMS SDK.

<script src="/Packages/Libs/jquery.1.8.3.min.js">

</script>

<script src="/Packages/Libs/json2.js">

</script>

 

Second, include the SDK library from the api.enviance.com website. It is always best to use the latest available version.

<script src="https://api.enviance.com/SDK/ver2/Enviance.SDK.js">

</script>

 

Third, manually configure the base address for the APIs. The base address will almost always be api.enviance.com.

<script

envianceSdk.configure({

baseAddress: "https://api.enviance.com"

});

 

Fourth, authenticate to the APIs.

envianceSdk.authentication.authenticate(username, password);

 

Finally, perform any desired work/calls to the SDK.

…

</script>

Handling Results and Errors

All of the methods in the JavaScript SDK take two parameters for callback functions: "onsuccess" and "onerror". These parameters by convention will be the first last two parameters of the method signature.

When programming a JavaScript application, it is recommend practice to use asynchronous callbacks and an event-driven design. This is to allow for a responsive user interface that will not block during the execution of potentially long running remote AJAX calls.

Therefore, you will want to specify a function for the "onsuccess" callback to handle the change in application state that should occur on the completion of a method call.

Specifying a function for the "onerror" callback is optional. If not specified, a generic error handler defined in the SDK will inspect the result of an error and raise alerts with some relevant messages according to the error type.

Call Result Object

The functions to be used for the "onsuccess" and "onerror" callbacks should take a single parameter, which is an instance of the response object.

The result object has the following properties:

metadata This property contains the following "EnvApi-" HTTP response headers as sub-properties:

version

remainingCalls

remainingInterval

warnings

Some other standard response headers and codes are also present, such as:

location

result This property contains the response of the API, if the call is successful. The structure of the data in this property depends upon the API. This property is not present if an error occurs.

error This property contains information about any error that occurs. This property is not present if the call is successful.

From this object, you will have access to the metadata, result, and error properties. The result property will contain the return value of the call during the "onsuccess" callback, and the error property will contain the error details during the "onerror" callback. Note that if the call is successful, the error property will not exist on the result object, and similarly, if the call causes an error, the result property will not exist.

For details on the properties of the Result object, see the section on API Response Data Format.
