Calculations Edit Tool

With the Calc Edit too you can edit calculated requirements in the system, including:

  • Calculation definition
  • Fixed and rolling periods
  • Calculation exceptions
  • Limits
  • Calculation Template fields

When uploading the calculation edit file, there is an option to suppress notifications (by default this is true) so that any data warnings generated by the job will not be issued. The Mailer is disabled during execution and then restored to the state it was in when the job started execution, purging any notifications generated by the job.

Edit Calcs

When editing calculations, you can apply changes in one of these ways with the History Update Type:

Replace: This option deletes all existing calculation histories and replaces them with the new calculation history specified.

Merge: This option will create a new calculation history with the specified start date and at the same time end the current history. The End Date for the current history will be the same as the Begin Date-Time for the new history.

End: This option will simply end date the current calculation history. Script is not required.

Examples (intervening columns not shown):

Requirement Path: Path to the Requirement. Do not include the system model name or "Locations and Programs". Path must start with slash ("\"); end slash is optional.

Requirement Name: Name of the Requirement in EMS.

Begin Date-Time: Required. Date-Time Format: 1/1/2010 12:00:00 AM

End Date-Time: Optional for Replace and Merge updates; if blank, calculation is valid ongoing into the future. Required for End update.

Script: Calculation definition (formula). Provide full path for any requirements that are not under the same parent object; full path not required for requirements in same location.

Divide By Zero: Value of Divide By Zero Exception. Optional.

Overflow: Value of Overflow Exception. Optional.

Other: Value of Other Exception. Optional.

Period Duration: Period Duration (numeric value) for time-based fixed and rolling calcs. Optional for time-based requirements.

Period Type: Period Type. Optional for time-based requirements. Valid values are: Hour, Day, Week, Month, Quarter (or Hourly, Daily, Weekly, Monthly, Quarterly, Yearly).

Intermediate Period Type: Intermediate Period Type. Optional for time-based requirements. Valid values are: Hour, Day, Week, Month, Quarter (or Hourly, Daily, Weekly, Monthly, Quarterly, Yearly).

History Update Type: Valid values: Replace, Merge, End. Replace overwrites all existing histories and replaces it with the new history. Merge adds new history with new script value and specified start date and ends previous history at the same time. End adds an end date to the current history.

Edit Limits

When editing limits, you may use one of three update types:

Replace: This options deletes all limit histories and replaces them with the new limit history.

Merge: This option will create a new limit history with the specified start date and at the same time end the current limit history. The End Date for the current limit history will be the same as the Begin Date-Time for the new history.

End: This option will simply end date the current limit history. Begin and End dates and comparison fields are required.

Requirement Path: Path to the Requirement. Do not include the system model name or "Locations and Programs". Path must start with slash ("\"); end slash is optional.

Requirement Name: Name of the Requirement

Begin Date-Time: Date-Time Format: 1/1/2010 12:00:00 AM

End Date-Time: Optional for Replace and Merge updates; if blank, limits are valid ongoing into the future. Required for End update.

Comparison: Comparison value (pick list). Valid values: >LOW | >=LOW | <HIGH |<=HIGH | >LOW AND <HIGH | >=LOW AND <=HIGH

Regulatory Limit Low Number: Regulatory low limit.

Regulatory Limit High Number: Regulatory high limit.

Internal Limit Low Number: Internal low limit.

Internal Limit High Number: Internal high limit.

History Update Type: Valid values: Replace, Merge, End. Replace overwrites all existing limit histories and replaces it with the new history. Merge adds a new limit history with specified start date and ends previous history at the same time. End adds an end date to the current history.

Calculation Template Fields

Calculation Template fields include the numeric and Boolean fields stored on a Calculation Template.

Note:  You cannot edit calculated numeric fields from the bulk tool. The formula for a calculated numeric field is defined on the template, not on the object to which the template is applied.

Path: Path to object with associated Calculation Template. Do not include the system model name or "Locations and Programs". Path must start with slash ("\"); end slash is optional.

Object Name: Name of the system model object with which the Calculation Template is associated.

Field Caption: Caption of the field from Calculation Template.

Value(s): Value of custom field: Number for number fields, True or False for Boolean fields.

Begin Date-Time: Date-Time Format: 1/1/2010 12:00:00 AM. Required for fields that track value history.

End Date-Time: Optional for fields that track value history.
