SubmitEventInstances

This method can be used to create event instances or update existing event instances.

When creating a new event instance the input parameters are:

  • Event Log ID
  • Requirement ID
  • Event Instance ID
  • Begin and End dates
  • Accept as Deviation
  • Name/Value pair for all custom fields

Creating new Event Instance

Event Instance should have ID property set to null.

RequirementId and EventLogId MUST be set to appropriate Requirement and EventLog. ID can be either TagId or GUIDId type.

Mandatory fields: Begin Date, End Date, Name MUST be set.

RequirementId and EventLogId are independent and CAN be of different type.

Creating new Event Instance with result ID

If client needs to know GUIDs for newly created Event Instances, then temporary ID is used: NewId. NewId indicates client's interest in obtaining GUID of Event Instance to be created. Client should supply some kind of ID to NewId. For each Event Instance where ID is set to NewId, the function result will contain a map of client-supplied ID to EMS GUID generated for this Event Instance.

Updating Event Instance by Tag

When client knows the Ids of existing Event Instances, ID property should be set to TagId. If Event Instances with specified Tags are not found, an error will be generated. The error message will contain tags which do not exist.

Updating Event Instance by GUID

If client knows GUIDs of Event Instances then ID property should be GUIDId.

A batchID is returned for both operations, create and update. The batchID is the input value for GetBatchStatus.

GetEventInstances

This method can be used to return a set of event instances and all of their associated fields. The input is a set of unique event instance tags.
