Best Practices

In order to produce consistent, reliable, robust, and usable EMS Apps, the following guidelines are recommended during EMS Apps development.

DO

  • Use the provided EMS SDK methods to instantiate EMS object types and call EMS APIs.
  • Use the provided EMS Apps SDK methods when generating links to EMS application pages.
  • Use the provided EMS Apps SDK methods to refer to pages/content within the EMS App.
  • Deploy pages related by functionality in a single EMS App, rather than in multiple.
  • Package all third party libraries, styles, images, etc within the EMS App, rather than referring to them on other servers. This ensures that the EMS App will be isolated from unintended changes to code and environments over time.

  • Use only HTML5/JavaScript/CSS3 standards to ensure support for IE8+, Chrome, Safari, Firefox and future platforms.

    Use polyfills if required to bring HTML5/CSS3 features to required browsers.

  • Log any handled errors (especially server request failures, authorization failures, etc) to the console for easy tracing.
  • Use a package configuration file for any assumptions about Management System Model configuration or setup, if the App is to be used in multiple Systems.
  • Use a local package script file to enable local, unhosted development of your EMS App.

CONSIDER

  • Using AngularJS as your javascript framework, if writing any non-trivial application. This is the framework that EMS will be using to roll out user interface controls for rapid development in the near future.
  • Using AngularJS routes within your app to avoid links to specific files that may change over time.

  • Writing targeted read only e2e tests. This will allow you to rapidly verify the correct functioning of your App. Such tests should be implemented in the EMS App as /_PkgTests/runner.html. Tests do not necessarily need to cover all elements of the App, but should at the very least address:

    • Any external API calls (other than EMS APIs).
    • Some DOM manipulation.
    • A few controls that call an API and modify their state according to the response.
  • Following a standard directory structure. The yeoman tool should be used to create the skeleton of an initial app.
  • Before deploying to production, minifying your javascript and css files using a tool like YUI Compressor.
  • Documenting any assumptions about System Configuration, Permissions, Naming, etc. that the EMS App makes in order to work properly. This documentation should be hosted in a file called README.html at the root of the EMS App.

DO NOT

  • Follow coding practices discouraged by the CSP standard. With CSP, any EMS Apps using discouraged practices may break.
  • Package and upload unnecessary files such as version control logs or IDE files.
  • Source or link directly to files in other EMS Apps, as this will introduce dependencies amongst EMS Apps that will be hard to track and manage over time.
  • Hard-code assumptions about Management System configuration, page URLs, or setup.
