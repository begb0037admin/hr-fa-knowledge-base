PATCH

Description:

Updates an existing System Variable. Updating the System Variable Value history data causes merge of old and new collections. Records with the same begin date are updated. Records with different begin dates are inserted. If period is set without any other data, any record that exists with the same period is deleted.

Updating the Custom Field Template of a Requirement object, if that object currently has no Template, adds the Template to the object. When switching from one Template to another Template, those values that belong to fields which are common to both Templates are kept, any values for Fields not in the new Template are removed permanently. Setting the Template to null permanently removes all Custom Field values.

SDK API: envianceSdk.requirements.updateRequirement(requirementIdOrPath, reqInfo, onsuccess, onerror)

SDK API (async): envianceSdk.requirements.updateRequirementAsync(requirementIdOrPath, reqInfo, onsuccess, onerror)

DELETE

Description:

Deletes an existing System Variable. Deletions are permanent. If ‘waitForCompletion’ flag is included, transaction will wait until operation is complete; ‘waitForCompletion’ flag is ignored for Async method.

SDK API: envianceSdk.requirements.deleteRequirement(requirementIdOrPath, waitForCompletion, onsuccess, onerror)

Models

reqCreateInfo 

Create/Copy System Variable body

Name Type Description Required
reqInfo reqInfo   No
copyFrom string The id string (GUID) of an existing System Variable whose properties will be copied and used as the properties of the newly created System Variable. Specifying this property allows you to copy an existing System Variable to another System Variable. Not required for: Create System Variable. Ignored for: Copy System Variable. No

reqInfo 

Represents a Requirement definition. Used for all numeric requirement types, distinguished by “requirementType” property value: Parameter (ParameterRequirement), Calculated Requirement (CalcRequirement), System Variable (SystemVariable), Time-Based Calculated Requirement (TBRequirement), Count-Based Calculated Requirement (CBCRequirement), Time-Based Aggregation (TBARequirement), Time-Based Subtraction (TBSRequirement), Material Activity Calculated Requirement (MACRequirement). Some properties of this structure are ignored during this operation.

Name Type Description Required
id string The id string (GUID) of the Requirement. Ignored for Create Requirement, Update Requirement. No
requirementType string The type of the Requirement. Value must be “SystemVariable”. Required for: Create or Copy Requirement. Ignored for: Update Requirement No
name string The name of the Requirement. Required for: Create Requirement. No
parentIdOrPath string The id string (GUID) or full path for the parent object. Updating the parent path serves to move an existing object to another parent. Required for: Create Requirement No
activeDate dateTime An active date of the Requirement. No
inactiveDate dateTime An inactive date of the Requirement. No
description string The description of the Requirement. No
responsibleUser string A User name. No
templateIdOrName string An id string (GUID) or name of a Custom Field Template. Any string that matches the pattern of a GUID is interpreted as an id string, and not a name. No
fieldValues [ customFieldValue ] An array of Custom Field values. No
specificCitation string A string value of Specific Citation. No
uom string A string value of UOM. No
valueHistory [ valueHistoryData ] An Array of Value History Data. Required for: Create Requirement type System Variable. No
documents [ docPath ] An Array of Document paths, specifying zero or more Documents which are or should be attached to the object. No

customFieldValue 

A set of one or more values for a Custom Field, identified by name.

Name Type Description Required
name string The name (NOT caption) of the Custom Field. No
values [ string ] An Array with one or more string values, representing the values (one or more) for the Custom Field. Note that even non-string simple values are encoded as strings for custom fields, and are parsed and validated on the server according to the Custom Field type. No
Copy Code
JSON
// Scalar value
{"name": "Aspect", "values": ["Air pollution control"]}

// Scalar date/time value
{"name": "Start Date", "values": ["2012-09-19T20:00"]}

// Linked-list values
