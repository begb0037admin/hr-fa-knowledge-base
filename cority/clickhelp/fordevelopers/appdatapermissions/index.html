App Data Permissions

As part of configuring an EMS App, you may specify Role-based read and/or write permissions for App Data key-value pairs within the EMS App.

Valid permissions are "AllowRead", "AllowWrite", "DenyRead", and "DenyWrite".

Permissions are mapped to any valid key by a "match string", and all keys that match the string are granted the specified permissions. Match strings are matched to keys with a trailing wildcard (i.e. "string*"). If two or more permissions match the same key, "longer" (more specific) match strings take precedence over "shorter" match strings. Only one permission set can be applied to a given key.

For each match string, you may specify a list of one or more allowed App Roles for read access, one or more allowed App Roles for write access, one or more denied App Roles for read access, and one or more denied App Roles for write access.

Unless specified otherwise, all key-value pairs with an EMS App default to being allowed read (but not write) access for the "Everyone" Role.

When enforcing permissions for a User and key, Allow and Deny read/write settings are calculated as follows:

  1. The set of all Roles in which the User is a member (either directly or through a Group membership) is collected.
  2. All permission sets which match part or all of the key are collected.
  3. The permission sets are filtered for those Roles in which the User is a member.
  4. The single permission set with the most specific (longer) match string that matches all or part of the key is used.
  5. If any Role is denied for the Item, the User has no access.
  6. Otherwise, if the User is allowed for the Item at least once through any Role, the User is allowed access.
  7. Otherwise, the User has no access.

The same calculation steps are used for read and write access separately, such that a User can be allowed read and/or write access, denied read and/or write access, or have none (no access).

You can allow or deny access to the "Everyone" Role to allow/deny all Users (other than Administrators).

Note:  EMS Administrators always have access to all data within all EMS Apps.

For example, the following is a list of permissions and resulting access for successively more specific match strings:

AuditConfig

Auditor: Allow Read, Allow Write

Result: Members of the Auditor Role are granted read and write access to any keys that start with "AuditConfig". All other Roles have no access.

AuditConfig_ReviewStep

Manager: Allow Read, Allow Write

Auditor: Allow Read

Result: Members of the Manager Role are granted read and write access to any keys that start with "AuditConfig_ReviewStep". Members of the Auditor Role only have read access (unless they are also members of the Manager Role), as the Role is not granted write access in this permission set.

AuditConfig_ReviewStepHistory Admin: Allow Read

Auditor: Deny Write

Manager: Deny Write

Result: Members of the Admin Role have read access to any keys that start with "AuditConfig_ReviewStepHistory".

All other roles have no access.

Additionally, members of the Auditor, Inspector, and Manager Roles are denied write access (regardless of their membership in other Roles) to these keys.
