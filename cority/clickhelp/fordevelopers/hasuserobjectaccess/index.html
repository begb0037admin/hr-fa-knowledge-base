HasUserObjectAccess

Note: The 'HasUserObjectAccess' function is only available for the Management System EQL.

Returns True if given user has access to respective Compliance object (including Group membership, defaults, and taking into account override inheritance).

Syntax:

HasUserObjectAccess (ObjectID, AccessLevel[, UserID])

ObjectID : Compliance Object ID. Identifier of object to be checked. Required.

AccessLevel : Access Level, text. One of the following values is accepted:

  • NoAccess : No access level present
  • ViewData : View Data or Full Control access level present
  • ViewProperties : View Properties or Full Control access level present
  • Report : Report or Full Control access level present
  • EnterData : Enter Data or Full Control access level present
  • ViewEnterEditData : View, Enter, and Edit Data or Full Control access level present
  • CreateCompleteTasks : Create and Complete Tasks or Full Control access level present
  • ViewTasks : View Tasks or Full Control access level present
  • Modify : Modify or Full Control access level present
  • FullControl : Full Control access level present

UserID : User ID to be used on access level check. Optional. If not provided, assume current user's ID.

Examples

select

r.id,

r.name,

HasUserObjectAccess(r.id, 'EnterData', getCurrentUser())

from requirement r

or (shortened version with same result):

select

r.id,

r.name,

HasUserObjectAccess(r.id, 'EnterData')

from requirement r

or (if userId is known ):

select

r.id,

r.name,

HasUserObjectAccess(r.id, 'EnterData', 'AE6E9DA2-2BA6-4AE8-AC50-89C7524237A7')

from requirement r
