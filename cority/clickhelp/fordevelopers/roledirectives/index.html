Role Directives

Role Directives may be used in the package manifest to create or remove Roles.

When adding Roles to an EMS App using Role Directives, a description should be provided so that System Administrators can determine the purpose of the Role within the EMS App, and which Users and/or Groups should be mapped to the Role.

During update of an existing EMS App, if an "add" Role Directive is specified with a name that matches an existing Role, the description of the existing Role will be updated with the description in the manifest, but no new Role will be added. Similarly, if a "remove" Role Directive is specified with a name that does not match an existing Role, the remove directive is ignored.

The following is an example of three Role Directives within a manifest.

<roles>

<add name="Manager" description="Managers for the plant."/>

<add name="Operator" description="Operators for the plant."/>

<remove name="Worker" />

</roles>

The above Directives result in the following operations being sequentially executed during upload of this manifest:

  1. The "Manager" Role is added, if the EMS App is new or the EMS App exists but the "Managers" Role does not exist for the App.
  2. The "Operator" Role is added, if the EMS App is new or the EMS App exists but the "Operator" Role does not exist for the App.
  3. The "Worker" Role is removed if it exists. All Permission Settings and User/Group mappings for the Role are removed as well.
