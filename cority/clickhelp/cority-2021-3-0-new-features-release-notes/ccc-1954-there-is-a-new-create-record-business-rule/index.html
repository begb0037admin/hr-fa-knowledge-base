CCC-1954: There is a new ‘Create Record’ business rule action (BRA)

  • Example use cases for the new ‘Create Record’ BRA are:
    • When a new Clinic Visit record is created, create a new Safety Incident record
    • When a new User record is created, create and link a new Employee record
  • While creating business rule (BR) with this action, when you click ‘Create Record’, on the resulting screen you must provide values for the following fields in order:
    • Code (for example, BRA Code) - a picklist
    • Main Record Entity (must match the BR entity) - a picklist
    • Create Record Entity (for example, Clinic Visit) - a picklist
      • The Query Component is then displayed.
      • You can now select multiple fields from your ‘Create Record Entity’ (at the left).
      • For each of these fields, you must either use:
        • The Plus Icon - to select a field from your ‘Main Record Entity’. This must include the ‘Today’ merge field in order to use the current date and time.
        • The Magnifying Glass Icon - to select a code from the selected table (for example, Clinic Visit Status Code).
        • Free text - To enter a hard-coded value to be mapped.
    • Run As Admin - a check box for specifying whether the security verification will run against the Administrator or the user who triggered the business rule
      • Note: Either way, the change will be logged in record history as made by the user who triggered the business rule.
  • If a user triggers a business rule that has a 'Create Record' business rule action (for example, with Main Record Entity = Clinic Visit and Create Record Entity = Questionnaire), Cority will:
    • Verify that the '<module>.save' security action for the Create Record Entity is granted to the user's role, or a security violation will occur
    • Create the new record as a main (in our example, Questionnaire) record, if the user triggering the business rule has permission to the Create Record Entity only
    • Create the new record as a record (in our example, Questionnaire) on a sublist of the main record (in our example, Clinic Visit), if the user triggering the business rule has permission to both the Main Record Entity and the Create Record Entity.
    • Note: Values for the 'Create Record Entity' record are copied over from the 'Main Record Entity' record automatically, if applicable.

Impact to Existing Users:

  • The ability to automate the creation of a new record of one entity type when an insert/update happens in another record will improve the efficiency of workflows and reduce work.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
