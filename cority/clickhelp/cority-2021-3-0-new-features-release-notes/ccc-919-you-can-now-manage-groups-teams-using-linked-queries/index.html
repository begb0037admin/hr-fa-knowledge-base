CCC-919: You can now manage groups/teams using linked queries

  • For this functionality, it is important to note the following:
    • We strongly recommend you manage each Group/Team using just one of the manual or the linked queries methods. A Group/Team should be generated either 100% manually or 100% by linked query (or queries).
    • Any linked queries must have 'Employee Number' for the first column.
    • Records assigned to a Group/Team are not updated retroactively when the employees for the Group/Team change. Only future assignments will reflect the change.
    • It is best practice to include a criterion in any linked query that excludes terminated employees, so that those employees are ended in the Group/Team.
  • A new 'Linked Queries' tab (sublist) has been added by default to the 'Group And Team' look-up table layout (ML-000619).
  • The sublist has a standard view with two columns:
    • Report Name - a picklist field
    • Created By - a calculated field, with calculation based on the Created By field in Query Builder / Report Writer
  • The sublist has the New, Save, Edit, Cancel, and Delete buttons, along with the Open Query action.
  • It also has inline-add and multi-add capability.
  • The user can link two or more queries at once.
  • In order to execute the 'Open Query' action, the user must select a query from the sublist.

  • The action takes the user to that query.
  • When the user clicks New on the sublist, a new Query layout opens that has three fields:
    • Group or Team - displays a description for the related Group or Team
    • Report (required) - a picklist of Query Builder / Report Writer queries
      • The picklist displays the Report Name and Created By columns, and is sorted alphabetically by Report Name.
    • Report Created By - a read-only field populated with the Created By value from the Query Builder / Report Writer query when it is selected
  • The Report picklist only displays queries that meet the following criteria:
    • Query Builder or Report Writer queries, and
    • Queries created by the current user or published or marked as a subquery, and
    • Queries for which Employee Number is the first column
  • The 'Group and Team' table is now a dependent object for linked subqueries in Query Builder / Report Writer, and will therefore be specified when applicable within the linked Dependent Objects count on any Group/Team that has one or more linked subqueries.
  • The following new fields can now be added to custom versions of the 'Group And Team Employee' look-up table layout:
    • Started By Type - an enumerated field (User or Subquery)
    • Started By User - a picklist to the Users look-up table
    • Ended By User - a picklist to the Users table
  • The standard 'All' list view for Employees in the 'Group and Team' look-up table has been updated to provide the following columns in order:
    • Employee
    • Start Date
    • Started By (read-only)
    • End Date
    • Ended By (read-only)
  • The standard 'Active' list view for Employees in the 'Group and Team' look-up table has been updated to provide the following columns in order:
    • Employee
    • Start Date
    • Started By (read-only)
  • The standard view 'Inactive' for Employees in the 'Group and Team' look-up table has been updated to provide the following columns in order:
    • Employee
    • End Date
    • Ended By (read-only)
  • For any records that existed before the new 'Started By' and 'Ended By' columns/fields were added, the values for those fields will be blank (empty).
  • When the user updates and saves a 'Group And Team Employee' record on which he or she has changed the 'Start Date' value (not blank), the logged in user will be set as Started By value.
  • When the user updates and saves a 'Group And Team Employee' record on which he or she has changed the 'End Date' value (not blank), the logged in user will be set as Ended By value.
    • If the user clears the End Date value, the Ended By value will be cleared as well.
  • The way this functionality works, basically, is that if an employee appears in any query linked to the Group/Team, even if the employee had previously been in the Group/Team and end-dated, the employee will then be added to the Group/Team.
    • The employee will be added to the Group/Team's Employees sublist (with his or her GDDLOFB), and the Start Date for the employee will be updated automatically.
    • If the employee is already in the Group/Team, no changes are made.
    • If the employee had previously been in the Group/Team and end-dated, his or her original record will be updated (End Date value changed to blank, Start Date value added, etc.) . A new record will not be created.
    • An Employee becomes end-dated in the Group/Team when the employees no longer appears in any query linked to the Group/Team. The employee is then removed from the Employees sublist on the Group/Team and his or her End Date is updated accordingly.
    • Note: Only employees added by linked query will be removed by linked query. Employees added manually that get removed from Group/Team's linked queries will not get removed from the Group/Team or end-dated.
  • The 'Goup and Team' linked queries update is run by a time-driven business rule (TDBR) nightly, before the TDBR for assigning inspections (if applicable).
  • Note: Any changes to the employee constituents in a Group/Team are not retroactive. For example, if an inspection is assigned to an employee, and the employee becomes ended in the group, the inspection will remain assigned to the employee.

Impact to Existing Users:

  • An administrator can now link queries to Groups/Teams, so that employees will be started/ended in a Group/Team automatically. This will reduce the amount of manual work involved in maintaining Groups/Teams.
  • Also, this will make it easier for an administrator to monitor how employees are added to a Group/Team, which will help him or her better understand why an employee was enrolled.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
  • For more information on working with Group/Teams,  see the Cority User Guide.
