CCC-227: There is a new Display Rules module for creating rules that dictate what should happen to a layout or set of layouts as a record moves through a workflow

  • The new module is included with the Administrator set of tools.
  • A display rule is similar to a business rule, except that display rules trigger immediately on values changing as opposed to triggering on Save.
  • The new module is accessible to any user with a role that is granted the DisplayRule security module, which is granted by default to the Administrator role.
  • The new module has a default list view named All Display Rules.
    • The list view has the Create/Clone View functionality.
  • When the user clicks New on the list view, the new default Display Rule layout opens.
    • The layout has the following fields, which exist already in the Business Rules module and function in the same way: Code, Description, Entity, Priority, and Inactive
    • It also has the new Layout field, which enables the user to select one or more layouts (Cority or user-created) corresponding to the specified entity.
    • The display rule will trigger when conditions are true on any of the specified layouts. If no layout is specified, the display rule will trigger on all layouts.
  • At present, only first-level fields and only the Equals operator are supported in the Display Rules module.
  • Subqueries are not supported in the module.
  • A display rule also has an action list with the following options:
    • Filter - for filtering a second field's picklist when specific value is entered for a corresponding first field.
      • On the specified layouts, the picklist will be filtered if the Equals operator condition is met and not filtered if the condition is not met.
      • For example: If 'Clinic Visit' Status = Open (Display Rule criteria), only the following values will be available for the 'Clinic Visit' Reason: Occ, Non-Occ, Checkup, and Immunization.
      • The maximum number of values for filtering to is ten.
      • Corresponding smart searches will also be filtered according to the rule.

    • Read Only Field - for making a field read-only (locking it from editing) when a specific value is entered for the field
      • When using this action, the field will become read-only if the Equal operator condition is met, and remain editable if the condition is not met.
  • Only one of each Display Rule Action Type can be used per display rule.
      • For example, you can't add two Filter actions to one display rule and you can't add two Read Only actions to one display rule.
  • A field can only be added once to a display rule.

    • Impact to Existing Users:

    • These rules will make is easier for an administrator to automate users' workflows.

    Additional Configuration Considerations:

    • Beyond what is described above, no additional configuration is required.
