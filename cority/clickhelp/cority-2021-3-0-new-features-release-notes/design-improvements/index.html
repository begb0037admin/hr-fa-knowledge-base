CCC-4693Business Rules - QuestionnaireN/A

The business rule 'Create Record' action now supports date calculations.

If a date field (for example, 'Date Completed') is specified within the BRA, the following will be provided next to it:

  • A field for specifying the date value
  • An operator drop-down menu for selecting either 'Plus' or 'Minus'
  • A number field for specifying how many units of time (0-999) should be added ('Plus') or subtracted ('Minus') from the date value specified
  • A time unit field for specifying one of Days, Weeks, Months, Quarters, or Years

Example use case: When a Date Completed value gets added to an 'Action' record, the BRA will create a new 'Action' record with a Due Date value equal to that Date Completed value plus 30 days.

CCC-4756Demographics – Job Positions2021.2.0

When either of the 'Enable Multiple Employee Job Positions' or 'Enable Filtering of Incident Investigators Based on the Job Position of the Employee Involved' system settings is selected, you can now successfully import a Job Position record that does not have a Start Date value, as long as there is no duplicate Job Position record (based on the combination of Employee #, Job Position, and Start Date values) already in the system. For such a Job Position record, the system will make the current date the Start Date value.

If the Job Position record being imported does have a Start Date value, the combination of Employee #, Job Position, and Start Date must be unique in order for the import to be successful.

Also, if the 'Enable Filtering of Incident Investigators Based on the Job Position of the Employee Involved' setting is selected, then for any updates to the Employee table, a duplicate Job Position record for the employee will no longer be inserted on the Job Positions tab (sublist).

Note: When the 'Enable Filtering of Incident Investigators Based on the Job Position of the Employee Involved' system setting is selected and a 'Date of Termination' is added (manually or through import) to an Employee record, all active job positions for that employee will become inactive with an End Date value equal to the employee's date of termination.

CCC-4162 and 4154Management of ChangeN/A

Within a change request approval sequence, an administrator can now define additional Management of Change (MoC) approvers.

To support this, new approver user-defined fields (UDFs), numbered 3 through 22, can now be added to each change request approval sequence step.

Once a new approver has been added, when the step in the sequence is reached:

  • The change record will be updated with the new status (existing behavior)
  • The new approver will receive an email
  • The new approver will be able to approve or reject the change request

As before, if the approver approves the change request and saves it, the record will be updated with the new approval date, and the next approver will receive an email notification and be assigned the record.

This new functionality is applicable to the Environmental, Safety, Quality, and BI solutions.

UDF extra approver fields 3-22 can be defined in LU_GLB_Approver in the ‘MoC Approval Role’. They can be linked to an employee.

When the GDDLOFB conditions are met, the defined employee name is populated in the selected field.

CCC-4520Platform - AdministratorN/A

For an employee, a second job position with the same code can now be created as long as the start date for each is different. This is to support the situation in which the employee returns to the same job position again at a later date.

Now when a user is creating a new job position for an employee, the system will validate it using the Employee, Job Position Code, and Position Start Date values.

If the combination is unique, the job position will be created. If the combination is not unique, the system will not create the job position because it will be a duplicate.

For legacy records, the Position Start Date value will remain null, so if the user tries to create a new record, an error will be generated until a Position Start Date is added to both the older record and the new one.

CCC-3879 and 4376Platform - AdministratorN/A

The email (with any contained documents) sent out by a scheduled business rule email action can now be password protected.

Note: If you need to have the email sent now and still want it password protected, you can simply schedule the business rule email action to fire now.

 

To support this, there is a new 'Password Protected' check box on the default 'Business Rule Email Action' layout.

The second will have the system-generated password for opening the zipped email and zip file of documents.

CCC-3532Platform - AdministratorN/A

You can now use QuestionnaireResponseHeader as the main (trigger) entity for a Create Record business rule action (BRA). This will enable you to map question responses from a questionnaire to field values on the record being created. Note: When a Create Record BRA using QuestionnaireResponseHeader as the main entity has a questionnaire selected for one of the fields on the right side of the BRA configuration screen, only one questionnaire code (the responses from one questionnaire), not multiple, can be used on the right side for mapping to the new record's fields.

To support this functionality, if QuestionnaireResponseHeader is used as the trigger entity and another module is used as the create record entity, when selecting a create record field, there is now a new Questionnaires node. The user can expand that node and then select from its list of available (according to the security configuration of the user's role) questionnaires.

Once a questionnaire is selected, all questions from that questionnaire will be listed.

  • The user must then select a question.
  • The response from the first instance of that question on the selected questionnaire will be used.
  • The following types of responses will be accepted for mapping to a field on the new record:
    • A text/numeric question response will map to a text/numeric field.
    • A look-up/tree object (Table Or Query question response) will map to a look-up/tree field.
    • A date question response will map to a date field.
    • A check box question response will map to a check box field.
    • A text question response will map to a look-up table / data table / text field.
    • A subquery question response will map to a look-up table / data table / text field.

For information on how to work with business rules and business rule actions, or on working with role security, see the Cority User Guide.

If the letter subsequently becomes unsigned and is in a non-draft state, the 'Revert to Draft' action becomes available.

CCC-1929Platform – End-UserN/A

The Sign action is now provided for letters.

To support this, the following fields can now be added to custom versions of all Letter layouts:

  • Signed - a read-only check box
  • Signed Date - a read-only date and time field
  • Signed By ID - a read-only look-up field that specifies the user (from the Users data table) who signed the record

To use the new fields on a Letter layout, the user's role must be granted access to the applicable new security action from the list below:

  • medicalletter.sign
  • casemanagementletter.sign
  • safetyletter.sign
  • ergonomicletter.sign
  • enviromentalletter.sign
  • ihletter.sign
  • qualityletter.sign

When you sign a letter without the cursor / Topaz device system setting selected, the new fields populate automatically, and the record becomes locked and marked signed. Note: The 'Employee Signature' and 'Staff Signature' fields can only be signed using the cursor or a Topaz device.

The Sign action will be disabled (greyed out) on a new letter and remain disabled until the Draft check box is deselected and the logged in user matches the user selected in the 'Letter Sent From' field.
