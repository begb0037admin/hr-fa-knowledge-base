CCC-4374: Applicability assessments recorded in ENHESA can now be imported into the Cority system

  • The new ENHESA ID field can be added to custom versions of the ML-000249 and ML-001337 Tree Master look-up table layouts. It is a numeric field that will accommodate up to 100 characters.
    • When added, the field’s value will associate the node with the corresponding ENHESA jurisdiction.
    • The field can be populated/updated using the Import Utility, and is available for use in Query Builder / Report Writer and in business rules.
  • A new ‘Get Applicable Regulations’ action (call) can be added to custom versions of the Environmental Applicability Assessment (ML-000258) and Safety Applicability Assessment (ML-000257) layouts.
  • For the user to execute the action, the following assumptions are made:
    • The user has created the required facilities (GDDLOFBs) within GX2 using the organizational tree and the facilities in ENHESA.
    • The ENHESA system settings configured and valid.
    • The ENHESA ID field on ML-000249 and/or ML-001337 is populated, where applicable.
    • The ‘Refresh Requirements’ action for regulations has already been run to import all regulations from ENHESA for the user’s organization.
  • When the ‘Get Applicable Regulations’ action is used, a new business rule will check to see if the assessment’s applicable locations have an ENHESA facility ID.
    • If so, any new regulations will be imported, the necessary audits will be created, and the applicability assessment(s) created in ENHESA will also be imported.
    • If the GDDLOFB or Applicable Locations sublist on the Applicability Assessment (ML-000258 or ML-000257) is populated, then only the ENHESA facilities that match the GDDLOFB or Applicable Locations (based on the ENHESA ID value on the ‘Tree Master with Attributes’ layout where the ENHESA ID is not blank) will be used to pull data from the ENHESA API.
    • If the GDDLOFB or Applicable Locations sublist on the Applicability Assessment (ML-000258 or ML-000257) are both empty (blank), then all ENHESA facilities (based on the ENHESA ID value on all the GDDLOFB nodes where the ENHESA ID is not blank) will be used to pull data from the ENHESA API.
  • For each ENHESA facility, as long as the applicability answer is yes, the content type pulled into GX2 will reflect the value specified for the ‘Regulatory Content Type’ system setting: Environmental Regulations or Safety Legal & Other Requirements.

Impact to Existing Users:

  • Compliance Managers can now import the results of their applicability assessments, so that they can relate their facilities to the applicable locations.
  • In turn, this will make it easier for Compliance Managers to track regulations that are applicable to their facilities, and therefore maintain regulatory compliance.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
