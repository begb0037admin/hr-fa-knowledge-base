CCC-1568, 3904, and 4048: There is a new Management Referral workflow

  • This is a general example of the workflow:
    • A Manager submits a questionnaire to refer an employee to a clinic. The auto-post to Case feature is configured, so a Case is created for the referral. A clinician then opens the Case record and from that record starts a referral appointment using the Appointments module. When creating the appointment, the clinician links it to a clinic-visit-related activity, which creates a Clinic Visit record. The case continues (with added information, perhaps one or more additional clinic visits, and messages back and forth between the clinicians and the referring Manager). The case is eventually closed.
  • This functionality is supported by:
    • Enhancements to the Appointments module
    • The integration of the Appointments and Case Management modules
    • A new employee consent workflow in the Case Management module
    • A new Messages tab in the Case Management module
  • The new Case Number field can now be added to custom versions of the Schedule Entry layout. The field is a picklist. Note: You must first select an Employee on the layout, which will then filter the Case Number list by the employee selected.
    • If case type security is enforced, then not only will the case number picklist will be filtered by case type, but if applicable the Schedule Entry will be hidden by the case type security. Therefore, if a Schedule Entry is linked to a case to which the user does not have access, he or she will not be able to see that Schedule Entry either.
      • If case type security is going to be used, to view the Schedule Entry, the user’s role must be granted the schedule.applycasetypesecuritytoscheduleentry action and have the appropriate case type security.
    • If the user has case type security preventing access to certain cases, he or she will only be able to reassign and/or cancel appointments, when linked to cases, that are linked to cases he or she can see.
  • If you use the ‘Schedule Follow-Up’ action in the Clinic Visit module, that will open the Appointments calendar as before, but if the Clinic Visit record is linked to a case (the Case Number field is populated on the Clinic Visit), then when you start creating the follow-up appointment, the case number will now populate automatically on the schedule entry (appointment).
    • Note: If at some point after setting up the follow-up appointment as above the user changes the case number on the schedule entry, the appointment will no longer be linked to the clinic visit, but the original case number will remain on that Clinic Visit record. Also, if the user removes the case number from the schedule entry after setting up the follow-up appointment, again nothing will be change on the Clinic Visit record, including the case number value and the date of the follow-up.
    • This is because it is bad practice to make such changes to such a Schedule Entry afterward. We strongly recommend you not make changes of that nature. If a change of that type is required on a Schedule Entry, it is best instead to delete the Schedule Entry and create a new one.
    • If the employee value is removed from the Schedule Entry after the follow-up appointment is created, to make it essentially a non-employee related entry, the case number will then be removed also, but no change will be made to any (formerly) linked Clinic Visit record.
    • Again, we recommend against such changes because they will result in unintended disconnects between records and could result in incorrect or poor data, which would also lead to poor/incorrect reporting.
  • A new Schedule History tab and Schedule Referral action can now both be added to custom versions of Case layouts.
    • The Schedule History tab will only show Schedule Entries (appointments) for the Case record on which it resides, even for clones or custom versions created of the Schedule History tab list views. By default, the Schedule History tab has two list views: All Schedule History for This Case and Current and Upcoming Appointments for This Case.
    • To use the new Schedule Referral action, the user’s role requires access to both the Case and Appointments modules.
    • The new Schedule Referral action in the Case Management module functions similarly to the Schedule Follow-Up Appointment in the Clinic Visit module.
  • The following is a typical use case:
    • When the user selects the new action, the Appointments calendar will open.
    • The user will then click New to create the referral appointment, and create the Schedule Entry record with date and time, and health center. The employee’s name and the case number will both be automatically populated on the record. The user will select, for example, a clinic-visit-related activity (for example, an Exposure Consultation), and then save the schedule entry.
    • If the user then goes back to the Case, the new appointment (schedule entry) will now appear in the Schedule History list.
    • After the appointment occurs, the user will then open it and designate it completed by selecting the Link action to create the corresponding Clinic Visit record, which will open that new record.
    • On the new Clinic Visit record, the Case Number and Treatment Date will populate automatically, and the Visit Reason will populate with the ‘Exposure Consultation’ clinic visit type the user selected on the Schedule Entry record.
    • When the user clicks Save on the Clinic Visit record, a notification will alert the user that he or she is linking the clinic visit to a case (with its case number).
    • If the case continues (more information is added, etc.) and the employee requires another clinic visit, the New action on the Case’s Schedule History tab or the Schedule Referral action on the Case record should be used to create the revisit appointment. If either or those is used to create the revisit and again a clinic visit related activity is selected on the revisit appointment (schedule entry), then the same fields will be populated automatically on the new Clinic Visit record, and the Revisit check box will be selected. When the user clicks Save on the new Clinic Visit record, a notification will alert the user that the clinic visit being created is a revisit.
    • Then both Clinic Visit records will be listed on the Clinic Visit tab for the original Case record.
    • If the user instead creates the second (the revisit) appointment directly from the Appointments module, instead of from the original Case record (bypassing the use of the Case record), but populates the same employee and case number and selects a clinic visit related activity, the newly created Clinic Visit record will still be marked a Revisit, the revisit notification will still be displayed when that Clinic Visit record is saved, and the new record will appear on the Clinic Visits tab for the original Case. This is because the employee and case number combination informs the system that this is a new Clinic Visit for that case.
  • As mentioned previously, it is always best practice is to follow the management referral and associated workflows as described in this release note in order to avoid unintentionally breaking links between records, therefore potentially creating incorrect or poor data, and in turn poor reports.
  • Note: For appointments, if in the Schedule Entry record the connection through activity is to any module other than Clinic Visit, then the workflows remain as before. It is just a link to the Clinic Visit module, because of its new connection to the Case Management module through case number, that necessitates these changes in workflows.
  • Several new fields can be added to custom Case layouts to support the management referral workflow:
    • Case Referred By – a picklist with a corresponding new look-up table
    • Referral Reason – a picklist with a corresponding new look-up table
    • Manager Name – a text field simply for capturing the name of the manager who referred the employee
    • Referred Date – a date field
    • First Offered Date – a date field
    • First Response Date – a date field
    • First Attended Date – a date field
    • Total Appointments – a calculated field, which is the number of appointments created/booked for the particular Case
    • Total Attended – a calculated field, which is the number of appointments attended by the employee for the Case
    • Total Cancelled – a calculated field, which is the number of appointments cancelled for the Case
    • Also, used for calculating the values above, the new ‘Schedule Status Type’ field is now provided in the Schedule Status look-up table. It has the following three options: Attended, Cancelled, Offered
      • Offered is when Schedule Entry record has been created, but not yet attended or cancelled.
      • In the Schedule Status look-up table, each ‘Schedule Status Code’ is linked to a ‘Schedule Status Type’. For example, Arrived Late, Attended, and Arrived are all count as attended towards the Total Attended calculated field value. Cancelled and No Show, for examples, both count towards Total Cancelled.
    • Date Opened to First Offered Date – a calculated KPI field that shows the amount of time between the two events
    • First Attended Date to First Response Date – a calculated KPI field that shows the amount of time between the two events
    • Date Opened to Date Closed – a calculated KPI field that shows the amount of time between the two events
    • First Attended Date to Date Closed – a calculated KPI field that shows the amount of time between the two events
  • The fields above can be populated/updated using Import Utility and are available for use in Query Builder and Report Writer.
  • The values of the calculated fields above are for measuring clinic efficiency and the efficiency and pro-activeness of the clinicians when attending to and completing management referrals (for analysis and reporting).
  • A new HR Manager field can be added to custom Case layouts.
    • The field is a picklist to the Users look-up table, and it is filtered to just the User records that have the new HR Manager check box selected.
    • This feature is so that the referral Manager and any other applicable Manager can check their employees’ Case records for progress. The data/information on the cases can be read-only for these Managers through configuration. This supports the management referral process in that it saves the clinicians from having to email updates to the Manager(s).
  • There is also a new employee consent workflow that is part of the management referral workflow. For details, see CCC-2593 in this document.
  • There is a new Messages tab (a tool for conversation between the clinicians and the Supervisor/Manager) that can be added to both custom GX2 and myCority Case layouts. Note: This tab cannot be viewed by the employee in the case.
    • The tab has the same look in both GX2 and myCority.
    • The tab can be viewed by the applicable clinicians (GX2 Users) and the Manager/Supervisor (myCority user).
    • One or the other initiates a conversation by clicking New on the tab, writing a free text message, and the clicking Save. Perhaps the clinician finds something in the initial referral that is unclear, or the Manager wants an update or an estimated time the referral process will be completed.
    • The message will then appear in the list on the Messages tab list view: All Messages for This Case
    • The list view has the following columns: Created By, Message, Message Date, Status, and Read Receipt Date
    • The statuses are: New, Dismissed, Read
    • The status will remain New for a manager’s message until it has been opened by one of the clinicians. The status will remain new for a clinician’s message until it has been opened by the manager. Once opened by the appropriate individual, that status will change to Viewed.
    • The Dismissed status is used when the Manager clicks the ‘Dismiss’ X for the message without opening it. The Manager could then open it later, and its status would change to Viewed.
  • Note: A Case record will only be visible to a manager if it is case-managed, has its ‘Share With Supervisor’ field selected, and the Supervisor is the one specified on that record. For Cases the Supervisor can see, he or she will only be able to see the main Case tab and the Messages tab, and the information/data on the Case tab will be read-only for the Supervisor.
  • Acquiring the employee’s consent to submit the employee’s contribution to the Case information to the Supervisor (see CCC-2593) and closing the case completes the management referral process.

Impact to Existing Users:

  • This makes it easy for:
    • A Manager to refer an employee to a clinic.
    • The clinician(s) to address and carry out the referral and any clinic visits.
    • The Manager and clinician(s) to communicate throughout the process.
  • It also enables your organization to measure clinic efficiency and the efficiency and pro-activeness of the clinicians when attending to and completing management referrals (for analysis and reporting).

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
