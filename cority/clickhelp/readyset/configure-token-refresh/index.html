Configuring Access Token Refresh

Receiving endpoints often require an access token for security. Access tokens typically expire after a short period of time — anywhere from an hour to a week — so an API call that runs on a recurring interval can start failing once its token goes stale. 

The Authorization Properties tab lets you configure a token request as part of your API call. Before ReadySet runs your scheduled or on-save API call, it first requests a fresh access token from your endpoint and automatically inserts it into the call, so you don't need to manually generate and update the token each time it expires. 

Authorization Properties are only available when the Initiation is set to On Save or Schedule. They are not available for Run Now calls. 

Enabling Authorization Properties

When configuring an API call with an Initiation of On Save or Schedule, a Requires Access Token? check box is available. Check this box if the endpoint you're sending data to requires an access token. 

Turning on Requires Access Token? enables a new Authorization Properties tab, where you can configure the request ReadySet will use to fetch the token. 

Configuring the Authorization Properties Tab

On the Authorization Properties tab, configure the following: 

  • API Type  — Fixed to REST. This field cannot be changed. 
  • Content Type  — Choose x-www-form-urlencoded or raw json, depending on the format the token endpoint expects. 
  • HTTP Method  — Fixed to POST. This field cannot be changed. 
  • URL — The URL endpoint to request an access token.  
  • Body  — The data sent to the token endpoint to request the token, for example a client ID, client secret, or grant type. 
  • Response Body  — The shape of the response ReadySet should expect from the token endpoint. 

If x-www-form-urlencoded is selected as the Content Type, you can configure the Body as key-value pairs, the same way you would configure Headers elsewhere in the API call. The Body is limited to 10 key-value pairs. 

Please reach out to your organization's IT team or the administrator of the receiving system for the token request URL, required Body parameters, and response format. ReadySet does not have visibility into the credentials or configuration of the system you are connecting to. 

Capturing the Access Token

The Response Body can only be edited as JSON. To tell ReadySet where to find the token in the response, replace the token value in the JSON with an [[access_token]] placeholder. For example: 

{
  "token_type": "Bearer",
  "expires_in": 3599,
  "ext_expires_in": 3599,
  "access_token": [[access_token]]
}

When the sub-API call runs, ReadySet captures whatever value is returned in the access_token field and stores it securely for use in the main API call. 

Using the Access Token in Your API Call

Add the [[access_token]] placeholder anywhere the token is needed in the main API call, such as in a header. For example, add a Header named Authorization with a value of Bearer [[access_token]]. 

When the API call runs, ReadySet replaces the [[access_token]] placeholder with the token retrieved from the Authorization Properties tab. 

If Requires Access Token? is turned on and the [[access_token]] placeholder is missing from either the main API call or the Authorization Properties Response Body, you will not be able to save the API call. You will see the message: "This API Call requires an access token. Please review and verify that the [[access_token]] placeholder(s) are present in the necessary areas."
