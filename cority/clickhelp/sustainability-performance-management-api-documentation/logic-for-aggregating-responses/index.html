Logic for Aggregating Responses to Match SPM Dashboards and Reports

This topic summarises how fields are aggregated and calculated to match the totals displayed on the SPM dashboards and reports. Note:  residual mix values apply to electricity only. 

Location-Based Calculations 

For location-based reporting, totals are calculated as follows: 

Scope 1:  For all records where the scope field is 1, calculate the sum of the tCO2e field across those records. 

Scope 2:  For all records where the scope field is 2, calculate the sum of the tCO2e field across those records. 

In addition, some transport records may represent electric vehicle usage. In those cases, the electricity emissions are stored in the following fields: 

  • electricitytCO2 

  • electricitytCH4 

  • electricitytN2O 

Where the scope field equals 1 and these fields contain values, they represent electricity emissions from transport and should also be added to the Scope 2 total. Therefore, the values in these three fields should be summed across those records and included in the Scope 2 aggregation. 

Scope 3: For all records where the scope field is 3, calculate the sum of the tCO2e field across those records. 

Scope 3 Indirect: Calculate the sum of the supplyChaintCO2e and biofuelSCtCO2e fields across records. 

Scope 3 Transmission: Calculate the sum of the transtCO2, transtCH4, and transtN2O fields across records. 

Scope 3 Indirect Transmission: Calculate the sum of the transSCtCO2 field across records. 

Out of Scope: Calculate the sum of the outofScopetCO2e field across records. 


Market-Based Calculations 

For market-based reporting, the system determines one value per record based on a defined priority, then sums the selected values. 

Scope 1: For all records where scope is 1, the system identifies a single value for each record based on the following priority, then sums those values together: 

  1. Primary: This is the value in the marketbasedEmissionsCO2e field. 

  1. Fallback 1: If marketbasedEmissionsCO2e is null or empty, the residualMixtCO2e field is used. 

  1. Fallback 2: If both of the above are null or empty, the tCO2e field is used. 

The total is the sum of these selected values across all applicable records. Note: A value of 0 is not the same as null. For example, if the value of Fallback 1 is 0, the emissions are 0 and Fallback 2 is not required. 

Scope 2: For all records where scope is 2, the system identifies a single value for each record based on the following priority, then sums those values together: 

  1. Primary: This is the value in the marketbasedEmissionsCO2e field. 

  1. Fallback 1: If marketbasedEmissionsCO2e is null or empty, the residualMixtCO2e field is used. 

  1. Fallback 2: If both of the above are null or empty, the location-based emissions, as detailed in the location-based section, are used. 

The total is the sum of these selected values across all applicable records. 

Scope 3: For all records where scope is 3, the system identifies a single value for each record based on the following priority, then sums those values together: 

  1. Primary: This is the value in the marketbasedEmissionsCO2e field. 

  1. Fallback 1: If marketbasedEmissionsCO2e is null or empty, the residualMixtCO2e field is used. 

  1. Fallback 2: If both of the above are null or empty, the tCO2e field is used. 

The total is the sum of these selected values across all applicable records. 

Scope 3 Indirect: For each individual record, the system determines the Scope 3 Indirect value before calculating a final total. The logic is applied as follows: 

  • Conditional Check: If either the marketbasedEmissionsCO2e or residualMixtCO2e fields contain data (are not empty), the Scope 3 Indirect value for that record is 0. 

  • Fallback to Supply Chain: If both the marketbasedEmissionsCO2e and residualMixtCO2e fields are null or empty, the  sum of the supplyChaintCO2e and biofuelSCtCO2e fields are used. 

The final Scope 3 Indirect Total is the sum of these determined values across all records. 

Scope 3 Transmission: For each individual record, the system determines the Scope 3 Transmission value before calculating a final total. The logic is applied as follows: 

  • Conditional Check: If either the marketbasedEmissionsCO2e or residualMixtCO2e fields contain data (are not empty), the Scope 3 Transmission value for that record is 0. 

  • Fallback to transmission fields: If both the marketbasedEmissionsCO2e and residualMixtCO2e fields are null or empty, the sum of the transtCO2, transtCH4, and transtN2O fields is used. 

Scope 3 Indirect Transmission: For each individual record, the system determines the Scope 3 Indirect Transmission value before calculating a final total. The logic is applied as follows: 

  • Conditional Check: If either the marketbasedEmissionsCO2e or residualMixtCO2e fields contain data (are not empty), the Scope 3 Indirect Transmission value for that record is 0. 

  • Fallback to transmission fields: If both the marketbasedEmissionsCO2e and residualMixtCO2e fields are null or empty, the value from the transSCtCO2 field is used. 

Out of Scope: Calculate the sum of the outofScopetCO2e field across records. This remains the same for both location and market-based.
