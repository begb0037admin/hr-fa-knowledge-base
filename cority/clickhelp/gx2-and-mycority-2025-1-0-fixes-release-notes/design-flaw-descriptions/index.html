Design Flaw Descriptions

The table below lists the design flaws we have addressed in 2025.1.0. The fixes are organized by module and the modules are arranged in alphabetical order.

Item #Component(s)Description
CCC-13799Environmental - Chemical Management, Workflows

For reporting, the Workflow History is now available in both Query Builder and Report Writer. This enables reviews of the workflow approval process to see where the workflow sits in the process (for parallel approvals, for example), determine who has completed/rejected, etc.

 

CCC-18828
Industrial Hygiene

IH 'Exposure Range' icons now function properly (appear when applicable).


CCC-8717Occupational Health - Appointments

The following phrases in the Appointments module are now available for translation (in Phrase Translations):

  • Attend
  • This time slot is no longer available. Please try again. (MG-001160)

 

CCC-6203Platform Administrator - Case Management, Clinic Visit

Where applicable, all pinned views (in OH Case and OH Clinic Visit, for examples) will now remain pinned.

 

CCC-15719Platform End User - Workflows

The 'Map comment to' field is now provided on the default 'Parallel Approval Workflow Action' (ML-003545) layout and functions as expected.

 

CCC-12092Platform End-User - Findings & Actions

If a user has two roles with different site security (for example, one contains all of Boston only and the other contains all of Chicago only), all Findings & Actions records that should be visible and accessible in the following now will be:

  • list views
  • sublist views
  • queries and reports

 

CCC-13099Platform End-User - myCority, Workflows

When applicable, for date/time fields in myCority, the dates and times in the associated 'Workflow History' will now honor the configured time zone.

 

CCC-19100Platform Interfaces - Clinical Testing

For the out-of-the-box QuestCare360 'Clinical Test HL7' integration, instead of the MSH-07 segment of the HL7 header, the MSH-06 section is now mapped to ClinicalTestSample.LabAccountNo.

 

CCC-7772Platform Interfaces - Logging

The following log tables can now be queried using (are now endpoints of) the REST API:

  • Event Log
    • GET coritysite/api/log
    • The user needs the log.apiread security action.
  • Email Tracking Log
    • GET coritysite/api/emailtrackinglog
    • The user needs the emailtrackinglog.apiread security action.
  • Login Log
    • GET coritysite/api/loginlog
    • The user needs the loginlog.apiread security action.
  • Import Log
    • GET coritysite/api/importlog
    • The user needs the importlog.apiread security action.
  • Process Status Log
    • GET coritysite/api/processstatuslog
    • The user needs the processstatuslog.apiread security action.

 

Also, the log.apiwrite and log.apidelete security actions have been removed.

 

CCC-19903Platform - myCority

Where applicable, the values in date and time fields in myCority will now reflect the format selected for, and the time zone of, the user.

 

CCC16365-
Questionnaires

If a questionnaire is submitted using myCority, even by a guest user (unauthenticated user), when the questionnaire gets posted, any documents attached to the questionnaire will now be associated with the employee listed in the Employee field of the questionnaire record.


CCC-10497Safety - myCority, Event Reporting

Now, in both GX2 and myCority, a user can no longer submit an Event Report prior to clicking Save. The Submit button will be greyed out and the equivalent shortcut inactive until an initial save. For Event Reports configured to 'Auto-post to Incident', this ensures that any hard-enforce business rule requirements/changes also flow to the resulting Incident record.

 

CCC-19731Safety - myCority, Permit To Work

When applicable, a custom standard Work Permit 'Workflow History' sublist view will now be visible and can be used in myCority by a user with the proper security configuration.

 

CCC-17117Safety - myCority, Permit to Work

When the user clones a permit in myCority or in GX2, the value of the Risk Category field from the 'Permit to Work' Risk sublist will now also clone in both myCority and GX2.
Note: To clone the permit, the user's role must be granted the workpermit.clonepermit security action.
