CCC-10974 and 3763: Questionnaires questions can now be configured to branch if a particular value is selected

Opt-In

  • Questionnaires now support branching.
  • Branching will guide the employee down a particular path within the questionnaire that is dependent on the employee’s responses.
  • Branching enables your organization to capture different answer-based workflows within a single questionnaire. This will eliminate the need for users to complete multiple questionnaires in order to obtain and share the same information. It will also provide a more tailored and seamless user experience, with each employee seeing only the set of questions applicable to him or her.
  • There are no limits as to how deep you can go with the branches.
  • Note: Clarity is now the only Cority theme supported. All others have been deprecated. Therefore, to use this new branching functionality, the 'Render Updated Questionnaire Response in Clarity' system setting must be selected. If the system setting is not selected, questionnaires configured with the new feature will not render properly. We recommend you select the setting and mark it Global.
  • The following question types support questionnaire branching:
    • Multiple Choice
    • Multiple Choice Checkbox
    • Multi Select Checkbox
    • Yes or No
    • Normal Abnormal
    • Numeric
  • All of these question types are supported by the ‘Valid Choices’ feature in the ‘Single Question’ look-up table. The new branching logic does not apply to any question type that does not have ‘Valid Choices’ capability (examples: Text, Text Area, Subquery, Date, Draw)
  • For nested questionnaires you can now branch:
    • From additional question types, not just Yes/No
    • For both yes and no responses for Yes/ No questions. Previously, this had to be one selection, one response.
  • There is now a new look-up selector field on the ‘Questionnaire Question’ layout called ‘Define Parent Branch Choices’, which must be added to a custom version of the layout to use questionnaire branching.
    • On a child question, open the ‘Define Parent Branch Choices’ picklist, which will be filtered to show only the valid choices of the related parent.  In this step you are defining the valid choice(s) of the parent question that will drive the display of that child question.
  • To prevent potential issues that could arise from mixing the old design with the new:
    • ‘Always Present Expanded’ will be disabled when the new ‘Define Parent Branch Choices’ field is used. To have a question expanded at all times is at odds with the new only when you provide a certain response should the next question appear logic.
    • ‘Auto branch on response Yes/No/Neither’ should be set to Neither when the new field is used. Again, the idea is you can define a path for yes and another one for No.
  • A corresponding 'Define Parent Branch Choices’ column can be added to the questions list view in the Questionnaire look-up table.  
  • The ‘Define Parent Branch Choices’ field has been added to the Import Utility with label QuestionValidChoice.Choice. This is for importing into that field in the 'Questionnaire Questions' look-up table.
  • In the Questionnaires look-up table, there is a new 'Enable Branching' check box.
    • By default, the new check box is not selected, therefore the new branching feature is off. Before selecting the check box for an existing questionnaire, we recommend you first review, and where applicable revise, any questions you want configured using the two new fields.
    • It is possible certain existing questionnaires can be tweaked slightly to use the new branching feature with no negative impact. For more complex questionnaires that include, for example, several nested questions, we recommend you instead create and configure (perhaps using cloning or the import tool) a new questionnaire to avoid any potential problems.
    • Once you are comfortable with the setup and have reviewed/completed the steps above, you can select the 'Enable Branching' check box and the new features will take effect.  
  • The following items do not support and are not affected by this new functionality:
    • Standalone questionnaires
    • Smart Notes
    • Flex Fields
  • For information on creating or configuring questionnaires and their questions, see the GX2 User Guide.
