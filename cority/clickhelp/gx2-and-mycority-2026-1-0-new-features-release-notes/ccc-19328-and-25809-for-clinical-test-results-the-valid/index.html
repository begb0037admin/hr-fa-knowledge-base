CCC-19328 and 25809: For Clinical Test Results, the ‘Valid Range’ functionality has been enhanced

N/A

Previously, when a logged in user had a System of Units that aligned with a different Unit of Measure (UOM), the ‘Valid Range’ was not being converted.
Note: It converted the actual results, which were stored in the ‘Converted Result’ and ‘Converted Unit of Measure’ fields prior to the new updates.

The following enhancements have been made:

  1. The logic of the existing ‘Current Range’ field in Clinical Test Results has been modified. ‘Current Range’ will  now reflect the appropriate values for the UOM that is associated with the result.
    1. Previously, ‘Current Range’ always reflected the ‘Valid Range’ in the Unit of Measure selected in the ‘Clinical Test Unit’ look-up table.
    2. Now a conversion gets applied to the ‘Current Range’ if the result UOM is different and if there is a conversion from the UOM in the look-up table record and the result UOM.
    3. If there is not a conversion, then the ‘Current Range’ will still reflect the ‘Valid Range’ for the UOM in the look-up table. See #1 above.
    4. For clarity, the UOM is now added to the ‘Valid Range’ field.
    5. Regardless,  the employee's gender and age will still be applied to select the appropriate ‘Current Range’.
  2. A new ‘Converted Current Range’ field can be added to custom versions of the ML-00309 layout. This will convert the ‘Valid Range’ (from #1 above) to a user's System of Unit (U.S. or U.K., for example) and the UOM for that System of Unit.
    Note: This applies, for example, when the ‘Clinical Test Units Module’ system setting is set to User (not Global) and the logged in user has a different System of Unit than the user who entered the results.
    1. For clarity, the new ‘Converted Current Range ‘ field shows the UOM.
    2. If the user viewing the record has a different System of Unit UOM than the UOM for the results and conversion information has been entered, then ‘Converted Current Range’ will be populated.
    3. If either of the conditions from #2 above is not true, then the field will be left empty.
