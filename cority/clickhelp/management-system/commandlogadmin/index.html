Command Log

The Command Log keeps track of data transactions sent to the system.

In order to ensure maximum performance and prevent browser lag time, the Management System uses "asynchronous transactions" to queue data transactions for commitment to the database.

Large data uploads may take time to process and commit to the database. Other types of data transactions may also affect system performance, such as recalculating data, changing calculation formulas, changing data limits, and adding new events. Most data transactions take only a few seconds to process, but the lag time for the browser to refresh the page with new results may be noticeable to the user.

When a new data transaction is entered by a user (such as adding or editing a data point, uploading data, or editing a calculation) a message informs the user that the data transaction has been successfully queued for entry. You can view the status of the command in the Command Log, and refresh periodically until you see that the command has succeeded.

If you have the Manage Commands right, you can view all commands sent to the system in Command Log. Users without the Manage Commands right see only their own transactions in the Command Log.

To view the transactions in the system:

  1. Select Command Log from the Messages page. 
    A list of commands sent to the system is displayed, with the most recent first. 

  2. Find specific transactions using the sort and filter options:

    • Select a column head to sort the transactions by that column.

    • Search for data transactions by status (Waiting, Processing, Succeeded, Failed, Resubmitted). If any errors occurred, the Error Message column will contain details.

    • Search for transactions by selecting a date/time range when they were entered in the system.

    • Filter commands for a specific object.

To view commands for an object, right click the object in the system model tree and choose View Commands.

The command log is filtered to display transactions for the selected object. When an object has failed transactions, the object is displayed in red on the System Model tree as a warning. If a transaction is in still in process, the object is displayed in blue.

Deleting Commands

Deleting commands from the command log removes the historical record from view in the command log. Depending on the command's status, the following occurs:

  • Deleting a processing log does not cancel the action, the command remains in the queue, and it will be executed.
  • Deleting a waiting log cancels the action and the command is not executed.
