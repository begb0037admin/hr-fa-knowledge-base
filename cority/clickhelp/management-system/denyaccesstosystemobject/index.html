Deny Access to a System Object

To deny access to a system model object to a specific group or user, you can do one of the following:

  • Edit the object permissions and change the permission level to No Access for the user or group.
  • Remove the user from the permissions list.

If a user is removed from the permissions list, but the user belongs to a group that has permissions, the user will still have access as a member of the group. To deny access altogether, you can either remove them from the group, or change the user’s permissions to No Access. No Access will override the user’s group access.

If permissions are inherited from a parent object, you must either change the permissions on the parent object, or uncheck "Inherit permissions from parent object" to enable setting object-specific permissions.

To deny permissions to a system object to specific users or groups:

  1. Right click the object (in the system model tree or the Applicable Requirements view) and select Permissions.

    The list of users and groups having permissions to the object are shown.

  2. If permissions have been inherited from a parent object, uncheck the Inherit permissions from parent object box. Then choose from the following two options:

    To deny access to an existing user or group: Edit the permissions for the user and select No Access for the permission.

    To remove an existing group/user from the permissions list: Select the user and click Delete. The permissions are removed from the Permissions column. (User’s permissions are not removed until you click Save.)

  3. Select Save after making your changes.

 A user who does not have permissions to an object generally will not see that object in the system model. The exception is when they have permission to a child object. The user will then be able to see the parent object as grayed out but will be able to expand the tree to view the child object(s) to which they have permissions.
