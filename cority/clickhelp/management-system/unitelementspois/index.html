Unit/Elements and POIs

A Unit/Element or a Point of Interest (POI) is a generic object type that may be used to represent subdivisions of a Facility/Program, such as physical plants, projects, or regulatory program areas.

The hierarchical rules that apply to these objects are:

  • A Unit/Element may be a child of a Facility/Program only.
  • A POI may be a child of either a Facility/Program or a Unit/Element.

To create a new Unit/Element or POI:

  1. Select the parent object in the System Model tree.

    For a Unit/Element, the parent object must be a Facility/Program. For a POI, the parent may be either a Facility/Program or a Unit/Element.

  2. Right click and choose New > Unit/Element or POI.

    On the first screen, you may select a Custom Field Template and a Calculation Template to apply, if desired. These are optional.

    Custom Field Templates are used to apply a group of user-defined fields to system model objects.

    Calculation Templates are used to hold numeric and calculated information specific to the object. These fields may then be used in calculations on direct child requirements.

    To apply a template, select it from the list. The fields on the template will be available for entry on the properties page next. You may also create a new template if you have the appropriate rights.

    If no templates apply, or you want to apply templates later, simply click Continue.

  3. Select Continue.

  4. Enter a Name.

    This is the name that will appear in the System Model tree. To add localized values for different languages, click the language symbol .

    Disallowed characters in names include "\", "/", "[", "]". For other discouraged characters, see Object Naming Rules.

    If the object name represents sensitive data that should be protected for security or privacy reasons (such as an employee name or other identifying information), you can indicate it by checking "May contain sensitive data". Custom fields that are applied to the object may be similarly marked as storing sensitive data. See Create/Edit Custom Fields.

     Fields marked as possibly containing sensitive data will be irreversibly scrubbed before leaving the customer environments, which means that Cority staff will not have access to these values in non-production environments such as staging and QA. See Sensitive Data Fields.

  5. Complete the rest of the fields as applicable.

  6. Select Save.

    The properties are displayed for review.

  7. Select Confirm to save the Facility/Program, or Back to edit it.

    The new Unit/Element or POI will appear in the system model under the selected parent object.

You can create identical Units or POIs in bulk by first filtering the Applicable Requirements view in the Content Pane for the parent objects under which you want to create the new objects.

To create multiple Unit/Element or POI objects in bulk:

  1. Use the Search in the Applicable Requirements view to filter for the objects under which you want to create the new objects.

  2. Select the checkboxes for the parent objects under which the new objects will be created.

  3. Right click and choose New > Unit/Element or New > POI.
  4. Select a Custom Field Template or Calculation Template, if desired, or just click Continue.

  5. Complete the properties form as applicable. The same property values will be applied to all the new objects.s

  6. Click Save and Confirm.

    The list of objects to be created and the property values are displayed for review. You may click Back to edit if necessary.

Fields for Unit/Element and POI Objects

The Unit/Element and POI tree objects have the same set of standard fields:

  • Name: Name of the Unit/Element or POI (as it will appear in the System Model tree). Disallowed characters include "\", "/", "[", "]".
  • Name may contain sensitive data: If the object name represents sensitive data that should be protected for security or privacy reasons (such as an employee name or other identifying information), you can indicate it by checking the box.
  • Active Date: The date that the Unit/Element or POI became active (optional).
  • Inactive Date: The date that the Unit/Element or POI became inactive (optional). See Non-numeric Requirement Field Definitions.
  • Responsible User: Optional user to be the default assignee for all tasks associated with the object. (Actual assignee may be changed on task creation or edit.)
  • Description: Optional description.
  • Geographical Coordinates: Latitude and Longitude and/or UTM Coordinates.
  • Meteorological Location History: Nearest city to use for meteorological data. This is used only for some Material Activity calculations. If not specified, meteorological location may be inherited from a parent object with a defined meteorological location. See Meteorological Data.
  • Relations: Documents from the Documents library to associate with the object. See Associating Documents.

 The Time Zone for a Unit/Element or POI is inherited from the parent Facility/Program.

Additional custom fields may be applied through a Custom Field Template and/or Calculation Template. See Custom Field Templates and Calculation Templates.
