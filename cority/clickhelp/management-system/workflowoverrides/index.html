Workflow Overrides

Workflow Overrides may be applied to any object in the system model tree (division, facility, unit or POI). Overrides for workflow types at the object level include:

  • Role Membership Overrides: Changes the default role memberships from those specified in the workflow type.
  • Policies Overrides: Changes the policies applied to the workflow type .

When a workflow override is created for an object, all workflow instances of that type that are associated with the object will use the role members and policies (if any) specified in the override. Workflow overrides are inherited down the system model tree, so only need to be applied once at the highest level object where you want it to take place.

If no override is specified, or no object with a workflow override is associated with the workflow instance, the role memberships and policies named in the workflow type are applied.

To create Workflow Overrides, users must have Full Control permission for the system model object (which implicitly grants Manage Workflows permission for that object).

To create Workflow Overrides:

  1. Right click the object (division, facility, etc.) in the system model tree and choose Change > Workflow Overrides.

  2. Select the appropriate tab:

    Select the Workflow Role Memberships Overrides tab to change role members. See Role Membership Overrides.

    Select the Workflow Policies Overrides tab to change notification policies. See Policies Overrides.

 Workflow defaults are not shown in the Workflow Overrides editor. To view the default associations, you will need to view the workflow type in Workflow Type Manager.
