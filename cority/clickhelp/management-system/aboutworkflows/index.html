About Workflows

Workflows are a way to ensure your organization’s compliance with internal policies and procedures, as well as regulatory requirements.

Workflows are comprised of one or more steps. Each step in a workflow has a step form with relevant fields. To complete the step, the workflow assignee completes or reviews the form and chooses an action. Typical actions include sending the workflow to the next step, initiating a child workflow, or ending the working.

Each Workflow step is associated with a Role. The assignees are determined by their role memberships, as individuals or groups associated with the role. When a workflow is associated with an object, such as a facility, the role members may vary depending on the object, through the use of role overrides.

The workflow process is defined by the Workflow Type. The Workflow Type describes the steps, forms, actions, roles and permissions necessary to the workflow.

Workflows may be associated with system model objects, but object association is not required. This means that as long as a workflow is not associated with an object, a user does not need any permissions to participate in a workflow. The only requirement is a login ID. If the workflow is associated with a system model object, the user needs permission to that object.

Many workflow instances of the same Workflow Type may be in process at the same time, each at a different stage of completion. For more information, see the following topics:
