Managing Workflow Types

A Workflow Type defines the rules and behavior to be used for all workflow instances of the same type.

A Workflow is comprised of a series of steps. Each step has an associated form template which is used for completing the step. One or more actions is available for routing the workflow to the appropriate next step.

Participation in workflows is managed by Roles associated with each step and the workflow as a whole. Users and groups in the system are associated with the various Roles. Permissions for workflow operations are granted to the Roles as needed.

There are several components to a workflow:

The Workflow Type defines the process for the workflow. It is managed in the Workflow Type Editor.

Form Templates define the forms that are to be used to complete the workflow steps.

Workflow Roles are used to assign responsibilities in a workflow type, with Role memberships assigned to users or groups.

Workflow Policies define the policies for notifications generated from workflows.

Notification Templates define the appearance and content of the notifications.

Workflow Overrides are used to assign default Role memberships and Notification Policies on a facility basis.

Workflow Aggregations can be created to obtain a count of workflow instances meeting specific criteria, or to perform calculated aggregations of numeric fields included in the workflow forms. For information, see Workflow Aggregations.
