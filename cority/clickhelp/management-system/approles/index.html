Roles for Apps

Apps use a role-based model for permissions. The Roles used in the app are not managed directly through the interface, but are defined in the package manifest. Once the App is uploaded to the system, you can map users or groups (groups are recommended) in the system to each Role. Users mapped to Roles inherit the permissions defined for the Role in the App.

App Roles are distinct to each App and are not shared across Apps.

To set up Role memberships:

  1. In Apps Manager, right click the package and select Edit.

  2. Select the Role Membership tab.

    The Roles defined for the App are listed. For each Role, select the users or groups to associate with the Role.

  3. Click the Role name to edit role memberships.
  4. In the dialog, select Add to add a user or group association.
  5. Click Save when you are done.

 Access for users to an App from the interface has two components: The Role memberships set in Apps Manager, and the display settings for the associated page, configured in Main Menu Manager. Therefore, a user may have permission to the App contents by virtue of being a member of a Role, but if display of the custom page is not enabled for that user in Main Menu Manager, the user will not see the page. (For Apps that are hosted externally, the page display does not apply.)
