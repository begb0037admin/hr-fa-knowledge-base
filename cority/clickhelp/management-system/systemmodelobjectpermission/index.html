System Model Object Permissions

Every system model object in a system tree has a set of access permissions that apply to specific users or groups. The permissions on an object control what users and groups are allowed to access the object and what functions are allowed to those users.

To set permissions on an object, a user must either be a member of the Administrators group, or be granted Full Control permission to the object by an Administrator.

The permissions that can be applied to system model objects and what they include are detailed in Functional Permissions.

To set permissions to a system model object, users must have Full Control for the object.

View or Assign Permissions to an Object

To view or assign permissions to an object, right click the object in the system tree and select Permissions.

The list of users and groups having permissions to the object are shown. If permissions are inherited from the parent object, the checkbox Inherit permissions from parent object is selected and the parent object from which permissions are inherited is shown. The users and permissions inherited from the parent object are displayed but all permission selection boxes are disabled.

If permissions are not inherited, the Inherit permissions from parent object is not checked and permissions may be edited. Uncheck the Inherit permissions from parent object box to enable editing permissions.

Add permissions for new users or groups

  1. To add users or groups, click Add User or Add Group.
  2. From the selection window, select the users or groups to add by checking the boxes, then click Select.
    The users/groups are added to the permissions list.
  3. Select the permissions to grant.
  4. With the Select box checked for the new users/groups, click Edit.
  5. From the pop-up box, select the permissions you want to grant, then click OK.
  6. To extend the same permissions to all child objects, check Apply to Children.
  7. Click Save.

 The new permissions will automatically be applied to all child objects that have inheritance for permissions selected. Selecting Apply to Children will add the new user or group’s permissions to those child objects that do not have inheritance for permissions.

Delete permissions for a user or group

  1. Check the Select box for the user or group.

  2. Click Delete.

    The permissions are removed and the Permissions column is now blank for the user. However, you must also save the changes.

  3. Check Apply to Children to delete user permissions to all child objects.

     The new permissions will automatically be applied to all child objects that have inheritance for permissions selected. Selecting Apply to Children will delete the new user or group’s permissions for those child objects that do not have inheritance for permissions.

    If the user belongs to a group that has permissions, the user will still have access as a member of the group. To deny access altogether, you can either remove them from the group, or change the user’s permissions to No Access. No Access will override the user’s group access.

  4. Click Save.
