Task Permissions

Task assignees must have the following permissions on the objects associated with a task in order to complete the task:

  • View, Enter and Edit Data OR Create and Complete Tasks (which also includes View Properties and Create Task)
  • View Tasks (optional, but recommended, as it allows users to view task properties)

Assignees will also need Read permission for any documents associated with the task in order to view the documents.

Typically, permissions are assigned through a parent object in the system model tree and inherited by all child objects, although they may be assigned to individual requirements.

 Best practice is to assign task permissions to a group, rather than to individual users. Use the same groups to assign permissions as you use to assign tasks.

To assign permissions to task assignees:

  1. Select the parent object in the tree, right click and choose Permissions.

    If permissions are inherited from another parent object, the "Inherit…" box will be checked and the parent object from which permissions are inherited is shown. Consider whether you want to add the user/group to that object's permissions, or if you want to set specific permissions for this object.

    To set specific permissions on this object, uncheck the "Inherit…" box. Otherwise, select the parent object from which permissions are inherited to make your changes.

  2. Select Add Group (or Add User). In the selection window, find and select the group (or user) and click Select.
  3. With the Select box checked for the new group/user, click Edit.

  4. In the popup window, select the following permissions:

    View, Enter and Edit Data OR Create and Complete Tasks

    View Tasks

  5. Click OK.
  6. Click Save.
