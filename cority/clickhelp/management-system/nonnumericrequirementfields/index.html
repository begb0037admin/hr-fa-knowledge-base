Non-numeric Requirement Field Definitions

Active and Inactive Dates

The Active and Inactive Dates are the begin and end dates that a requirement applies. The dates may be different from the effective and expiration dates for a requirement as defined in the Requirement Template.

For example, hazardous waste tank regulations became effective on 11/19/80. A facility uses a tank to store solvent product for many years, but decides to start using the tank for used solvents (hazardous waste) on 05/01/01. Hazardous waste tank requirements have an Active Date of 05/01/01 for that tank.

 Requirements that have expired (as determined by the Active/Inactive Dates) will appear with a red X through the icon in the system model tree. Also, only one date can be entered per field. This means that if a requirement was Active, became Inactive, and then became Active again, the second active period must be identified as a new requirement.

Requirement Source

The Requirement Source section allows you to further define the requirement driver information, as initially supplied from the template. Depending on the driver information from the template, you have the opportunity to supply the specific citation, specific requirement, condition number, or other information. If the information you need is not on the selection list, you can enter it in the text box provided.

Periodicity

Periodicity in a non-numeric requirement defines how often the requirement should be implemented or is applicable. For example, a requirement to inspect an area at the start of each shift at a 24-hour/7-day facility would have a requirement frequency of three per day (assuming three shifts per day).

Description for a Non-Numeric Requirement

This field is for specific information about an applicable requirement. The description should be aligned with the Compliance Statement. The information may include instructions on how to meet the requirement, where to find related documents, etc. The description should be written in such a way that a new employee can read it and understand exactly what needs to be done to be in compliance with the requirement. When a task is associated with a requirement, the requirement description is used by default for the task description.

Following are two examples of descriptions for non-numeric requirements, one derived from a federal regulation and the other from an air permit.

Example 1: Federal Regulation for Hazardous Waste Containment

40 CFR 262.34 (with 265.174) requires that a hazardous waste generator maintain its hazardous waste containers in a prescribed manner and conduct inspections of the container areas at least once weekly. The description of this non-numeric requirement could be written as follows. This description can also be used as is to describe a task for the weekly inspection of the hazardous waste containers:

The hazardous waste container areas are to be inspected weekly. Consider all of the following questions during the inspection. Any findings of "Yes" to the questions require immediate action. If the remediation work requires more than one hour, notify your supervisor for assistance.

  • Does any 90-day container lack the accumulation date?
  • Is any container missing a "Hazardous Waste" label or mark?
  • Are there any open containers (other than those in which waste is being added or removed at time of inspection)?
  • Is there more than 55 gallons of hazardous waste (or one quart of acutely hazardous waste) at or near a satellite accumulation area?
  • Are there any containers holding ignitable or reactive waste, located less than 50 feet from the property line?
  • Are there any containers not in good condition (e.g., excessive dents, deterioration, leaks)?
  • Are there any leaks or spills of hazardous waste or hazardous materials in the area?
  • Have incompatible wastes been placed in the same container?
  • Are containers holding hazardous waste not separated (e.g., by berm, dike, wall) from containers or other devices holding waste or other materials that are incompatible (e.g., acids and bases) with the hazardous waste?

Any findings of "Yes" to the above questions require immediate action. If the remediation work requires more than one hour, notify your supervisor for assistance.

Example 2: Requirement for Air Permit Condition

An air permit condition requires that the dust filter be maintained so that particulate removal efficiencies of 99.5% are maintained, including the following actions: 1) the filter vent be inspected for visible emissions on a daily operating basis; 2) the filter elements (bags) be inspected every six months and changed as necessary; and 3) records of visible emission checks and maintenance inspections of the dust filters be kept on site and available for inspection.

Since this permit condition contains three actions with different frequencies, three separate non-numeric requirements could be created. Also, a generic requirement could be created for the permit condition as a whole (with a reference to the three separate non-numeric requirements). The users have several options for managing and documenting their environmental compliance data. The description of this non-numeric requirement (or the three separate non-numeric requirements) could be as written below in italics. The descriptions could also be used to describe three tasks for maintaining compliance with the permit condition:

1) The operator on duty checks the filter vent for visible emissions at least three times per shift. The VE checks are noted on the Operations Checklist, which is given to the O&M Supervisor at the end of the day. If visible emissions are noted, the O&M Supervisor is notified immediately for a maintenance check.

2) The maintenance helper inspects the filter bags every six months and records the inspection on the Dust Filter Maintenance Inspection Form. If the bags are changed as a result of the inspection (or at any other time), the bag change is also noted on the Form. Then the Form is given to the O&M Supervisor.

3) The O&M Supervisor retains the completed Operations Checklist and Dust Filter Maintenance Inspection Forms and makes them available for air agency inspections.

For an example of a Compliance Statement for this requirement, see Compliance Statement for a Non-numeric Requirement next.

Compliance Statement for a Non-numeric Requirement

Use this field to describe the method that will be used to determine compliance with a requirement. This statement should be designed to meet reporting needs, as it may be used in reports like the Title V Annual Compliance Certification.

For example, the compliance statement for Example 2 would be:

1) VE inspections are conducted every day.

2) Maintenance inspections are conducted every six months and bags are changed as needed.

3) Inspection and maintenance records are retained.

Create Task

If the Create Task box is checked on the form to create a new non-numeric requirement, a new task form appears after you save the requirement so you can configure the task. By default the Requirement Description field is used for the task description (however, it may be edited if necessary). You can select task assignees and set up the recurrence schedule and notifications.
