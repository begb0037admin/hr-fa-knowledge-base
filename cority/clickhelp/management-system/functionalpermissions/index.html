Functional Permissions

Functional permissions are grouped together in several arbitrary access levels that may be assigned per user/group to each system object.

The following table shows the permissions that can be granted for system model objects with a summary of the allowable actions:

Access Level

Actions allowed

No Access

Cannot view or perform any action on this object or section. (See Note below.)

View Data

Can view data, but not enter or edit data. Also includes ability to view data in reports

View Properties

Can view object properties

Report

Can run reports for all objects. Selecting this permission automatically includes View Data, View Properties, and View Tasks.

Enter Data

Can add data (but not edit or view data)

View, Enter, and Edit Data

Can view data, enter data and edit data

View Tasks

Can view tasks (but not edit or complete tasks)

Create and Complete Tasks

Can create tasks, edit and complete tasks; enter and edit data.
Create and Edit Objects Can create objects, edit object properties, create or modify associated tasks, add or edit data. Cannot delete objects.

Modify

Can create objects, edit object properties, create or modify associated tasks, add or edit data, plus delete object.

Full Control

Can perform all of the actions, including adding and deleting objects and setting object permissions. Also grants Manage Workflows permission for object-related workflows.

 The No Access permission overrides any other permissions granted. For example, if a user belongs to a group with permissions on an object, the administrator may override the group permissions by specifying No Access on that object for one or more users.
