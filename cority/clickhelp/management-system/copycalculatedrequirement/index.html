Copying Calculated Requirements

Calculated requirements may be copied to another parent object using the Copy/Paste functions. They may also be moved using Cut/Paste. However, there are important rules to keep in mind when copying or moving calculated requirements.

When a calculated requirement is copied, the calculation formula is retained. The requirement copy should be verified to make sure it is valid in the new environment.

  • If the calculation references calculation fields from calculation template on its parent, check that the fields are also available on a calculation template on the new parent.
  • If copying to a different time zone, ensure that the Calculation Begin/End Dates and the dates for any referenced objects are correct for the new environment. See Copy/Move Objects Across Time Zones.

When copying a parent object with calculated child requirements, containment rules apply to any calculated requirements included in the copy:

  • If all requirements referenced in the calc are included in the copy, then relative reference integrity is maintained. That is, the calculation formula will reference the new requirements that are created in the copy operation along with it.
  • If requirements referenced in the calc are not part of the copy operation, then relative references to the original requirements are retained.

To copy a calculated requirement:

  1. Right click the requirement you want to copy and select Copy.

  2. Select the parent object under which you want to create the copy. Right click and select Paste.

    The Copy Object screen appears. The item to copy is shown, along with the target parent object.

  3. Rename the requirement, if appropriate. Then click Copy.

    An advisory warning is displayed on the copy page and in the properties of the Requirement copy.

  4. Right click the new requirement and choose Properties > Edit.

    Check that all Calculation Requirements are present, and add any missing requirements needed for the calculation. Correct the calculation if necessary.

    Check that the Calculation Begin Date is appropriate in the new environment.

  5. Click Save, then Confirm to save the requirement.

Depending on the actions taken when editing properties, the advisory warning and the Calculation History from the original requirement may disappear or may remain on the copied requirement, as follows:

No action (but save and confirm): The advisory warning disappears.

Change the Calculation Begin Date to an earlier date: The advisory warning and the original Calculation History disappear.

Change the Calculation Definition: The advisory warning and the original Calculation History disappear.

Change the Calculation Begin Date to a later date: The advisory warning and the original Calculation History are retained, unless the requirement’s Active Date is also changed to the same as the Calculation Begin Date.

It is advisable to set the calculation Begin Date time to 12:00 AM. The exception is when calculation is for hourly data and the calculation change occurs at a specific hour.
