App Configuration

Apps allow you to extend the functionality of the Management System by creating a custom-designed interface with its own logic and look-and-feel, which can then be configured to display in a custom page.

Some of the things you can do with Apps include:

  • Create Workflows with specially designed forms.
  • View or edit data that is usually disconnected in different subsystems of the application (such as task information and numeric data entry).
  • Incorporate data from your own internal data systems, in real time.
  • Create very rich and specific visualizations of data (charts and graphs) from the application.
  • View a merge of data between the application data and another separate application (for example, merge facility CO2 emission rates with production values from your operations systems).

An App is simply a collection of files (including html, scripts with API calls, stylesheets, etc.) that defines a custom interface. The files are uploaded to the system as a zipped package. Apps may be designed to the customer's specifications by the Cority development team, by Cority partners, or by your own development team.

For best practices to use when designing an App and detailed description of the Apps SDK, JavaScript APIs and REST APIs, see the Apps SDK documentation. (You can access this documentation from Apps Manager.)

Once an App has been created, it may be easily configured and managed from the platform, if Apps Manager is enabled for the system.

 To configure and manage Apps from the Management System, Apps Manager must be enabled for the system. When Apps Manager is disabled, it is not available in the application, regardless of user rights. However, disabling management does not disable the use of any Apps configured for the System.

For documentation on the Apps SDK, JavaScript SDK and REST APIs, see Apps SDK Help.
