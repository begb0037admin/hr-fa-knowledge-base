Daylight Saving Time Rules

For time zones that observe Daylight Saving Time (DST), the hour of 2am on the day upon which DST begins does not exist. Data with a completion date in that hour (2:00 - 2:59) is handled in the following manner:

  • User entered data (interactive or web service) that falls in that hour is shifted one hour forward.

  • If, in a single data entry batch, the shifted data point(s) conflict with other data points with the same explicit completion date, then the data point(s) with the explicitly set completion dates overrides the shifted data points.

    Two data points are entered at 2:15 and 3:15. The 2:15 data point is shifted to 3:15. Since only one data point may exist for a Requirement at any given date and time, the original (explicit) 3:15 data point is saved and the shifted data point is discarded.

  • Calculated data (produced by the calculation engine) that falls in that hour is discarded.

    For time zones with Daylight Saving Time (DST) enabled, the hour of 2am on the day upon which DST ends occurs twice. Data with a completion date in that hour (1:00 - 1:59) is handled in the following manner:

  • The data point that is entered last for that hour is the data point that is saved.
