Divisions

A Division is an organization container that may optionally be used, if desired, as the first-level object in the System Model tree. It has no important properties, but may be thought of as simply a "master folder."

To create a new division:

  1. Right click Locations & Programs in the System Model tree and select New > Division.

    On the first screen, you may select an optional Custom Field Template to apply.

    Custom Field Templates are used to apply a group of user-defined fields to system model objects.

    To apply a template, select it from the list. The fields on the template will be available for entry on the properties page next. You may also create a new template if you have the appropriate rights.

    If no templates apply, or you want to apply templates later, simply click Continue.

  2. Select Continue.

  3. Enter a Name.

    This is the name that will appear in the system model tree. To add localized values for different languages, click the language symbol .

    Disallowed characters in names include "\", "/", "[", "]". For other discouraged characters, see Object Naming Rules.

    If the object name represents sensitive data that should be protected for security or privacy reasons (such as an employee name or other identifying information), you can indicate it by checking "Name may contain sensitive data".

     Fields marked as possibly containing sensitive data will be irreversibly scrubbed before leaving the customer environments, which means that Cority staff will not have access to these values in non-production environments such as staging and QA. See Sensitive Data Fields.

    The remaining fields are optional. For field information, see below.

  4. Select Save.

    The properties are displayed for review.

  5. Select Confirm to save the Division, or Back to edit it.

    The new Division will appear in the System Model. Divisions will always display first in the tree.

Fields for Division Tree Object

Name: Name of the Division (as it will appear in the System Model tree). Disallowed characters include "\", "/", "[", "]".

Name may contain sensitive data: If the object name represents sensitive data that should be protected for security or privacy reasons (such as an employee name or other identifying information), you can indicate it by checking the box.

Active Date: The date that the Division became active (optional).

Inactive Date: The date that the Division became inactive (optional). See Non-numeric Requirement Field Definitions.

Responsible User: Optional user to be the default assignee for all tasks associated with the object. (Actual assignee may be changed on task creation or edit.)

Relations: Documents from the Documents library to associate with the object. See Associating Documents.

 Additional custom fields may be applied through a Custom Field Template. See Custom Field Templates.
