Report Permissions

Two types of permissions control access to reports in the Reports library:

  • Report permissions: These permissions, granted on the report folder or individual report, include View, Edit and Unrestricted. View and Edit determine what the user may do to the report. Unrestricted is actually a shortcut to granting object permissions (see below).
  • System object permissions: These permissions are granted on the system model tree. The Report permission allows users to see data included in a report; it is an aggregate of 3 permissions: View Data, View Properties and View Tasks (the types of data that may be include in a report).

As an alternative to granting system object permissions, users may be granted Unrestricted report permission. This means that users may view data for any objects in the system in the report, regardless of their object permissions.

In addition to Administrators, users with the Manage Reports right may set permissions on reports or report folders. (See User Rights.)

Within the Reports library, permissions can be assigned in the most efficient manner by applying them to folders. However, you can also assign permissions to individual reports if necessary. Report permissions include View, Edit and Unrestricted.

The possible permission combinations for reports are:

  • View: May run reports. Users will also need Report permission on objects included in the reports.
  • View+Edit: May run and edit reports. Users will also need Report permission on objects included in the reports.
  • View+Unrestricted: May run reports and view cached reports. Users do not need any object permissions and will be able to view data for any objects included in the reports. When running reports users can use the object selector (if available) to select any objects in the system model tree.
  • View+Edit+Unrestricted: May run and edit reports and view cached reports. Users do not need any object permissions. When running reports, users can use the object selector (if available) to select any objects in the system model tree. When editing the report, users may add any system model objects.

Users with Edit permissions on a report folder can (in addition to the above) create new reports, manage versions, create report subfolders, copy and move reports, and delete reports and folders.

 Unrestricted permission on a report or Manage Reports right is required to access a cached report via a Quick Link. Unrestricted permission is also required to use the object selector when running a report. Users with Manage Reports right have unrestricted permission to all objects, meaning they can create and run reports for all objects, regardless of permissions.

The following types of reports require additional permissions or user rights:

  • Citation Report: Requires View permission for citations included in the report.
  • Material Report: Requires user rights Manage Materials and Activities, Manage Reports
  • Chemical Report: Requires user rights Manage Materials and Activities, Manage Reports
  • Security Report by Permissions: Requires Full Control permission for objects included in the report
  • Security Report by Rights: Requires user rights Manager Users and/or Manage Groups plus Manage Reports

For more information on report-specific permissions, see Managing Access to Reports.

You can add, delete or modify permissions on any report folder. When you add a new user/group, you may choose whether to apply folder permissions to all reports and subfolders or not.

View and Modify permissions on reports are best granted through folders. However, you can also assign permissions to individual reports. By default, new or copied reports inherit the permissions set on the parent folder.

 Permissions can be applied or reapplied at the folder level. However the permission settings are saved with each report. Therefore, when new users/groups are added to the permissions on a folder, you must use Apply to Children to grant access to the existing reports.

The Manage Reports user right is required to view document permissions.

View permissions on a report folder or report

You can open the Permissions Editor by one of the following means:

  • In the Reports library, select Current Folder Permissions (to view permissions for the currently selected folder.

  • Right click a folder or report and choose Permissions.

The Permissions Editor shows groups and users with permissions on the folder or report and the permissions granted to each.

Add users or groups

  1. Click Add User or Add Group.

  2. From the selection window, select the users or groups to add by checking the boxes and click Select.

    The users/groups are added to the permissions list. Next, select the permissions to grant.

  3. With the Select box checked for the new users/groups, click Edit.

  4. From the popup box, select the permissions you want to grant, then click OK:

    View: Users may run the reports. Users will also need Report permission for objects included in the reports.

    Edit: Users may run and edit the reports. Users will also need Report permission on objects included in the report. If permission is on the folder, users may create and modify reports for objects to which they have permissions, manage versions, create subfolders, and copy or move reports.

    Unrestricted: In combination with View or Edit, allows users to view or edit reports for objects regardless of their permissions to the objects. Unrestricted permission is also required to view cached reports accessed via Quick Links or any cached reports run on-demand that were not executed by the user.

     Unrestricted permission on a report or Manage Reports right is required to access a cached report via a Quick Link. Unrestricted permission is also required to use the object selector when running a report.

  5. To extend the same permissions to all child folders and reports, check Apply to Children.

    Permissions are inherited by default only when a folder or report is created. To grant new users permission to existing reports and folders, the changed must be applied to children.

  6. Click Save.

Delete permissions for a user or group

  1. Check the Select box for the user or group.

  2. Click Delete.

    The permissions are removed and the Permissions column is now blank for the user. However, you must also save the changes.

  3. Check Apply to Children to delete user permissions to all existing reports and subfolders.

    If you do not check Apply to Children, the user’s permissions on all existing reports and sub-folders will be retained. The changes will only apply to new reports that will inherit the new permissions.

  4. Click Save.
