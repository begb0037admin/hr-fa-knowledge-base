Create a Requirement (Overview)

Several different types of requirements may be represented in the system model. Although each type may have specific configuration steps, creating a requirement object includes the same basic steps for all requirement types.

A Requirement may be associated with a Facility/Program, Unit/Element, or POI. The following generic steps apply to creating a requirement.

To create a requirement:

  1. Select the parent object (Facility/Program, Unit/Element or POI) to which the requirement applies.

  2. Right click the object in the system model tree and choose New > Requirement.

  3. Choose the Requirement Template from the selection list.

    In many cases an appropriate Requirement Template has already been created and you can choose it from the list. If no appropriate Requirement Template exists, you can click the link to Create a New Requirement Template (if you have the appropriate rights). See Requirement Templates.

  4. Select the type of requirement to create.

    Optionally, you may select a Custom Field Template to apply.

    Custom Field Templates are used to apply a group of user-defined custom fields to system model objects. If an appropriate Custom Field Template already exists, you may choose it from the list. The fields will then be available for entry on the properties form next. You may also create a new Custom Field Template if you have the appropriate rights.

    See Custom Field Templates.

    If you do not have a Custom Field Template to apply, skip this option. You may also apply a template later. Apply or Change Custom Field Template.

  5. Select Continue.

    The form that is displayed is specific to the requirement type chosen. See the sections for each requirement type for specific instructions.

    For the fields that apply to all requirement types, see Standard Fields for Requirements.

  6. Select Save and Confirm.
