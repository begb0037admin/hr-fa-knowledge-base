Facility/Program

A Facility/Program may be either a first or second-level object in the system model hierarchy. A Facility/Program may represent an actual physical facility (plant, equipment, etc.), a project, or a regulatory program (such as air quality requirements or Title V permits).

A Facility/Program may be placed under a Division in the tree for organizational purposes. However, a Division is simply a container object which has no requirements associated with it. The Facility/Program has fields that may be used to define the regulatory program. Most importantly, it sets the time zone to be used for tracking, which is inherited by all objects beneath it. It is the highest level object with which requirements may be associated.

To create a new Facility/Program:

  1. Select the Locations and Programs object in the System Model pane, or select a Division object that you want to place the Facility/Program under.

  2. Right-click and choose New > Facility/Program.

    On the first screen, you may select a Custom Field Template and a Calculation Template to apply, if desired. These are optional.

    Custom Field Templates are used to apply a group of user-defined fields to system model objects.

    Calculation Templates are used to hold numeric and calculated information specific to the object. These fields may then be used in calculations on direct child requirements.

    To apply a template, select it from the list. The fields on the template will be available for entry on the properties page next. You may also create a new template if you have the appropriate rights.

    If no templates apply, or you want to apply templates later, simply click Continue.

  3. Select Continue.

  4. Enter a Name.

    This is the name that will appear in the system model tree. To add localized values for different languages, click the language symbol .

    Disallowed characters in names include "\", "/", "[", "]". For other discouraged characters, see Object Naming Rules.

    If the object name represents sensitive data that should be protected for security or privacy reasons (such as an employee name or other identifying information), you can indicate it by checking "Name may contain sensitive data".

     Fields marked as possibly containing sensitive data will be irreversibly scrubbed before leaving the customer environments, which means that Cority staff will not have access to these values in non-production environments such as staging and QA. See Sensitive Data Fields.

  5. Select a Time Zone.

    This is a required field. The time zone is inherited by all child objects and is used for all data associated with the facility and its children.

    Daylight Saving Time is enabled by default and is usually used for task-based systems. For data that must be stored in standard time (without DST), such as data uploaded from continuous monitoring systems, be sure to disable the Daylight Savings Time option by unchecking the box.

    The time zone cannot be edited once data has been entered in the system, so choosing the correct time zone and DST option is important during the setup.

  6. Complete the rest of the fields as applicable.

  7. Select Save.

    The properties of the Facility/Program are displayed for review.

  8. Select Confirm to save the Facility/Program, or Back to edit it.

    The new Facility/Program will appear in the system model.

You can create multiple Facility/Program objects in bulk under different Divisions. The objects created in bulk will share the same name and properties.

To create multiple Facility/Program objects in bulk:

  1. In the Applicable Requirements view, select the Divisions under which you want to create the new Facility/Program objects.

  2. Right-click and choose New > Facility/Program.

  3. Select a Custom Field Template or Calculation Template, if desired, or just click Continue.

  4. Complete the properties form as applicable. The same property values will be applied to all the new objects.

  5. Click Save.

    The list of objects to be created and the property values are displayed for review. You may click Back to edit if necessary.

  6. Click Confirm.

Fields for Facility/Program Tree Object

Required fields:

  • Name: Name of the Facility or Program (as it will appear in the System Model tree). Disallowed characters include "\", "/", "[", "]".
  • Time Zone: The Time Zone for the Facility or Program. The time zone is inherited by all child objects and is used for all data associated with the facility and its children.

The first set of selections for US time zones use Daylight Saving Time adjustments and are normally used in task-based systems. When data needs to be stored in standard time only, without DST adjustments, use the set of USA Standard time zones.

Optional fields:

  • Name may contain sensitive data: If the object name represents sensitive data that should be protected for security or privacy reasons (such as an employee name or other identifying information), you can indicate it by checking the box.
  • Active Date: The date that the Facility or Program became active (optional).
  • Inactive Date: The dates that the Facility or Program became inactive (optional). See Non-numeric Requirement Field Definitions.
  • Responsible User: Optional user to be the default assignee for all tasks associated with the object. (Actual assignee may be changed on task creation or edit.)
  • Official Facility/Program Name: Official name, if different from the name used in the System Model tree.
  • Facility/Program Address: Address fields. Select the desired country, state or province (territory) from the drop-down menu.
  • Mailing Address: Mailing address, if different than above.
  • Primary SIC/NAICS: Primary industry code, as defined by the North American Industry Classification System (post-2003, six digits) or the pre-2003 Standard Industrial Classification System (four-digits).
  • Secondary SIC/NAICS: Secondary industry code.
  • Dun & Bradstreet No.: D-U-N-S number for this business location (nine digits).
  • Province/Region/Other: Use for any additional information desired.
  • Contact Information: Name and information for the primary contact.
  • Geographical Coordinates: Latitude and Longitude and/or UTM Coordinates.
  • Meteorological Location History: Nearest city to use for meteorological data. This is used only for some Material Activity calculations. See Meteorological Data.
  • Regulatory Identification Numbers: EPA, State Agency, Local, or other authority ID numbers
  • Relations: Documents from the Documents library to associate with the object. See Associating Documents.

 Additional custom fields may be applied through a Custom Field Template and/or a Calculation Template. See Custom Field Templates and Calculation Templates.
