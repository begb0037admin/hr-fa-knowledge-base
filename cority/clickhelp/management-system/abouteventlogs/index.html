About Event Logs

Event logs are used for two purposes in the system:

  • To store information about deviations, or periods when a requirement is not determined to be in compliance.
  • To store non-deviation information about one or more requirements for reporting purposes, such as to provide a log of safety incidents.

Event Logs may be configured for Automatic or Manual entry. The method depends on the type of requirement being monitored and the type of record-keeping required.

  • Event Logs that monitor deviations for numeric requirements are usually automatic. Events are automatically generated when the requirement limits are exceeded.
  • Event Logs that monitor non-numeric requirements automatically generate events when an associated task is completed with a compliance status of Not Determined, thereby providing a deviation log for non-numeric requirements.
  • Event Logs that store non-deviation information about a requirement, such as health and safety incidents or required activity logs, are usually configured for manual entry.

Both manual and automatic event logs can be configured to automatically generate a task when an event is created. When a task is associated with an event, the information fields to document an event may be completed directly from the task completion form.

Examples from Solution Templates:

Auto Event Log for Numerics with task triggered by exceedance: CEMS Facility\Unit\PC-Fired Boiler Emission Point\Air Emissions Deviation

Auto Event Log for NNRs triggered by task "Not Determined": Permit Management Facility 2\Major Emission Sources\Title V Deviations (has task template)]

Manual Event Log with task triggered by creation of log entry: SPCC Facility\Spills and Discharges\Spill Response and Resolution]
