Parameter Field Definitions

Active Dates

The active and inactive dates define the date range when a requirement applies.

These dates are not necessarily the same as the effective dates for a requirement, as specified on the Requirement Template.

For example, hazardous waste tank regulations became effective on 11/19/80. A facility uses a tank to store solvent product for many years, but decides to start using the tank for used solvents (hazardous waste) on 05/01/01. Hazardous waste tank requirements have an active date of 05/01/01 for that tank.

 Requirements that have expired (as determined by the Active/Inactive Dates) will appear with a red X through the icon in the system model tree.

Responsible User

If a responsible user is assigned, that user becomes the default assignee for any tasks associated with the requirement. However, the assignee may be changed. For multi-object tasks, all responsible users designated on the selected objects will be included as task assignees.

Requirement Source

The Requirement Source section allows you to provide further information concerning the requirement driver, as initially supplied from the Requirement Template. Depending on the Requirement Template, you can supply the specific citation, specific requirement, condition number or other information.

Periodicity

Periodicity for a Parameter or Variable defines how often the parameter should be monitored or the period it applies to, as specified in the permit. This field is for information only and does not affect any tasks or events set up to monitor the requirement. However, it may be used on reports. If not applicable, leave the field blank. The Periodicity should not be confused with Data Collection/Sampling Frequency, which specifies how often the data is actually collected (which may be more or less frequently than the permit requirement).

The limit on a particular emissions requirement is given as X per hour. Data is entered once a month and calculations made to determine the hourly emissions. The Periodicity is 1 per hour. The Data Collection Sampling Frequency is 1 per month.

Description

Description of the Requirement (what it is set up to measure or other information).

Quality Template

An optional Data Quality Template may be applied to a parameter in order to store additional attributes attached to a particular data point. Fields on a data quality template are custom fields. Optionally, they may be used in a substitution script for a specific data point. See Data Quality Templates.

Calculation Parameters for Quality Substitution Script

These are the numeric, Boolean and calculated fields on the Quality Template that are available for use in defining the Quality Substitution Script. The list is read-only.

Quality Substitution Script

Based on the Data Quality Template applied, you may define a formula to be used to substitute a given or calculated value for a data point.

For example, if the data point is below the detectable limit, then substitute one-half the detection limit. The Data Quality template contains the Boolean field "Below detectable limit?" , the numeric field "Method detection limit" and the calculated field "Limit substitution value," which is defined as:

0.5*[Method detection limit]

The Quality Substitution Script is defined as:

IF ([Below detectable limit?]=1) THEN

[Limit Substitution value]

ELSE

[CURRENT]

END IF

The Begin/End Dates define the active dates for the substitution script.

Both the raw data point and the calculated value are stored in the system. The substitution value is the value that will be used in other calculations and in reports.

The NEXT, PREV and CURRENT functions are available for use in data substitution scripts. These fields return the next, previous or current raw values of the parameter, relative to the date/time of the data point.

Unit of Measure (UOM) fields

The unit of measure for data entered for the requirement. Select Use Auto UOM Conversion to allow users to enter data in any of the UOMs defined for the specified UOM Category (UOMs and UOM categories are defined in the UOM Libraries). Select the UOM to be considered the base UOM. Data entered will be converted into the base UOM. 
If Use Auto UOM Conversion is not selected, select the UOM to be used for entering data. No conversion will take place.
These UOM fields cannot be changed once data is applied.

Data Determination Method

Specifies the method used to collect or determine numeric data. Data determination methods include hand-held instruments, laboratory analysis, visual observation, process instrumentation, continuous emissions monitoring, and the output of software applications.

Select a value from the list, or enter a value in the text box provided. This field is for information only; if not applicable, leave the field blank.

Data Collection/Sampling Frequency

The Data Collection/Sampling Frequency specifies how often data is collected. For example, a sample that is taken weekly has a Data Collection/Sampling Frequency of 1 time per week. This field is for information only and does not affect any tasks or events set up to monitor the requirement. However, it may be used on reports. If not applicable, leave the field blank. See the example under Periodicity for the difference between these two fields.

Precision

Determines the number of places to the right of the decimal point that will be displayed when displaying data, both online and in reports when HTML or standard Excel is the output format. The values are rounded. However, the full, unformatted value is stored in the system and is used for all calculations, including the aggregate functions of a report. The full value is also exported in an Excel template report.

Valid Range

Valid range fields may be used optionally to define valid data entries and limit data entry errors. For example, due to the physical or chemical nature of a parameter, some values have limits. For example, pH ranges from 0-14; therefore, the valid range for a pH requirement is 0 to 14. If you try to enter data outside the valid range, the system will not accept the data.

Acronym Data Substitution

Defines acronyms (text entries) that may be used in data entry. Each acronym is associated with a numeric value that is then stored in the system.

Expected Frequency

The expected frequency of data points may be specified as the number of data points expected per day. If this field is used, missing data warnings are generated when data is not entered as expected.

Regulatory Limit

The regulatory limit for the requirement. When data exceeds this limit, a data warning is issued. If an event log is associated with the requirement, an event will also trigger. An automatically triggered task may also be associated either directly with the requirement, or with the event log. See Setting Regulatory Limits.

If a regulatory limit is specified, the limit Begin Date must also be set.

Internal Limit

The internal limit for the requirement, used to issue a warning when the data value exceeds the internal limit. Options are the same as for the regulatory limit.

Task Template

Specifies the task template to be used, if any, to trigger a task when the data exceeds the specified limits. Tasks may be assigned directly to the parameter this way.

Alternatively, if an Event Log with a task is associated with the requirement, an event will trigger and create a task when data exceeds limits. Using an Event Log allows for the inclusion of custom fields to document the event on the task. However, if you do not need to track exceedances as events or provide supplemental information, you can assign the task directly from the parameter.

Limit Begin/End Dates

Defines the date range to which the limits apply. A limit history is maintained so that if the limit changes at a particular date, you may edit the limit value and set a new begin date to apply to data in the new date range.

Data Warning Notifications

Use to specify additional persons or groups who should receive notifications if the regulatory or internal limits are exceeded. All persons with view rights on the requirements will automatically receive notifications, so this should be used only to notify those without view rights on the requirement.

Documents

Links to documents stored in the Documents library that are associated with the requirement. For example, specifications or instructions.

Citations

Links to Citations associated with the requirement. See About Citations.

Tags

Tag Schemes and Tags associated with the requirement. See Tag Schemes and Tags.
