Manage Security Policies

Administrators may specify security policy criteria for all system users in the Security > Policies page. Password requirements and automatic account lockout features may be customized to suit your business security requirements.

Password options include the ability to specify password complexity, and to set requirements for changing passwords regularly, as well as automatic password expiration.

In addition, account lockout options may be set to automatically lock an account after a specified number of failed login attempts.

Concurrent Logins Policy: In addition to System-specific security settings, concurrent sessions (interactive user sessions) are disallowed from separate computers. This means that if someone attempts to login with a user name that is already logged on, the person is granted a session and the existing session for the same user is revoked, resulting in the person already logged on being kicked off.

Security policies that may be controlled by a System Administrator include password requirements, account lockout options, and session timeout. Security policies affect all users of the system model. Limited security options for an individual user may also be specified in the user profile.

To set security policies for the system:

  1. From the menu, select Setup > Policies under Security.
  2. Check the desired options (see below for description).

  3. Select Save to save the options.

    Password options:

    Enable password complexity: Complex passwords required for all users. A complex password must include 3 out of 4 of the following:

    • At least one upper-case letter
    • At least one lower-case letter
    • At least one number
    • At least one special character

    Enable minimum password length: Passwords must meet a minimum character length. Specify number of characters (minimum three) in adjacent box.

    Enable maximum password age: Passwords expire a specified number of days after last reset. When a password expires, the user will be redirected to a password change page on login. Specify number of days in adjacent box.

    Password "age" is calculated based on the last time a user changed their password. If the user has not changed the password the system uses the time the initial user password was set by the administrator.

    Enable password history: Password history is retained, in order to restrict a user from setting a password that has been recently used. Specify number of password instances remember in the adjacent box.

    The system will store passwords and not allow the user to reuse a password if it falls within the specified number of instances. For example, if set to 3 instances, the first password will not be available to be used again until three different passwords have been saved in the profile.

    The following option is available:

    Enable minimum password age: This option is only available if "Enable password history" is selected. Requires a minimum period before a password can be changed. Specify number of days until password can be reset in adjacent box. The system will not allow a user to change the password until the specified time has elapsed since the last password change. Check "Except if user has forgotten password" to enable resetting the password regardless of age in the case of forgotten passwords.

    Enable forgotten password request: This option enables users to reset their passwords by clicking on a "forgot password" link on the login page. An email with a temporary password is sent to the email on the user profile. After logging in with the temporary password, the user is required to answer one of the security questions set on the user profile, after which they must reset their password. Optionally, as an additional security measure, you can specify that an administrator be notified when the feature is used and select the user/group to be notified.

    Account Lockout

    Enabling account lockout allows you to lock an account after a number of failed login attempts. The following criteria may be set:

    Failures before lockout: How many failed login attempts are allowed before account is locked.

    Minutes until lockout ends: Number of minutes after lockout until login with correct password will work.

    Minutes before lockout counter reset: Number of minutes the system retains a log of invalid login attempts.

    Session timeout: Period of inactivity allowed before session times out and user must log in again.
