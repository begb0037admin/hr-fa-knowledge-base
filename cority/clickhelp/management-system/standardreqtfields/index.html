Standard Fields for Requirements

The following fields are standard for all requirements. Other property fields are specific to the requirement type and are explained in the sections for each requirement type.

  • Name: Name of the Requirement (as it will appear in the system). Certain characters are disallowed or strongly discouraged in names. For naming restrictions, see Object Naming Rules.
  • Active Date: The date that the Requirement became active (optional).
  • Inactive Date: The date that the Requirement became inactive (optional). See Non-numeric Requirement Field Definitions.
  • Responsible User: Optional. If a user is selected, that user will be the default assignee for tasks created for the requirement.
  • Requirement Template: Template that contains the information about the driver for the requirement. See Defining Drivers for Requirements.
  • Requirement Source: Collection of fields that allow specifying the Specific Citation, Specific Requirement or Condition Number.
  • Periodicity: defines how often the requirement is to be implemented or is applicable. Use of this field may vary according to the requirement type. See the field information for the requirement type.
  • Relations: Documents associated with the Requirement may be linked from the Documents library, if desired. See Associating Documents. If there are related Citations in the system, they may also be linked. See Citation Associations.

Additional custom fields may be applied to the Requirement through a Custom Field Template. See Custom Field Templates .
