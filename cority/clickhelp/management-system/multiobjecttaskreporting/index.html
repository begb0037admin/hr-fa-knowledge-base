Multi-Object Task Reporting

When reporting on multi-object tasks, you can choose whether to combine multi-object tasks into a single row in the Task Report, or to include one row for each task-object instance.

Step 1 in the Task Report setup page has a checkbox for Aggregate Multi-Object Tasks. If this is checked, then one row will be returned for each multi-object task. If unchecked, one row is returned for each task-object instance. In order to aggregate task, the Task Due Date must be included.

Different properties are available for inclusion in the report, depending on whether you want to aggregate results for multi-object tasks or not.

When aggregating multi-object tasks, the following three properties should be used to aggregate results in a Task Report:

  • Overall Completion Status (%): This is computed as the average of all task status records for a task instance (given due date, object, and task).
  • Overall Status Description: Gives the status of all task status records for a task instance (given due date, object, and task). Possible status descriptions are Completed On-Time, Completed Overdue, Pending, Overdue, and Dismissed.
  • Overall Completion Date: Gives the date/time of the final completion date of all task status records for a task instance (given due date, object, and task).

The following three properties are used to report on singular task-object instances, without aggregation:

  • Task Complete Status
  • Task Status Description
  • Task Completion Date

Assuming you have a multi-object task that applies to 4 objects, a task report produces the following results:

  • If you include "Overall.." properties AND check the "Aggregate" checkbox, results show 1 row for the task.

    Overall Task Completion (%) reported is an aggregate of the completion % of all 4 task-object instances. If the task is complete for 3 of the objects and not complete for 1 object, the Overall Task Completion (%) is 75%.

    Overall Completion Date is the last completion date in the set. If not all instances are not complete, value is null (shown as "-").

    Overall Completion Status is aggregated and reported as Completed on Time (if task was completed on time for all instances, Completed Overdue (if any instance was completed overdue), Pending (if any instance is incomplete and not yet overdue), Overdue (if any instance is incomplete and overdue), or Dismissed (if task was dismissed for all instances).

  • If you include "Overall.." properties and do NOT check the "Aggregate..." checkbox, the report returns 4 rows, one row for each task-object instance. However, the "Overall.." property values are still aggregated as above. You must use the singular Task Complete Status, Task Status Description and Task Completion Date properties if you want to see singular instance (task-object) status.

For example, if the task is to clean 4 pieces of equipment, and the task was not complete for one equipment, using aggregation you would see Overall Completion Status of 75%. If you want to know which one was not cleaned, you would have to run the report including the Task Complete Status property and unchecking the aggregation checkbox. The Task Completion status for the 1 equipment would be 0%. The Overall Completion Status would still be 75%.

When a report includes multi-object tasks, the Overall task properties are preferred. For single-object tasks, the "Overall..." properties will return the same values as the singular "Task Complete.." properties. So in general the use of the Overall properties in the task report is recommended, since aggregation of multi-object tasks is the most commonly desired result. However, if you want to see other properties of the tasks (such as Time to Complete, Cost to Complete and Comments), you will have to run the report with "Aggregate.." unchecked. When tasks are aggregated, these columns will be null for multi-object tasks. Additionally, any custom properties will also not be reported when aggregation is requested for multi-object tasks.

The aggregation checkbox has no effect on single-object tasks. For example, Cost to Complete will be shown for single-object tasks, but will not be shown for multi-object tasks unless the aggregation box is unchecked.

If parent object name or other parent object properties are included in the report, aggregation for multi-object tasks will show only the properties for the lowest common parent object. For example:

Task 1 (due 1/1/yyyy) applies to two objects:

F1\U1 : 100%

F1\U2 : 100%

Report columns are:

Facility Name | Unit Name | Task Name | Due Date | Overall Completion Status

Results show:

+F1 | -- | T1 | 1/1/yyyy | 100%

+results aggregated for multi-object task
