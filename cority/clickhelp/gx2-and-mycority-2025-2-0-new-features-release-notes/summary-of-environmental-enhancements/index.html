Summary of Environmental Enhancements

The table below contains design improvements we have made in the Environmental cloud. The items are organized by component and the components are arranged in alphabetical order.

ItemComponent(s)Description
CCC-18863Chemical Management

The applicable location logic for approved Chemical Product 'Change Requests' is no longer hard-coded. It is now implemented through a new business rule (BR-100663) that uses a new method action (BRA-100663).

The BRA adds MoC location details to its Inventory location when the workflow is 'Approved'.

The BR adds the location(s) selected on a product's MoC record to its Inventory location(s) when the MoC workflow is moved to the 'Approved' status.

The entity is EnvironmentalManagementOfChange.

This makes the functionality more flexible:

  • It can now be disabled.
  • The priority can now be altered.
  • The sequence for when the functionality should be triggered can now be configured.

 

CCC-17216Compliance

When the Import Utility is used to upload a regulation and associated permit, the relationship will now be recognized during upload and the regulation will be linked to the permit after the upload is complete.

 

CCC-12504Compliance

There is a new look-up table named LU_GLB_Requirement_A (with Entity = RequirementRecordHistory). It contains all fields in LU_GLB_Requirement. The table stores the Environmental and Safety requirements (from LU_GLB_Requirement) record history.

The table is available for use in both Query Builder and Report Writer.

 

CCC-8276EHS Investigation – myCority

There is a new global system setting ‘EHS Investigation Level Always Available in myCority’, which is a check box that allows administrators to specify whether or not the EHS Investigation approval level is always available in myCority.

By default, the setting is selected.

 

If the setting is selected, the existing behavior is retained.

 

If the setting is not selected, the EHS Investigation approval level record will not appear in myCority until the other investigation levels (up to three) are completed:

  • Even if the user is assigned all investigation levels, only one Incident record will appear in myCority.
  • If the Incident Investigation is using separate layouts for each level and/or using Primary Category (General Incident Category), then only the current approval level’s record, the one with the buttons for the current level, will be shown.

 

CCC-14746Environmental Requirements – Site Security

Site security is now enforced on the Environmental 'Requirements' module, based on the 'Applicable Locations' sublist.

Now, only requirements that pertain to the locations granted to the user will be visible on the Environmental 'Requirements' list view.

Also, when the user is adding a record to the Requirements sublist, the modal box will filter to only the Requirements records applicable to the location of the main record.

 

CCC-19432Event Reporting – myCority

In myCority, an embedded questionnaire can now be completed while offline. This is beneficial because questionnaires are used to obtain additional, critical information not collected through the Event Report layout.

An automatic or manual download of an Event Report template or in-progress Event Report will now include any associated, embedded questionnaire(s).

While offline, the embedded questionnaire will now function as if online. It can be completed offline and then uploaded/submitted when back online.

 

CCC-16840Waste Management

For the Event Reporting, Sampling, and Waste solutions, for a form or record downloaded in myCority, any filter display rules associated with the corresponding entity will now also download so that they can execute offline.

When the display rule criteria are met, the rule(s) will execute as expected dynamically (without save).
