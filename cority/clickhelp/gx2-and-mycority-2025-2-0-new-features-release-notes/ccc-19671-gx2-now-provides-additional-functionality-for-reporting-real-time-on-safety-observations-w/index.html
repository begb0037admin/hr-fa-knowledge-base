CCC-19671: GX2 now provides additional functionality for reporting real-time on safety observations within your organization

Opt-In

This will help drive a proactive approach to safety and overall organizational compliance by enabling Protex AI to automatically add detected safety observations to the system.

Updates made to support this functionality include:

  • The following new fields can now be added to custom versions of applicable Safety ‘Event Reporting’ and ‘Incident’ layouts:
    • Protex ID – A text field with a maximum character limit of 1000
    • Protex Rule – A text field with a maximum character limit of 8000
    • Protex Camera – A text field with a maximum character limit of 1000
    • Protex URL – A text field with a maximum character limit of 1000
    • Protex Tag – A multi-select look-up table (picklist) field, which categorizes events for filtering
  • The first four fields can also be added to custom versions of applicable myCority Safety ‘Event Reporting’ and ‘Incident’ layouts.
    • For the ‘Protex Tag’ field, a corresponding new look-up table with appropriate default entries has also been added. The look-up table is categorized under the Demographics module and has all of the functionality typical of standard GX2 look-up tables.
    • Each of the new fields can be used in business rules and display rules, populated and updated using import, and reported on using Query Builder or Report Writer.
    • For each field, a corresponding new column can be added to applicable list views.
    • When an Event Report using the new fields is posted to an Incident Investigation, the new fields and values will also be posted to the Incident Investigation.
  • The REST API has a new ProtexEvent endpoint that supports only POST calls. The Employee and Event Type used are the ones specified beforehand in the new ‘Default Protex Employee Event’ and ‘Default ProtexAI Event Type’ system settings. The former is a picklist to the Employees look-up table and the latter is a picklist to the ‘Safety Event Type’ look-up table.
    • A ProtexEvent POST call should include values for the following:
      • eventData.violation_uuid – Protex ID (the Protex primary identifier)
      • eventData.event_time – Time and date the event occurred
      • eventData.camera.name – Protex Camera
      • eventData.rule.name  - Protex Rule
      • eventData.event_link – Protex Link
      • eventData.violations_tags[].tagname -  Protex Tags
      • eventData.site.site_id – Associates the event with specific sites (populates the record with the associated GDDLOFB in the linked GDDLOFB fields)
      • Event Type – A GX2 value
      • Person Reporting – A GX2 value
    • To support the eventData.site.site_id parameter, a new ‘Site Mapping’ (GDDLOFB) look-up table has been added. The look-up table is categorized under the Demographics module and has all of the functionality typical of standard GX2 look-up tables.
      • This new look-up table has security actions for create view, edit view, add to favorites, clone view, and delete.
    • Each import and import attempt will be logged in the ‘Process Status & Log’ and ‘Event Log’. The former has a new ‘ProtexAI Import View’

To use this functionality, a subscription to Protex is required. For more information about that, contact your Cority representative.

For more information on working with custom layouts or list views or on working with the REST API, see the GX2 User Guide.
