CCC-15823: Query Builder now allows multiple join operations for the same entity

Opt-In

This replaces the need to combine two columns as a string and then set up the join with the new calculated column.

The new functionality reduces the CPU consumed and long running time encountered while using the previous method when dealing with a dataset of less than even 10,000 records.

This will assist greatly in creating and running OH reports (for example, SEG reports, as Clearance and Surveillance Enrollment are not linked).

To support this, the existing functionality has simply been expanded intuitively (as would be expected).

It provides the ability to select the duplicate entity in 'More Settings', which applies to look-up tables, data tables, and subqueries.

Note: If the 'Parent Matching' and 'Child Matching' field values are not specified in the 'More Settings' tab, an error will occur during save.

Once the selected entity is duplicated, Query Builder allows for the use of the 'Matching records only' check box for the first row. Subsequent records will have the check box hidden. 

If the entity needs to be removed, the 'X' option can be used.

On the Build tab, an entity joined multiple times will appear only once.

In Query Builder, when using this feature, all other functionality (site security, scheduling, publishing as a dashboard indicator, use of the Query Builder report in Report Writer, etc.) will work as it did before.

For more information on how to set up a join in Query Builder, see the GX2 User Guide.
