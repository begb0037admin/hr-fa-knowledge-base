QualityEventReportType

This table lists the possible event report types that may be included in the QualityEventReportSelection and/or the myCorityEventReportSelection look-up table(s) for display to event reporting users.

For each report type:

  1. Enter a Code and Description for the report type.

  2. Optionally, select an Icon to be shown with the event report type name on the event reporting start page (must be included in the UserIcon table).

  3. Optionally, select the Standardized Value (from the EventReportTypeStandardizedValue look-up table) to categorize each record. This value will be used by the predictive Analytics module to compare your data to that of other organizations and determine your relative performance.

  4. Select the layouts to be used when accessing event reporting in Cority and via standalone access and the Portal.

  5. Optionally, enter any Instructions for users to complete event reports of this type.

  6. By default, a user must save the event report before they can submit it. If you want to disable this workflow for this event report type, you must add the Require Save before Submit checkbox to a custom view or layout in order to deselect the checkbox.

    • If you deselect the checkbox and Save is on the layout, it will still appear for users but will be optional.

    • If you leave the checkbox selected, the Save button appears for users even if it's not on the layout, and the Submit button is disabled until after Save is clicked.

    See below for further guidelines about selecting or disabling this workflow.


Guidelines for determining whether ‘Require Save before Submit’ should be selected:  

This is not a complete listing of all possibilities; you may have some event reports that require Save first and others that do not.

Require Save Before Submit = selected when: 

Require Save Before Submit = deselected when

  • Create New Record BRA is applied to Event Report e.g. adding a Questionnaire to Event Report for completion prior to submission
  • Sublist records need to be completed prior to submission
  • Geared to Guest User (may not even want Save button) since they cannot leave record and come back later to finish and submit
  • Simple Event Reports to reduce clicks
