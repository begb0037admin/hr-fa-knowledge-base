Migrating Configurations

This function enables you to quickly and easily import or export business rules, dashboards, layouts, PDF forms, questionnaires, reports, and/or system settings from one environment to another. You can import or export links to dashboards (e.g. links from the My Views dashboard gadget); if importing, the dashboard(s) must already exist in the target environment.

  1. In the Administrator menu, click Migrate Config (you may have to add this to your menu).

  2. If you want the import/export of an object to apply only to certain records, select the object and click Edit, then select a Query.

  3. To export a configuration, select the object(s) that you want to export and choose Actions»Export Configuration. A JSON file will be downloaded to your computer containing the configurations for each of the selected objects.

  4. To import a configuration:

  • Choose Actions»Import Configuration.

  • If you want to update existing records, you must set the toggle before selecting the file to import.

  • Select the JSON file to import.

  • When the import is complete, the Import Configuration dialog will refresh and list each of the objects that were imported, as well as any errors encountered during the import. Click View Log to view the Process Status & Log (see Viewing Import Logs) that will show a detailed record for each of the imported objects.

 You can export (or import) configurations from select modules directly from the Actions menu in their list view. For example, in the Users list view you can choose to Export User Configurations, Export User Menu Configurations, Export User Setting Configurations, etc. This applies to look-up tables, standard views, translations, roles, users, and workflows.

Migrate Configuration Checklist/Best Practices

  1. Schedule Downtime
    Do not migrate configuration into a live system — the configuration being migrated will affect the system for users that are logged in. Moving configuration data will have unintended consequences if the system is live.
  2. Test Import
    Before migrating into a production environment, the process, objects, queries and sequence should be tested in a non-production environment.
    Additionally, the procedure should be documented, steps, sequence, expected results and actual results to establish the validity of the process.
  3. Backup Target
    Before moving any configuration into a production environment it must be backed up in the event the migration does not go to plan or fails verification/testing.
    • Take a snapshot of the entire database the configuration and date.
    • The configuration of the target environment should be well documented to ensure the configuration can be restored manually if necessary.
  4. Review/report on the export queries, publish the queries to:
    • Dashboard
    • Reports
  5. Document Changes
    Print reports from source, verify in target date and sign
  6. Be precise with the configuration being migrated — don’t migrate everything
    • Only configuration that’s been added/changed as part of the project
    • Always use a query to limit the scope
    • Exclude negative IDs
    • Exclude Cority Translations
