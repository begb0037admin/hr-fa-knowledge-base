Setting Up Users

Users defined as MEIP User can run the Cority HR Integration Utility to import large numbers of employees. For more information, refer to the Cority System Guide.
myCority users can be auto-created with the generic Import Utility; for more information, see Importing Text or XML Files into Cority Tables.

Non-admin users with “user.new” and “user.save” security action privileges can also create new users.

If the active user count is at the maximum licensed, you will receive an email notification if you attempt to add (or import) a user or change an inactive user to active. The following users are not included in the “Active” user count:
- users flagged as inactive
- users who are not assigned any roles
- portal users
- anonymous/public users

To create a user:

  1. In the Administrator menu, click Users. A list of all user accounts that have been defined appears.
  2. Click New.
  3. Enter a Login Name/Profile Name and Login Password, and complete as many of the fields as necessary.
    • To prevent a Portal user from accessing the Cority application, select the Portal Only checkbox.
    • To prevent this user from viewing or creating their own medical records when the “Restrict Users from Viewing Their Employee Medical Records” system setting is on, select their Employee. This logic is also carried over into Portal.
    • To enable Mixed Authentication SSO and Password function for this user, select the Allow Mixed Mode Authentication checkbox. 
      Note  The "Authentication Method" and "Portal/myCority Authentication Method" system settings must be set to "Mixed Mode (SSO SAML 2.0 and UserID/Password)". If the user clicks Login with SSO on the GX2 login screen, they will be directed to your organization's IDP SSO login screen (as defined in the SAMLKey look-up table record that is set to "Default for Main Application"). If you want users to be taken directly to your IDP's login screen without having to click Login with SSO, you must modify your GX2 URL to include the additional required URL parameter.
    • Users flagged as MEIP User or MGIP User will not become inactive and their passwords won’t expire.
    • If you have defined profiles of system settings and/or menu configuration, select the appropriate Default Profile for this user.
    • For OH Users: Indicate if the user may be selected as a Practitioner in OH modules, and/or if the user may be selected as a Case Manager in the Case Management module.
    • For Scheduling Users: Indicate if the user may be selected as a Scheduling User in the Appointment or Scheduling modules.
  4. Click Save. If you entered an email address, you are prompted to send a verification link to the user. This verification is required before the user can access the online user community (see Online User Community).
  5. On the Granted Roles tab, define which role(s) apply to this user.

    Before assigning roles to users, be sure you have configured the roles according to your needs; these may include functional roles, site security roles, and/or case type security roles (Setting Up Roles, Setting Up Site Security, and Setting Up Case Type Security).

  6. Optionally, use the remaining tabs to link the user to one or more health center or geographic location.

To prevent a user from logging in to Cority, mark them as Inactive. If you just want to temporarily stop a user from being able to log in, a Block Login flag can be added to a custom layout. The user will be blocked across all entry points, e.g. myCority, API, standalone links, etc.), and they will see a message to contact their administrator.

Enforcing Two-Factor Authentication for Users

If your company is using username/password authentication, you can set up 2FA within Cority as described below. If your company is using SSO, you can set up MFA on your internal network (your SSO provider will handle the MFA).

The Enforce 2 Factor Authentication global system setting provides the following options: Disabled (default), Every 30 Days, and Every Login. Note: The setting is only available if the Authentication Method is set to ‘Application User ID and Password’. 

When set to ‘Every 30 Days’ or ‘Every Login’ and the user attempts to log in at one of those times, the Cority login screen will display a two-factor authentication message followed by an Enter PIN code field and a Verify button.

  • If the user has an email address specified on their User record, the following message will display: ‘Please check your email for a verification code, and enter the code below to log into the Cority Platform’. The system will then send an email to the user’s email address. The subject of the email will be ‘Please complete 2 Factor Authentication with Cority’ and the body of the email will contain a 6-digit verification code for logging into Cority. After 10 minutes, the verification code will expire.
    The user can enter the 6-digit code in the field provided, and then click Verify to log into Cority. The login screen will also have a Resend button. If the user has lost or forgotten the six-digit code, or if it has expired, they can click Resend to receive a new verification email and code.
  • If there is no email address on the user's User record, the following message will display: ‘2 Factor Authentication is enabled. A valid email address has not been provided for you, so please contact your Cority Administrator’. Once a Cority Administrator has added the user’s email address to their User record, the user will be able to receive a verification code for use with two-factor authentication. When the user has entered the six-digit verification code and clicked Verify, they will be able to log in and out of Cority as usual for that session.

When a user logs into Cority using a six-digit verification code, a record of the event will be added to the ‘User Sessions’ view. To view this information, in the ‘[User Name] Settings’ screen choose Actions»Show User Sessions. The entries can be deleted or exported to Excel.

Impersonating a User for Troubleshooting Purposes

An administrator may be granted security permission to view the software, view data, and make changes as another user. The administrator may also impersonate the user in myCority, if the corresponding action has been added to a custom User layout. The impersonated user’s role must also be granted the General Security security module. The following functionality is not supported while impersonating another user: ePrescribing, refilling ePrescriptions, and Translations Mode.

Important Security Note for clients who must adhere to GDPR or other such regulations: This gives the user permission to impersonate any user, and therefore potentially the permission to view any record in the system. The impersonating user could then view records in modules that they otherwise do not have access to, and view sites outside of their site security settings. This privilege is best limited to support personnel who require this broad-level access in order to perform their jobs.

To impersonate a user, open the user record, then choose Actions»View Application as this User (or Actions»View myCority Application as this User). While you are impersonating another user:

  • A reminder notification will be displayed across the top of the screen.

  • Any changes you make will be logged under your own user name in the appropriate log.
  • All security settings will be respected (based on the user you are impersonating) when navigating and/or making changes.

To stop impersonating the user and return to your own GX2 account, click  in the banner notification.
