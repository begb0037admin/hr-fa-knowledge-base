Working with Ad Hoc Reports

Use the Query Builder or Report Writer to drill down through data sets and create your own reports that can be viewed on screen, exported to Excel or PDF, or emailed. These two modules allow you to:

  • filter values (e.g. PractitionerName = “BLACK”) including search using wildcard characters (i.e. * and ?)

  • define sort order, both for records within a field and also the order that fields appear in the report

  • click on a specific sample in a report output and launch sample details

  • save the report template for future queries using the same data set.

The Query Builder is an intuitive interface that replaces the Report Writer, which will eventually be removed from the Cority application. In the interim, you can use either module and any queries/reports will appear in both. For more information, see
Editing or Creating an Ad Hoc Report in Query Builder or
Editing or Creating an Ad Hoc Report in Report Writer.
When you click the Navigate to Source icon on an Advanced Dashboard indicator, the query will open in the tool defined in the “Default Data Query Tool” system setting.

An administrator can migrate reports from one environment to another; see Migrating Configurations.

Columns with high character counts will be either resized where spacing allows, or the content will be wrapped within the column. This is controlled by the "Wrap report columns with high character count" system setting. 

A user with appropriate security permissions can take ownership of any reports owned by an inactive user: in the list view, select the report and choose Actions»Take Ownership.

Using OData

The Query Builder and Report Writer support OData connections; please refer to the documentation for the external application (Excel, SQL Server, etc.) for instructions on setting up a connection. The path to the Enterprise Data Gateway that Cority has provided to you typically takes the form of:
https://yourcompany.cority.com/yourproductionsite/odata/querybuilder
(where yourcompany and yourproductionsite are specific to your configuration).

For information about filtering results from these queries, refer to OData filtering documentation, e.g. https://docs.microsoft.com/en-us/dynamics-nav/using-filter-expressions-in-odata-uris .
