Safety or Environmental Events

Cority users (normally a supervisor or a safety representative) can review submitted events and post them to incident records. Posted event reports are listed on the Related Event Reports tab of the incident report they are posted to.

If defined in the EnvironmentalEventReportType or SafetyEventReportType look-up table, an event may be automatically posted to an incident and the first email notification in the investigation workflow sent. Ergonomic events may be auto-posted to audits.

  1. In the Safety menu, click Event Reporting Inbox
    or
    in the Environmental menu, click Event Management.

  2. The default view is non-posted events; if necessary, change this to only view posted events or to view all events (including those created in the Portal that were saved but not submitted). You can also use the fields at the top to filter records by the date they occurred, type of event, or location.

  3. Click a link to review an event.

  4. Take one of the following actions:

  • If the event is deemed not valid, close the event without taking any action. The data remains available for analysis in the Business Intelligence Cloud.

  • If you have deemed the event valid, choose the appropriate action to post the event to a new or existing incident:

    • If you choose Actions»Post and Create New Incident, the event record is locked and is transferred to the Related Event Reports tab of a new incident record. If the event was an Employee’s Injury or Illness type, an injury/illness record is also created within the new incident report.

    • If you choose Actions»Post to Existing Incident, you are prompted to choose from a list of incidents to attach the event report to. The event record is locked and is transferred to the Related Event Reports tab of the incident record. If the event was an Employee’s Injury or Illness type, an injury/illness record is also created within the new incident report only if it is a new injury to another employee not already associated with the incident.

Choose Actions»Go to Incident to open the incident report and complete any additional information. See Working with the Incident Report.

When an event is posted to an incident record, the event's Findings & Actions, Questionnaire, and Document records are duplicated and posted to that incident record unless disabled via system setting.

  • If you want to have the EHS review the event to determine its validity, click Submit. A copy of the event report, including a link to the report in the Cority system, is sent to the email address identified in the IncidentInvestigationEmail look-up table. This can be configured to send to any person or persons in the organization, although normally it is sent to the EHS or Safety Manager responsible for the area where the accident occurred.

The email link can only be opened if the user has an account and password in Cority.

Ergonomic Events

Cority users (normally an ergonomist) can review submitted events and post them to audit records. Posted event reports are listed on the Related Event Reports tab of the audit report they are posted to.

If defined in the ErgonomicEventReportType look-up table, an event may be automatically posted to an audit.

  1. In the Ergonomics menu, click Event Reporting Inbox.

  2. The default view is non-posted events; if necessary, change this to only view posted events or to view all events (including those created in the Portal that were saved but not submitted). You can also use the fields at the top to filter records by the date they occurred or type of event.

  3. Click a link to review an event.

  4. Take one of the following actions:

  • If the event is deemed not valid, close the event without taking any action. The data remains available for analysis in the Business Intelligence Cloud.

  • If you have deemed the event valid, choose the appropriate action to post the event to a new or existing audit:

    • If you choose Actions»Post and Create New Audit, the event record is locked and is transferred to the Related Event Reports tab of a new audit record.

    • If you choose Actions»Post to Existing Audit, you are prompted to choose from a list of audits to attach the event report to. The event record is locked and is transferred to the Related Event Reports tab of the audit record.

Choose Actions»Go to Audit to open the audit record and complete any additional information. See Working with Audits.

Quality Events

Cority Quality users can review submitted events and post them to nonconformance records. Posted event reports are listed on the Linked Records tab of the nonconformance record they are posted to.

  1. In the Quality menu, click Event Inbox.

  2. The default view is non-posted events; if necessary, change this to only view posted events or to view all events (including those created in the Portal that were saved but not submitted). You can also use the fields at the top to filter records by the date they occurred or type of event.

  3. Click a link to review an event.

  4. Take one of the following actions:

  • If the event is deemed not valid, close the event without taking any action. The data remains available for analysis in the Business Intelligence Cloud.

  • If the event involves a customer complaint that should be investigated and resolved, choose Actions»Post and Create New Complaint. The event record is locked and transferred to the Related Quality Event tab of a new complaint record (see Managing Customer Complaints).

  • If you have deemed the event valid, choose Actions»Post and Create New Nonconformance. The event record is locked and is transferred to the Linked Records tab of a new nonconformance record (see Managing Nonconformances).
