Setting Up the Standalone Event Reporting Module (Optional)

The standalone Event Reporting module can be accessed by a non-Cority user. The URL for the standalone is comprised of the Virtual Directory Address system setting, plus the appropriate path
/safetyincidentselfreportselection/displaystandalone.rails,
/environmentalincidentselfreportselection/displaystandalone.rails, or
/ergonomicauditselfreportselection/displaystandalone.rails

As with all Cority standalone applications, there is an anonymous user that logs into the application behind the scenes. In the case of Event Reporting, the anonymous user is called Anonymous_ISR, and this user is accessible by the Users list in the application so that clients can configure their roles. Note that these anonymous users cannot be deleted.

There are four business rules for each event type that are configured to send an email notification whenever an Event Report is submitted (either through the standalone module or from within the Cority application). The body of the email will contain the details associated with submitted record, as well as a link to view the actual Event Report record. For more information, see Setting Up Business Rules.

The link in the email is configured to bring the user to the standalone component to view the submitted Event Report record. However, the Allow Self Reporting Email Recipients to Bypass Login Screen system setting determines whether or not the user must first login to access the record. If this system setting is set to true, the system will automatically log in the Anonymous_ISR user. If this system setting is false, the user must first login successfully by providing their login credentials to view the record.
