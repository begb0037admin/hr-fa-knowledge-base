Managing Electronic Staff Records (ESRs) from NHS

Cority provides an interface with the NHS to upload and manage Electronic Staff Records (ESR). This allows records to be imported from NHS to Cority, and for Cority to export updated or new records to NHS and inform if any immunization records have been deleted. ESR records are a combination of HR and Immunization data.

 The Employees list view has an Employee Merge action. If you are not using ESR, this action functions as a shortcut to the Employee Global Merge utility. If you are using ESR, this will also merge the employee’s ESR-specific job position data.  

Configuring the ESR Interface

  1. In the Administrator menu click ESR Config. 
  2. To configure ESR import:
    1. Select the Enable ESR Import checkbox.
    2. ESR records are matched to Cority data through the ESR Person ID. In the Registration Matching Rules section, select the additional matching criteria rules to be followed if multiple employee matches are encountered.
    3. The Organization (Trust) ID checkbox is selected by default and will be used in employee match-checking during import. If you have employees working in more than one entity/organization, you may want to clear this checkbox to avoid GX2 creating more than one record for such employees.
      Note  This feature applies only to Demographics records in GX2 that have multiple Job Position records and to Immunization records.
  3. To configure ESR export:
    1. Select the Enable ESR Export checkbox.
    2. Indicate if the user must have consent to export immunization records to ESR. If selected and the user has consent, the exports will run without issue. If selected and the user does not have consent, the exports will not run for the user and an error notification will be displayed.
  4. Enter the ESR FTP Setup credentials to connect with the NHS.

Layout Customizations Available for ESR

The following layouts can be customized to include fields specific to ESR import/export:

  • JobPosition:
    • Assignment Number field will display the assignment number sent by ESR for Assignment Detail (AST) records. Together, the Assignment Number and Position construct the unique record sent by ESR.
    • Export to ESR checkbox will be selected automatically upon clearance fields being changed and saved if the employee record was previously created or updated by ESR Import (i.e. has an ESR Person ID); this record will be included in the next export. It is not required to add this checkbox to the layout for the export to work, but you may choose to add it if you want to allow a user to unselect a selected checkbox to prevent that record from being exported. Conversely, if the checkbox is manually selected on a record that is otherwise not "eligible" for export, the record will not be exported.
  • Immunization – Export to ESR checkbox (same as for JobPosition described above). 
  • ImmunizationCode:
    • ESR Immunization Type, Primary Immunization for ESR – The ESR Immunization Type field maps the GX2 immunization code to the corresponding code used by the NHS in the ESRImmunizationMap look-up table. You can link multiple GX2 immunization codes to the same ESR immunization code, but must specify which one is the Primary Immunization for ESR. This mapping is required for both ESR import and export.
    • Results tab – can be used to link specific result options (the applicable ones only) to each immunization code. When this is configured, and on an Immunization record you specify an immunization code in the Immunization Test field, only the applicable result options will be available in the Immunization Result field picklist. If this Results tab is not used, then the Immunization Result field picklist will display every option from the ImmunizationResults look-up table.
  • WorkStatus – Work Status Type field; when a new employee with job data is created or when an existing employee’s job data gets updated (manually or while data sent from ESR is being processed) and the value of Work Status Type is populated on the Work Status look-up table, one of the work statuses (Active, Applicant, Applicant-Closed, Pre-Placement, or Removed) will be assigned to the employee's job position record based on specific logic required by ESR. The value of the Work Status Type field lets GX2 know which status to populate on the Employee Job Position record.
    Note  There must be a one-to-one relationship between each Work Status look-up table record and its Work Status Type value.
  • Organizational Tree – Trust Identifier field allows you to populate a node with your trust identifier code so that the node will serve as your organization’s trust identifier when the ESR interface is processing data. It is a one-to-one relationship, so the code used for the Trust Identifier value can only be used on one node in the Organizational Tree.
    Note  The trust identifier supporting the ESR data must be configured against the Organizational Tree (TreeMaster Type must be Org); if the trust identifier is populated against any other trees, the ESR interface will ignore it, and because its information is necessary for inserting a new or identifying an existing employee within GX2, the import will fail. If a trust identifier code for an incoming ESR is missing in GX2, the record will be skipped (not processed).

Importing from NHS

When importing ESR records:

  • For a new employee, a new Employee Demographics record will be created with the Job Position tab populated and any immunizations populated/updated.
  • For an existing employee, their Employee Demographics record will be updated, if necessary, and any new immunizations will be populated/updated.

The interface logs the following record types:

  • Assignment Details (AST) – processes, interacting with Job Position(s)
  • Deleted Immunization (ETD) – processes, interacting with the Immunization module
  • Immunizations (ETA) – processes, interacting with the Immunization module
  • Personal Details (PER) – processes, interacting with the Demographics module
  • Not Supported – data that GX2 does not support, received but ignored

Reviewing the ESR Import Log

In the Administrator menu, click ESR Import Log.

The ESR Import Log captures all interactions from ESR to Cority. Each log record includes the name of the file imported, the created date (when the import was executed), the total number of records in the file, and one of the following statuses:

  • Pending (while still processing)
  • Awaiting User Action (for one or more employee matches)
  • Ignored (for data Cority does not process)
  • Exception
  • Completed

When viewing a log record, you can open individual import records in the ESR Record Details layout. For AST, ETD, and ETA record types you will only see the raw data imported. For PER records, if the status is Awaiting User Action there will be actions you can take. For example, if in the import file there is a record that has the same ESR Person ID as an existing record in GX2, one or more Possible Registration Matches will be shown and you must select which GX2 match is the correct one. These possible matches are identified using the Registration Matching Rules described in "Configuring the ESR Interface" above. The possible actions are:

  • Ignore – do nothing/ignore the import record
  • Match – choose a match and select Match
  • Search – if you do not see a match in the list provided, you can select one from the GX2 Employees list
  • Add New – create a new Employee record as a placeholder that will be auto-populated with the data sent for that ESR Person ID, using the employee number from the ESR file to prevent additional files being created in the future for the same employee. The import job status is set to Pending.

Exporting to NHS

Only records associated with "ESR employees", i.e. those previously created or updated by ESR Import, can be exported back to NHS. These are identified by the ESR Person ID that is attached to the GX2 employee record (this field may be made visible on a custom Job Position or Immunization layout but it is not necessary for the export to work). 

All Job Position and Immunization records include an Export to ESR checkbox. When changes are made to the fields on the record, a BR sets the Export to ESR flag to true on save. For an employee's Job Position (on their Demographics record) and Immunization records that are marked Export to ESR, each export will send any changes that have occurred, including for any deleted immunizations marked as such, and then clear the checkbox. This checkbox may be made visible on a custom layout but it is not necessary for the export to work; however, you may choose to add it if you want to allow a user to clear a selected checkbox to prevent that record from being exported. If the checkbox is manually selected on a record that is otherwise not "eligible" for export, the record will not be exported.

Export runs daily at 5 pm ET for each of the trusts set up (see "Configuring the ESR Interface" above). The interface logs the following record types:

  • Acknowledgements (ACK) – no processing, just acknowledging receipt of the export
  • Deleted Immunization (ETD) – processes, interacting with the Immunization module
  • Immunizations (ETA) – processes, interacting with the Immunization module
  • Occupational Health Assessments (OHA) – processes, interacting with the Demographics module (job position clearance fields)

The ESR Export Log will have one of the following statuses:

  • Pending (while still processing)
  • In Progress
  • Exception
  • Completed

The ESR Export Log contains raw data only; there are no user actions to be taken.
