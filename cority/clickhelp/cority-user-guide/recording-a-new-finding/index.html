Recording a New Finding

  1. To add a finding directly in a module record, retrieve the record and click the Findings and Actions tab, then click New.

    2. If you are viewing a Cloud’s list of findings (e.g. you clicked Findings & Actions in the Cloud menu such as “Corrective Actions” in the Environmental menu), click New in the list.

    You can create a finding and action from within an action plan (see Creating an Action Plan), or add an existing finding to an action plan (choose Actions»Add to Action Plan and select the plan).

  2. Change the Finding Date if necessary, enter the Finding Details, and select the Finding Type. Depending on the layout, you may also be able to record risk-related fields.

    3. If this is an Environmental finding, indicate if the Finding resulted from deviation. If yes, a new event will be created with the event report type of “Environmental Deviation” (see Tracking Deviations).

  3. Identify the Location of the finding, if relevant. If the finding was created from a module record, the demographics fields are taken from the parent record and are not editable unless you are using a custom layout that includes the Modify Finding Demographics checkbox.

  4. Identify the Action required (Details and Type), who it has been assigned to, and the due date. The Action Type may be populated automatically if the selected Finding Type is defined with Related Actions in the FindingType look-up table.

    5. Set the assignee and/or due date for multiple records at the same time: on the Findings list, select the records and choose Actions»Set Assignee/Due Date, then select the assignee and/or due date that will apply to all the selected records.

    If the Assigned to Group field was added to a custom layout, you can assign the action to a group or team of employees (defined in the GroupandTeam look-up table) instead of to an individual in the Assigned To field. If the Complete as Team checkbox was added to the layout and selected, a single action is created for the group/team. If the checkbox is not selected, an action is created for each employee in the group/team. 

    You may be able to assign the action to a combination of multiple employees and/or groups. 
    To facilitate this, an Administrator would need to enable the "Allow Assignment of Actions to Multiple Groups (Teams) and/or Assigned To" system setting, and in the applicable "Actions" or "Compliance Obligations" layout, select the Enable Multiple Values checkbox for the Assigned To and/or Assigned to Group fields.
    When business rule emails are sent for the assignment(s), all of the following individuals will be included:
    • AssignedTo - all employees specified
    • AssignedToGroup - all current members in all groups specified
    • GrouporTeamMembers - all current members in all groups and teams specified
    • VerifiedByEmployee - only the first selected (primary)
    With this functionality configured a single action is assigned to all assigned to and teams for each due date, and any of the associated individuals or team members can complete the action. The Complete as Team checkbox will be selected and non-editable. MAEN notifications are sent to all expected recipients. Without this functionality configured, each member of the Assigned To Group could have an action to complete.
    This functionality cannot be used with assignment of actions for Corrective Plans with Legal Requirements and Permits.  

    If necessary, select an Escalation profile (from the TaskEscalation look-up table), which will automatically send a notification according to the due date. You may need to add this field to your layout.

    See below for information about setting up recurring actions.

  1. Use the Documents tab to link an external file (e.g. an image) to a finding. Linking a file to a finding offers users easy access to the file (for more information, see Linking or Importing a Document).

  2. The Notes tab allows you to record additional information that does not fit elsewhere in the form. For more information, see Adding Notes to a Form.

  3. Click Save. You are prompted to send an email message notifying the person assigned to complete the action, or you can choose Actions»Email at a later time to send messages related to one or more finding. The email message includes a link to view their upcoming and overdue assigned actions in a standalone version of Cority (no menus, restricted functionality).

    4. Automatic email notifications and reminders may be sent for actions according to the MAEN settings, if enabled (see Working with MAEN Settings). You can override the default settings for individual actions (e.g. to include an alternate employee, different frequencies, etc.). To do this, clone the applicable “Action (w/ Notification)” layout and use this layout when adding the action; be sure to select the Override MAEN Settings checkbox to override the default notification settings. If this checkbox is not selected, the default MAEN settings for the Cloud’s action type will be used.
    These alternate layouts are included with Cority but marked as Inactive. They include a Notification section with all relevant MAEN fields. For more information, see Defining Form Layouts.

  4. To identify another action required for this finding, choose Actions»Add New Action to Finding. If you want to repeat the same action for this finding but assigned to a different person, choose Actions»Copy Action.

When the action is completed, enter the Date Completed and any Completion Comments. The person verifying the action can record the Verified Date and Verification Comments and the Action Rating (the effectiveness of the action).
Once a Date Completed is recorded on a Compliance Action, the record is locked and no further edits are possible; however, depending on your role permissions, you may be able to unlock the record (Actions»Unlock Record) to clear the Date Completed and edit the record.

Setting Up Recurring Actions

The recurring action functionality changed for actions set up in version 2024.3 or later. These will have an Initial Action Id populated. This field is not populated for any recurring actions created prior to 2043.3. Recurring actions set up prior to 2024.3, as well as those created from corrective action plans, continue to work as in the past but without the new functionality.

Creating Recurring Actions

  1. Select the Is Recurrent checkbox. Note that this checkbox cannot be selected until Assigned To and Due Date are entered. If you Assign to Group, Complete as Team must also be selected.
  2. You are prompted to complete the recurrence settings (frequency pattern, start date, and end method). Future actions are created based on the due date of the original action plus the frequency:
    • 2024.3 or later: Daily/Monthly recurrences are created for one year out plus 1, while Monthly/Yearly recurrences are created for five years out plus 1 (fewer will be created depending on End Method, i.e. if End after # of Occurrences or End Date were specified). The daily processing job will add another action to the end of the series as each subsequent action comes due, so that rolling time frame from the current date is maintained.
      If the end date is not known, we recommend using No End Date; these will continue to generate and must be manually ended when they no longer apply.
    • prior to 2024.3: If No End Date is selected, then 52 actions were created; if the actions need to continue, a new recurring action will need to be created.

To view existing recurrence settings, choose Actions»View Recurrence Settings.

To set up recurring compliance actions that have the next due date based on the previous completion date, use the Daily > Every <n> Day(s) recurrence pattern, select the Based Off Completion Date checkbox, and set the Due Date for the initial action to today or later. Here's what happens:

  • The initial action will be created but no future actions.
  • If an action is completed early (for example, the Completion Date is provided before the Due Date), the next action will be created and the due date will be the prior action’s Completion Date plus the number of days specified in ‘Every <N> days’.
  • If an action is not completed early (for example, there is no Completion Date populated and the Due Date is Today), then the next action will be created and the due date will be the prior action’s Due Date plus the number of days specified in ‘Every <N> days’.

Modifying Action Fields — Set Up in 2024.3 or Later:

See “Configuring Which Fields Should Be Copied to Future Actions” below for information on how these fields are stipulated.

  • Ensure you're on the correct action record with the right due date (i.e. the earliest incomplete action after which you want to change fields).
  • Modify action fields that need to be changed, then click Save. You will be asked if you want to apply the changes to future actions for fields flagged to copy (in the configuration screen; see below).
    • Click Yes to apply the changes.
      Note: Even if changes to some fields not set to copy are included, only the values of fields configured to copy will be applied to future instances.
    • Click No to apply the changes to only that action record.
  • Only changes made in the layout will trigger this behavior. If the Date Completed is populated on the action, you will not be prompted to update future instances.
  • If there are multiple action series related to the same finding, only the future actions of the one that the you are editing are changed or deleted.

For actions that were configured prior to 2024.3, to apply changes to future instances, you would need to end the recurrence, make the changes, and then reset up the recurrence. See the section below.

Note: You can modify the Assigned To for multiple actions in bulk: from the Findings & Actions view choose Actions»Set Assignee/Due Date (customers using "Allow Assignment of Actions to Multiple Groups (Teams) and/or Assigned To" cannot use this option).

Modifying or Ending Recurrence

  • Ensure you're on the correct action record with the right due date:
    • When ending a recurring action series, this should be the action with the Due Date that is the last time that needs to be completed.
    • When modifying a recurring action series, this should be the next action after the last one required for previous pattern.
  • To delete future actions, clear the Is Recurrent checkbox. You are prompted to confirm. Actions that are completed will not be deleted.
  • To modify the recurrence pattern: 
    • After clearing the Is Recurrent checkbox and future actions in that series are deleted, modify any of the action fields that need to be changed (e.g. action details, assigned to, due date, etc.).
    • Reselect the Is Recurrent checkbox and set-up the recurrence pattern.
    • Carefully review the recurrence settings because they will default to the original settings.  Especially be sure to update the Start Date to match the new Due Date.

Configuring Which Fields Should Be Copied to Future Actions

The administrator defines which action fields should or should not be copied over to future recurrences when changes are made.

  1. In the Administrator menu, choose the Recurring Actions Configuration. Note that this must be added to the Admin menu.
  2. All action fields are listed by their field name (not label name, which may vary or have been customized for a layout). Each is set to either Always Copy or Not Copy. This can be modified for many fields, e.g. those that do no thave additional coded logic associated.
  3. By default the configuration applies to all cloud solutions but can be modified for a specific solution. We recommend that you start with defining the default for all (Apply Configuration to All = Yes) and save the settings.
    Then change Apply Configuration to All = No and select the cloud you want to change settings for as required. Remember to save each configuration.

The Administrator Email(s) field is currently non-functional - in a future release this field will define where service logs are sent.

The administrator can also monitor the Recurring Actions Services Log to view entries when users create, modify or delete recurring actions, and to track daily process jobs that add new actions to the end of the action series.
