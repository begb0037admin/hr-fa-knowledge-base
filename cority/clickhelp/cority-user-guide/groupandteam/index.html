GroupandTeam

This table allows you to set up groups or teams of employees that can then be assigned to an action so that any member can complete the action. A group/team may be populated either manually by identifying the associated employees, or automatically based on the results of one or more linked queries defined in the Query Builder.

Because employees are listed on the Employees tab whether they were added manually or automatically, it is recommended that you manage your groups/teams using only one of the methods (manual or linked queries) to avoid confusion about how or why an employee was included.

Identifying Employees Manually

  1. Enter a Name for the team and optionally a Description.
  2. Identify which Cloud(s) the group/team is available in.
  3. On the Employees tab, identify the employees who are associated with the group/team. If you do not specify a Start Date that they became part of the team, the system will use today's date.

Using Linked Queries

A linked query is a way to manage lists of people for groups and teams based on fields present in the Cority platform. An example of this would be creating a list of employees who work in a specific department. If you use linked queries, you can have a list that updates automatically when employee HR data changes. Another example might be to create a group of people who have completed the training and assessment. You could create this group using a linked query and it would update automatically as employees complete the training.

Queries must either be created by you (in the Query Builder), or have been published, or are marked as a subquery; and must have "Employee Number" for the first column.
It is best practice to include a criterion in any linked query that excludes terminated employees, so that those employees are ended in the group/team.

  1. Enter a Name for the team and optionally a Description.
  2. Identify which Cloud(s) the group/team is available in.
  3. On the Linked Queries tab, click New and select the query. You can include multiple queries.

To view the details of a query, select it and choose Actions»Open Query.

The Group and Team linked queries update is run nightly before the business rule for assigning inspections. Any changes to the employee constituents in a group/team are not retroactive. For example, if an inspection is assigned to an employee, and the employee becomes end-dated in the group, the inspection will remain assigned to the employee. Records assigned to a group/team are not updated retroactively when the employees for the group/team change; only future assignments will reflect the change.  

If an employee appears in any query linked to the group/team, even if the employee had previously been in the group/team and end-dated, the employee will be added to the group/team.
If the employee is already active in the group/team, no changes are made. If the employee had previously been in the group/team and end-dated, their original record will be updated (End Date removed, Start Date value updated) .

Removing Employees from a Group/Team

If an employee was manually added to the Employee tab in error, select the record and click Delete. However, if an employee who was added manually should no longer be part of the group/team, you should make them inactive instead, to preserve the audit history: in this case, open the employee record from the list and enter an End Date.

An employee who was added via a query will be end-dated if they no longer appear in any query linked to the group/team. The employee is removed from the Employees list and their End Date is updated accordingly.

Only employees who were added by linked query will be removed by linked query; employees who were added manually that get removed from a group/team's linked queries will not be removed from the group/team or end-dated.
