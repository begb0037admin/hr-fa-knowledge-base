CCC-3967Occupational Health - Employee CareN/A

For an appointment entry that has one or more GDDLOFB fields populated, regardless of whether or not the Employee field is populated, if recurrence is configured, the same GDDLOFB values will be applied to all of the future instances created for the recurrence pattern.

For an appointment entry that has one or more GDDLOFB fields populated, regardless of whether or not the Employee field is populated, if the Copy action is executed, the GDDLOFB value(s) will not be applied to the new record (the copy).

  • If the user selects an employee on the new record, the GDDLOFB will populate automatically based on that selection.

CCC-1406 and 4432Occupational Health - Medical MonitoringN/A

For an employee, you can now add more than one immunization at a time.

To support this, the default 'Immunizations' list view now has the new 'Add Multiple Immunizations' action. Note: For immunizations, anywhere the 'Add Multiples' action is displayed, the label has been changed to 'Add Multiple Immunizations'.

When the new action is executed, a dialog box will open with the following fields:

  • Employee (required) - pre-populated with the global employee, if one is specified; otherwise, a picklist to the 'Employees' look-up table
  • Immunization/Test - a picklist, with the multi-select feature, to the 'Immunization Code' look-up table
  • Dose Date - a date field that defaults to 'Today'

The 'Save' button will create new Immunization record(s) based on the selection(s).

Upon 'Save', for each new Immunization record, any default value associated with the immunization code (for example, for Immunization Route, Dose, Type, Recall, etc.) will be auto-populated on the new record(s), and the GDDLOFB of the employee will be auto-populated as well.

The 'Cancel' button will close the dialog box.

The new 'Add Multiple Immunizations' action is available to any user whose role has access to the 'Immunization' module.

To prohibit the action from a user or group of users, an Administrator can simply prohibit the role from the 'immunization.addmultipleImmunizations' security action.

This new feature works as expected in conjunction with (supports and is supported by) the multi-job functionality.

CCC-3613Platform - InterfacesN/A

The RESTful API has a new 'exact match' parameter:  

  • &exactmatch=true

or

  • &exactmatch=false (if not provided, this is implied by default)

When the setting is true, for the text provided, only exact matches will be returned (for example, providing benzene will return only items with just benzene as the phrase/name/string). When the setting is false, for the text provided, wildcards before and after the text will be implied (for example, providing benzene will return any items with benzene in the phrase/name/string).
