CCC-2587: GX2 now has a bidirectional interface with the NHS ESR for managing Electronic Staff Records (ESRs)

Opt-In

  • To support this, there is a new ESR Config module in the Administrator cloud. This module can be granted to or prohibited from a user’s role.
  • For new users whose role has access, the module will be added automatically. For existing users, the Administrator will have to add it through menu configuration.
  • This module is used to configure how the interface will import (read and process) and export ESR data.
  • An Electronic Staff Record (ESR) is a combination of HR and Immunization data.
  • Note: The demographics information ESR sends to GX2 is not as extensive as the information our HR Integration Utility can import.

Importing

  • When importing from ESR:
    • For a new employee, a new Employee Demographics record will get created with the Job Position tab populated correctly, and any immunizations will be sent and populated/updated accordingly.
    • For an existing employee, his or her Employee Demographics record will get updated, if necessary, and any new immunizations will be sent and populated/updated accordingly.
  • The ESR Config screen provides:
    • ‘Enable ESR Import’ and 'Enable ESR Export' check boxes for enabling or disabling the functionality
    • An ‘FTP Setup’ section for configuring the FTP settings
    • A ‘Registration Matching Rules’ section for configuring the matching criteria rules that will be followed when an employee match is encountered
  • There is also an ‘ESR Import Log’ now provided in the Administrator cloud. This will log all interactions.
    • Each log entry can be opened in the ‘ESR Record Details’ (ML-003670) layout, which is hardcoded (cannot be cloned and/or customized).
    • An import log entry will provide the name of file imported, the created date (when the import was executed), the total number of records in the file, and have one of the following Statuses: Pending (while still processing), Awaiting User Action (for one or more employee matches), Ignored (for items we don’t process), Exception, or Completed
  • The interface recognizes and logs the following:
    • Personal Details (PER) - processes, interacting with Employee table
    • Assignment Details (AST) – processes, interacting with Job Position(s)
    • Deleted Immunization (ETD) – processes, interacting with the Immunization module
    • Immunizations (ETA) – processes, interacting with the Immunization module
    • Not Supported – receives, but does not process
    • Personal Details (PER) – processes, interacting with the Demographics module
  • When opened in the ‘ESR Record Details’ layout, all except a PER provide just the raw data. For a PER, there might be actions the user can take.
    • For example, if in the import file there is a record that has the same ‘ESR Person ID’ as an existing record in GX2, one or more matches will be shown in the ‘ESR Record Details’ layout’s ‘Possible Registration Matches’ section at the bottom. The section is expandible/collapsible. In that case, the user is required to make the call on which GX2 match is the correct one.
    • The options (possible actions) for the user are:
      • Ignore – choose a match or matches and select Ignore
      • Match – choose a match and select Match
      • Search – if the user does not see a match in the list of matches provided, he or she can select one from the GX2 Employees list
      • Add New – if none of the above options apply, the user can then create a new Employee record that will be auto-populated with the data sent for that ‘ESR Person ID’
  • As well, the Organizational Tree in the Administrator cloud has a new ‘Trust Identifier’ field. When you add this field to a node with TreeMaster Type = Org, then populate that node with the required values including your trust identifier code, that node will then serve as your organization’s trust identifier when the ESR interface is processing data. It is a one-to-one relationship, so the code used for the Trust Identifier value can only be used on one node in the Organizational Tree.
    • Note: The trust identifier supporting the ESR data must be configured against the Organizational Tree (for example, TreeMaster Type= Org). If the trust identifier is populated against any other trees, the ESR interface will ignores it, and because its information is necessary for inserting a new or identifying an existing employee within GX2, the import will fail.
    • If a trust identifier code for an incoming ESR is missing in GX2, there is error messaging to handle that, and the record will be skipped (not processed).
  • For more information on working with the Organizational Tree, see the GX2 User Guide.
  • The new ‘Assignment Number’ field (read-only) has been added to the EmployeeJobPosition table and can be added to custom ‘Job Position’ layouts. The field will display the assignment number sent by ESR for Assignment Detail (AST) records when they are processed. Together, the Assignment Number and Position construct the unique record sent by ESR.
  • Also, the new Results tab (sublist) can be added to custom versions of the Immunization Code layout. This tab can be used to link/associate specific result options (the applicable ones only) to each immunization code. When this is configured, and on an Immunization record the user specifies an immunization code in the ‘Immunization Test’ field, only the applicable result options will be available in the ‘Immunization Result’ field picklist.
    • If this new Results tab is not used, then the ‘Immunization Result’ field picklist will continue to display every option from the Results look-up table.
  • In addition, the ‘Work Status’ look-up table layout now provides the new ‘Work Status Type’ field. When a new employee with job data is created or when an existing employee’s job data gets updated (manually or while data sent from ESR is being processing) and the value of ‘Work Status Type’ is populated on the ‘Work Status’ look-up table records, one of the work statuses (Active, Applicant, Applicant-Closed, Pre-Placement, or Removed) will be assigned to the employee's job position record based on specific logic required by ESR. The value of the ‘Work Status Type’ field lets GX2 know which status to populate on the ‘Employee Job Position’ record. Note: There must be a one-to-one relationship between each ‘Work Status’ look-up table record and its ‘Work Status Type’ value.
  • Lastly, the Employees list view has a new ‘Employee Merge’ action. This is a shortcut to the Employee Global Merge Utility.
    • The action opens a dialog box with a ‘Change From’ field, a ‘Change To’ field, and ‘Merge Employee Records’ and ‘Cancel’ buttons.
    • The Change From’ and Change To’ fields are picklists to the GX2 Employees list.
    • For customers not using ESR, this will function in the same way as the Employee Global Merge Utility. For customers using ESR, this will also merge the employee’s ESR-specific job position data. This particular feature can be turned on/off for each customer upon request.
    • For all customers, this handles ‘Additional Job Position’ data properly as well (for example, if a recruiter submits information at the same time other changes are made, and this has resulted in an additional record of similar information).
    • The employee.merge security action must be granted to the user’s role for the user to see this new ‘Employee Merge’ action in the Employees list view. 

Exporting

  • For exporting to ESR:
    • The 'Enable ESR Export' check box on the ESR Config screen must be selected.
    • Export is scheduled to, and will, run daily at 5 pm GMT for each of the trusts set up (see above in 'Importing').
      • A new 'Export to ESR' check box has been added to all 'Job Position' and 'Immunization' layouts. By default, the check box is selected. For the employee's 'Job Position' (on his or her Demographics record) and 'Immunization' records that are marked 'Export to ESR', each export will send any changes that have occurred, including for any deleted immunizations marked as such.
      • Towards the bottom of the ESR Config screen, a check box 'Require consent to be obtained for exporting immunization records to ESR' is provided. If checked, each individual immunization record will need to have the 'Consent Obtained to Export to ESR' check box selected to be included in any updates exported to ESR.
      • An 'ESR Immunization Map' look-up table with default ESR immunization types has been added.
      • The 'Immunization Codes' look-up table layout now provides the two new 'ESR Immunization Type' and 'Primary Immunization for ESR' fields. The 'ESR Immunization Type' field lets you map the 'Immunization Code' to its corresponding ESR immunization code. You can link multiple immunization codes to the same ESR immunization code and specify which is the primary immunization code using the new ‘Primary Immunization for ESR’ check box. Then, when new immunizations are created from ESR, they will be for immunization codes with the primary check box selected.
      • To custom versions of the 'Employee Job Position' layout, a new Notes field, four new date/time UDFs, six new check box UDFs, and six new look-up table UDFs (with accompanying, similarly named look-up tables) can now be added.
      • An 'ESR Export Log', with similar functionality to the 'ESR Import Log' (see above in 'Importing'), is provided in the Administrator cloud. After each ESR export, the 'ESR Export Log' will get updated, and each successful entry will provide an informative acknowledgement file with details about the export. Note: The export log does not record PER or AST entries, but does record OHA (Occupational Health Assessment) entries.
        • An export log entry will have one of the following Statuses: Pending (while still processing), In Progress, Exception, or Completed
    • The following new business rules have been created to support the ESR export functionality: BR-100588, BR-100589, BR-100591, BR-100592, and BR-100593. The business rules identify records that are ready to be exported.
