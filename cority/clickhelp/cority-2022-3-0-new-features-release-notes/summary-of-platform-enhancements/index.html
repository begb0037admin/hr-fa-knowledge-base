Summary of Platform Enhancements

The table below lists the smaller design improvements we have made to the GX2 Platform. The items are organized by component and the components are arranged in alphabetical order. Descriptions of any larger features follow the table.

ItemComponent(s)Description
CCC-8978 and 9876Administrator

In the Administrator > Roles module, there is a new 'Pinned Views' tab. This enables an administrator to assign pinned views to a role. When a user opens a list view for which his or her role has a pinned view, that view will be displayed/used. Note: For each GX2 list view, only one pinned view can be added per role.

When an administrator has pinned a view for a user's role, on the list view the Pin button will be disabled and a tooltip will notify the user that a view has been pinned.

 

CCC-9177Administrator

A table added to a letter template will now display properly when exported to PDF or emailed.

 

CCC-5570Administrator

The 'Create Record' business rule action (BRA) can now be used to:

  • Create users and assign each multiple roles successfully
  • Create users and assign each a password that can be used to log in immediately after the user is created

Any assigned password will be treated as a masked value on the business rule screen.

 

CCC-2008Administrator

When the status of a workflow step is updated by a business rule action (BRA), the step's chevron at the top of the screen will now update accordingly.

 

CCC-9708End-User

Starting with the 2022.3.0 release, on all Test and Production environments the Cority GX2 Platform will be upgraded automatically to the newest user interface theme, Clarity.

Users of other themes who log into 2022.3.0 or later will be presented with the Clarity theme. All other themes will be deprecated.

Clarity retains all existing functionality and improves the overall user experience.

Here are some of its other benefits:

  • A modern, streamlined look and feel, with better use of space
  • Improved navigation
  • New features each release

Also, this upgrade will help us improve our development and quality assurance processes, and should reduce bugs and support time.

 

CCC-7185End-User

The character limit of the Body field has been increased to 250,000 for the following:

  • Medical Letters
  • Case Letters
  • Quality Letters
  • Safety Letters
  • Ergonomics Letters
  • Environmental Letters
  • I.H. Letters

 

CCC-6663End-User

The text editor has been upgraded to improve security.

 

CCC-122End-User

The Layout Editor has a new 'Flex Fields Display Mode' field with a Subsection option. By default, the option is not selected.

If selected and the layout has a Flex Fields tab, that tab will be displayed as a subsection at the bottom of the layout's main form.

The subsection will use the Flex Fields questionnaire's description for its heading.

The layout's Save button will save any changes made to the Flex Fields subsection.

For more information on working with Flex Fields, see the Cority GX2 User Guide.

 

CCC-10018Infrastructure

You can now export configurations from your environment(s) and import configurations into your environment(s) by using the 'Export <Module> Configurations' and 'Import <Module> Configurations' actions within the following modules:

  • Look-up Tables
  • Standard Views
  • Translations
  • Roles
  • Users
  • User Menu Configurations
  • Workflows

 

CCC-9008Infrastructure

For additional security, when the 'GX2 Authentication Method' system setting is set to 'Mixed Mode' and the 'Enforce 2-Factor Authentication' system setting is set to either 'Every Login' or 'Every 30 days', userpass users will now be required to use two-factor authentication accordingly.

Note: SSO Users authenticating when 'Mixed Mode' is on will not be affected. They can continue to log in with SSO.

If an administrator changes the 'GX2 Authentication Method' setting from 'Mixed Mode' to 'Username/Password' or from 'Username/Password' to 'Mixed Mode', the 'Enforce 2-Factor Authentication' setting will remain enabled (if already enabled).

If an administrator changes the 'GX2 Authentication Method' setting from 'Mixed Mode' to an authentication method other than 'Username/Password', the 'Enforce 2-Factor Authentication Method' setting will become read-only with its value disabled. Even if an administrator changes the 'GX2 Authentication Method' setting back to 'Username/Password' or 'Mixed Mode', the 'Enforce 2-Factor Authentication Method' setting value will remain disabled. The administrator will have to manually re-set the value to 'Every Login' or 'Every 30 Days' if that's what is required.

 

CCC-7307Infrastructure

While the user resizes a dialog box, or if the user performs one of the following searches, the GX2 screen will now dim to indicate that the engine is temporarily busy in the background:

  • On a Clinic Visit list view, searching by Clinic Visit ID
  • On a Case list view, searching by Case ID
  • In Administrator tools, under Roles, searching for an action to grant/add
  • In Administrator tools, under Event Logs, searching for an error message by reference ID
  • For BRA merge fields, searching by location

 

CCC-6386Infrastructure

For the older Portal 'My Account' screen, the 'Allow auto-complete password on login' system setting is now not selected in all SAAS environments. Auto-completion for such fields is a security vulnerability.

 

CCC-4990Infrastructure

The GX2 platform's host header has been made more secure to help ensure it cannot be altered to include improper and/or potentially harmful data (for example, a "poisoned" password reset link).

 

CCC-4989Infrastructure

Our Content Security Policy has been updated with the CSP directives it was missing.

 

CCC-4536Infrastructure

Cority GX2 no longer supports Windows Server 2008 or earlier.

 

CCC-8613Interfaces

We have changed the format of the output from the Query Builder RESTful API endpoint to be more user-friendly. For example, it can now be more readily used with reporting tools such as Microsoft Power BI.

 

CCC-8515Interfaces

All Cority RESTful API endpoints that support GET, POST, and PUT requests now also support DELETE requests.

The user can delete a single record by specifying the record's ID (for example, coritysite/api/employee/123).

A user can only delete using the RESTful API if his or her role has:

  • The required site security
  • The APIdelete security action for the endpoint

 

CCC-7326Interfaces

For the RESTful API, the 'Access Token' field in the API Token look-up table will now accept a maximum of 1100 characters. Note: The tokens are generated by the API/token endpoint using the refresh token for authentication.
