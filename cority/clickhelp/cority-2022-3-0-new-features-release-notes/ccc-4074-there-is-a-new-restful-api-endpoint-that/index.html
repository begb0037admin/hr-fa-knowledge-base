CCC-4074: There is a new RESTful API endpoint that for a POST call will accept all MGIP parameters

Opt-In

  • The endpoint is named '<<TableName>>/Import'.
  • The parameters are provided in an OPTIONS envelope, and all MGIP options are available:
    • table - The user must specify the data table or look-up table into which the data will be imported. Only one table can be specified (imported into) per call.
    • updateExistingRecords - If this is selected and the table key already exists, applicable data in the table will be overwritten with the data provided in the POST call.               
    • insertBaseTables - If a look-up table code does not exist, the table will be created first, then assigned to the included data record(s).
    • alwaysInsertAsNewRecord - This is only provided for specific tables (for example, Clinic Visit), therefore can only be used with those tables.
    • insertNewRecordWhenMultipleRecordsFound - This is only provided for specific tables (for example, Clinic Visit), therefore can only be used with those tables.
    • dateFormat - This is for specifying the date format that will be used where applicable.
    • importTree - When importing into the TreeMaster table, this is for specifying the correct tree.
    • bypassBusinessRules - This is only provided for specific tables (for example, TreeMaster), therefore can only be used with those tables.
  • The data records are provided in a RECORDS envelope.
  • The import format will be implied based on the first record included in the call to be added to / updated within the table (for example, EmployeeNumber,EmployeeType).
  • The user can provide as many records as he or she needs added/updated.
  • The response will include the following information:
    • import uid - This will always be null. It is set after the RESTful API response is returned to the user.
    • processing complete - This will always be true unless, for a special case, Cority turns on QueuedImports.
    • errors encountered - This informs the user how many errors occurred and the type of each error.
    • import type - This will always be 0.
    • import type string - This will always be GenericImport.
    • processStatusLogId - This provides the user with the log ID for the log record that will be located in Administrator > Process Status and Log.
    • message - This informs the user how many records were added/updated/rejected.
    • recordsTotal - This informs the user how many records in total the system attempted to import.
    • recordsAdded - This informs the user how many records were added.
    • recordsUpdated - This informs the user how many records were updated.
    • recordsDeleted - This informs the user how many records were deleted.
    • recordsRejected - This informs the user how many records were rejected.
    • recordsUnprocessed - This informs the user how many records were unprocessed.
    • recordsWarning - This informs the user how many records generated warnings.
  • To use this new endpoint:
    • The user's User record must have 'MGIP User' selected.
    • The user's role must be granted the security action for importing into the specified table (for example, to import into the Clinic Visit data table, the user's role must be granted the clinicvisit.apiwrite security action).
    • The user's role must be granted the mgip.import security action.
    • Note: Ensure this new endpoint is excluded from the API Daily Threshold Limit.
  • The following is an example:

POST
{

    "options": {

        "updateExistingRecords": "TRUE"

    },

    "records": [{

        "employeeNumber": "CCC4074",

        "firstname": "firstname4074",

        "lastname": "lastname4074"

    }]

}

RESPONSE
{

  "importUid": null,

  "processingComplete": true,

  "errorsEncountered": false,

  "importType": 0,

  "importTypeString": "GenericImport",

  "processStatusLogId": 9252,

  "message": "0 record(s) added; 0 record(s) rejected; 1 record(s) updated. 1 record(s) added to the log file.",

  "recordsTotal": 1,

  "recordsAdded": 0,

  "recordsUpdated": 1,

  "recordsDeleted": 0,

  "recordsRejected": 0,

  "recordsUnprocessed": 0,

  "recordsWarning": 0

}
