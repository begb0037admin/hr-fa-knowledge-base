Summary of Safety Enhancements

The table below lists the smaller design improvements we have made in the Safety Cloud. The items are organized by component and the components are arranged in alphabetical order.

ItemComponent(s)Description
CCC-6798 and 6600Safety – Contractors

For list views in the Safety 'Contractors' module, security has been enhanced so that users can now only see records to which they have access.

 

CCC-8018 and 7270Safety – Incident

The North Dakota WSI 'First Report of Injury' form has been updated to the latest version.

 

CCC-8071 and 6115 Safety – Incident

The WCB - Alberta C040 form has been updated to latest version, and a value must now be included for each mandatory field.

 

CCC-6169Safety – Incident

There is a new IncidentWhyTree.AllowUnmarkAsRootCause security action. When granted to a role, any user with that role will be able to unmark root causes as favorites and/or remove them entirely from a Why Tree analysis even if the role does not have the security permission to delete root causes.

Note: The user's role must also have write permission for the incident investigation itself.

For information on working with safety incident investigations or security configuration, see the GX2 User Guide.

 

CCC-4484Safety – Incident

An incident investigator can now edit the 'Driver/Employee Involved' field value on the Safety MVA (ML-001410) and Environmental MVA (ML-001411) layouts (and custom versions of them) after the record has been saved.

To use this functionality, the user's role must be granted the new safetymva/environmentalmva.editemployee security action.

Note: When the investigation has been locked using the Approved action, both the field and record will be locked as well.

 

CCC-5425Safety – Risk Assessment

For risk assessors, the Key Contact column can now be added to custom Risk Assessment list views. The column has the inline-add/edit feature for updating values.
