Summary of Platform Enhancements

The table below lists the smaller design improvements we have made within the GX2 Platform. The items are organized by component and the components are arranged in alphabetical order. Descriptions of larger features follow the table.

ItemComponent(s)Description
CCC-6684Administrator

There is a new display rule condition named 'Changed'.

This condition can only be used with the 'Message/Toast' action that will be implemented in the GX2 2022.3.0 release. It will not work in cases where the page is refreshed (for example, when the picklist value alters the display).

The following is a typical use case: Incident Category is equal to Injury/Illness and the Incident Category changes ('Changed' condition). As a result, the display rule action configured will be performed automatically.

Note: For display rules, a save is not required. Each display rule is evaluated immediately.

For more information on working with display rules, see the GX2 User Guide.

 

CCC-6565Administrator

There are new display rule conditions named 'Is Null', 'Is Not Null', and 'Is Not Equal'.

For example: The Incident Category field value is null. As a result, the display rule action configured will be performed automatically.

For display rules, a save is not required. Each display rule is evaluated immediately.

For more information on working with display rules, see the GX2 User Guide.

 

CCC-6540Administrator

The Employees list view has a new ‘Employee Merge’ action.

This is a shortcut to the Employee Global Merge Utility.

  • The action opens a dialog box with a ‘Change From’ field, a ‘Change To’ field, and  ‘Merge Employee Records’ and ‘Cancel’ buttons.
  • The Change From’ and Change To’ fields are picklists to the GX2 Employees list.
  • This processes ‘Additional Job Position’ data as well (for example, if a recruiter submits information at the same time other changes are made, and this has resulted in an additional record of similar information).
  • The employee.merge security action must be granted to the user’s role for the user to see this new ‘Employee Merge’ action in the Employees list view.

 

CCC-4444Administrator

For a field that supports multiple values, the corresponding column when added to a custom list view can now be configured to render those multiple values.

To support this, when creating a custom list view, for such columns there is a new ‘Enable Multiple Values’ check box.

Note: When using this feature on a custom list view, to maintain rendering performance we recommend you limit the maximum rows per page to 50.

Also, for filtering such a column, multiple values can now be specified in the column’s search field. The filtering will use the ‘or’ operator (for example, if you specify three values in the search field, the column will filter to records with any of Value 1, Value 2, or Value 3 in the field).

Field values that are read-only will of course be read-only in the corresponding column as well.

 

CCC-4262Administrator

The Display Rules module has a new Require Field action

The Display Rules module is used for creating rules that dictate what should happen to a layout or set of layouts as a record moves through a workflow.

A display rule is similar to a business rule, except display rules trigger immediately on values changing, as opposed to triggering on Save.

The Display Rules module is included with the Administrator set of tools.

For more information on the module, see the release note for CCC-227 in the Cority 2021.3.0 New Features Release Notes document.

For a display rule with a Require Field action, the specified field will be required on the workflow step’s layout if the step meets the rule’s conditions and not required if the step does not meet the conditions.

If two different display rules fire at the same time, one making field A required and another making field A not required:

  • If the two rules’ priorities differ, the rule with the lower priority value will take precedent.
  • If the two rules’ priorities are the same, the rule with the lower ID will take precedent.

If a display rule to make a field not required has fired, another that makes the field required cannot be created until the first is deleted, and vice versa.

Both workflow step configuration and display rules have the required and read-only options. These should not be configured in both for the same field. For a particular field, required and/or read-only should be configured in either the workflow step or a display rule, not both.

Only one of each display rule action type can be used per display rule.

  • For example, you can't add two Require Field actions to one display rule.

 

CCC-2312Administrator

In the 'Phrase Translations' module, new Core and Source columns are now available to be added to custom 'Phrase Translations' list views. For each phrase, the Core column will indicate whether or not the phrase is a core Cority phrase. If one is not a core Cority phrase, then it is user-created/entered. The Source column will indicate the type of phrase (Core - Layout Code, Core - Exception Message, User-Defined - Form Relabel, etc.). Note: These two new columns will only become populated when the Reset Phrases action is performed.

 

CCC-1562Administrator

In applicable logs, the character limit for Exception column entries has been increased from 2000 to 4000. That should enable administrators to view and copy the entire message.

 

CCC-1063Administrator

For release 2022.2.0 or newer, self-hosted clients must upgrade to SQL Server 2016 or newer. Older versions of SQL Server are no longer supported.

 

CCC-7228End-User

For the pre-employment, recruitment process, if the user clones a questionnaire that has the Auto-Clearance tab (sublist) configured, the clone will also have the configured Auto-Clearance tab. Also, on the Auto-Clearance tab of the clone, the user will be able to add, modify, and delete records.

 

CCC-7125End-User

If a recruiter is using a custom Employee (Applicant) Demographics layout, when he or she clicks 'Save and Close', if any of the following fields are on that layout, their value(s) will now be saved into the Employee Job Position data table.

  • Medical Insurance Number
  • Work Status
  • Employee Type
  • Job Position Group
  • Job Type
  • Supervisor

 

CCC-6383End-User

The SAML Key look-up table is now an available entity in business rules. This will enable a SAML 2.0 SSO authentication user (configured by the 'Authentication Method' system setting) to create a BR with BRA that will send an email 30 days (for example) prior to the 'Valid To' date of a SAML Key look-up table entry, which will remind the user his or her keys for SAML 2.0 SSO authentication are about to expire and to schedule time to update them.

 

CCC-2754Security

To improve security, best practices for protecting credentials stored in locations such as configuration and properties files are now strictly followed.

 

CCC-7276Security

To improve security, the Lodash JavaScript utility library has been upgraded to version 4.17.21.

 

CCC-6665Security

To eliminate known vulnerabilities that could compromise the security of the system, patches have been applied to both the Microsoft .NET Framework and Microsoft ASP.NET.

 

CCC-6429Security

In GX2, the insufficient 3DES encryption algorithm has been replaced with the more secure AES encryption algorithm.

 

CCC-6294Interfaces

For importing test results, a new version of the HL7v23 standard (labelled HL7v23_2) is now supported in the Clinical Testing module. This will map data accurately to the existing 'Results Date' field and to the new 'Specimen Received By Lab Date' field.

 

The new 'Specimen Received By Lab Date' field must first be added to a custom version of the ML-000278 layout. It can also be added as a column to custom versions of applicable list views.

 

CCC-5263Interfaces

The new RESTful API CorityURL/api/refreshtoken POST endpoint will enable a user to obtain his or her refresh token using the RESTful API, without having to log into GX2 to get it.

The username and password must be provided in the body of the POST request.

If successful, the GX2 platform will create a new refresh token, add it to the user, and return it in the RESTful API response.

This is the same as Administrator > Users > Select User > Tokens Tab > Actions > Generate New Refresh Token, within the platform.

The token, refresh date and time, and expiry date and time will be returned.

The refresh token returned can be used in a token call to receive an access token.

This will only work for the following scenarios:

  • For all users if GX2 Authentication Method = Username/Password
  • For all users if GX2 Authentication Method = SSO SAML 2.0 / SSO Token
    • Note: The password from the Cority User Profile must be used, not the Client's IDP password
  • For users that have the Allow Mixed Mode Authentication system setting selected, if GX2 authentication method is Mixed Mode

For all users if GX2 Authentication Method = LDAP, in these scenarios, users should receive the same error in their API response:

  • Expired
  • Locked Out
  • Inactive
  • Mixed Mode Authentication is ON, but user does not have ‘allow mixed mode’ = true in their user profile
  • Username/Password Incorrect

 

CCC-5113Interfaces

A RESTful API GET request will now return the following additional information, regardless of whether or not the user provides the &includeTotalCount parameter:

  • totalCount - the total count of the dataset for what is being queried
  • pageSize - the current page size set in the URL as a parameter (maximum, 100)
  • pageIndex - the current page index set in the URL as a parameter
  • startAt - the number of the record that starts the dataset being returned

For example, if you provide pageSize=100 and pageIndex=2, the returned startAt will be 101.

 

CCC-5085Interfaces

The RESTful API has a new 'querybuilder' GET endpoint that will return the results of a configured Query Builder report.

In the GET request, the ID for the report must be specified (for example, corityURL/api/querybuilder/123).

To use this new GET endpoint, the API user's role must be granted the new querybuilder.apiread security action.

Also, the user must have access to the report being queried (that is, module and site security are respected).

If the user is querying a report for which he or she is not the owner, the report must first be published.

The report will be returned as a CSV file within a JSON envelope.

The report will use PageSize and PageIndex, as other GET calls do.

Only a maximum of 100 rows will be returned per page, even if the user specifies more than 100 rows.

By default, values for all fields specified in the Query Builder report will be returned. The values will be provided in the body.

The existing includeTotalCount parameter can be used to query how many records in total there are in the results.
