CCC-1430: The employee contacts functionality has been enhanced

  • A new 'Contacts' tab (sublist) can now be added to custom versions of the 'Employee Demographics' layout.
    • The sublist has the standard buttons and an Actions menu with the 'Export to Excel' and 'Show Record History' options.
    • The sublist corresponds directly to the new DT_EmployeeContacts data table, in which contacts are stored, per employee, by Employee ID.
    • The sublist has a default 'All Contacts' list view with the following columns:
      • Contact Name
      • Contact Type
      • Email Address
    • The columns are sorted alphabetically by 'Contact Name'.
    • The list view has the Create/Clone view options.
  • For creating new records or opening existing records, the sublist has the new default 'Employee Contact' layout.
    • The layout has the same functionality as the existing 'Witness/Contact' (ML-001329) layout.
    • On the layout, in addition to providing a contact name by selecting from the Contacts picklist (the LU_GLB_WitnessContact look-up table), a contact name can be entered using free text. A record with a contact name entered using free text will be saved as a contact with the 'Employee Demographics' record, but will not be added to the new DT_EmployeeContacts data table. A record with a contact name provided by selecting from the Contacts picklist will be added to the DT_EmployeeContacts data table.
  • Important: We recommend as best practice that you keep the 'Witness Contacts' look-up table up to date (as your single source of contacts), because contact updates only go in one direction (from that look-up table to the 'Employee Contacts' data table). The values for a contact in the 'Witness Contacts' look-up table will always override the values for the contact in the data table. For example: If a contact in the 'Employee Contacts' data table is updated with an email address that is different from the one for the equivalent entry in the 'Witness Contacts' look-up table and then the look-up table entry gets updated to change just the phone number, all values (including the email address) in the updated look-up table entry will override those for the 'Employee Contacts' data table contact, not just the phone number. If you update a contact's information by updating through the 'Employee Contacts' data table, the corresponding entry in the 'Witness Contacts' look-up table will not get updated at all.
  • The new 'Employee Contacts' data table can be reported on using Query Builder / Report Writer and used in business rules.
  • To help ensure the 'Employee Contacts' data table is kept up to date (for example, if a value in the 'Witness Contacts' look-up table that is used in the 'Employee Contacts' data table is updated, the corresponding value in the 'Employee Contacts' data table gets updated automatically), the new BR-100550 business rule (BR) and accompanying BRA-100551 business rule action (BRA) have been created:
    • Both are active out of the box, trigger on applicable updates to the 'Witness Contacts' look-up table entity, and update the corresponding contact(s) in the 'Employee Contacts' data table.
    • BRA-100551 is named CopyToEmployeeContact.
  • The default 'Contacts' picklist has a new 'Contact Type' column.
    • If the 'Contact Type' field is populated for one or more Contact records, the new column can be used to filter the contacts by contact type (for example, when sending letters to contacts).
    • The 'Contact Type' field can be used for configuring criteria when creating custom versions of the picklist view.
  • Across the Cority platform, where applicable, you can now send letters to a list of contacts stored in the 'Witness Contacts' look-up table and to additional ad-hoc recipients.
    • Note: Cority list views (both out-of-the-box and custom) currently do not support multi-select fields. For that reason, we recommend you refrain from adding either of the 'Send Employee Contacts' or 'CC Employee Contacts' columns to your custom Letters list views. Either will generate an error breaking the view. We will add support for multi-select fields on list views in an upcoming release.
  • For all Letter layouts, the 'Employee Contacts' option has been added by default to the 'Send Letter' drop-down field.
    • That option opens the 'Employee Contacts' picklist to the 'Contacts with Emails' list view, which only displays the contacts that have email addresses.
    • After the user selects one or more contacts, their email addresses are displayed in the 'Send Letter' field.
    • The existing Letter functionality (enable/disable dependencies) for the 'To' and 'CC' fields is retained.
    • By design, the Fax functionality is not included with this feature.
    • Any values configured prior to the introduction of this feature will continue to work as expected.
  • By default, the new 'Employee Contacts' option has been added on the following layouts:
    • Quality Letter (ML-003444)
    • Medical Letter (ML-000187)
    • Case Management Letter (ML-000914)
    • Safety Letter (ML-000915)
    • IH Letter (ML-000916)
    • Environmental Letter (ML-001448)
    • Ergonomics Letter (ML-001449)
  • Note: By design, the 'Send Letter' drop-down field remains unavailable on both the Noise Monitoring - IH Survey Letter (ML-003462) and Monitoring - IH Survey Letter (ML-003463) layouts.
  • A new free-text field named 'Ad-hoc Email' has been by default to the following layouts:
    • Quality Letter (ML-003444)
    • Medical Letter (ML-000187)
    • Case Management Letter (ML-000914)
    • Safety Letter (ML-000915)
    • IH Letter (ML-000916)
    • Environmental Letter (ML-001448)
    • Ergonomics Letter (ML-001449)
  • The field will accept more than one email address, separated by comma or semicolon.
  • Any addresses added using the field will be populated in the 'To' field.
  • The 'Email Log' will continue to reflect any emails (of non-draft letters) sent through the Letters module.

Impact to Existing Users:

  • This functionality will help ensure each employee's address book is kept up to date.
  • A user recording contacts details can now filter his or her contacts by contact type, making it easier to quickly locate and select the appropriate contacts when, for example, emailing letters.
  • A user of the Letter functionality can now more easily send letters to a group of contacts (from the contacts look-up table and as ad-hoc recipients), so that he or she has more flexibility in sharing information.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required. For information on working with employee demographics, employee contacts, or letters, see the Cority User Guide.
