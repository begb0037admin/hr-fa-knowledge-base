CCC-2248: For Occupational Health, there is a new Medical Correspondence module

  • The module enables users to email a set of an employee's medical correspondence.
  • The module is not available by default. It must be added by an Administrator for each user through Menu Configuration.
  • Once added, the new 'Medical Correspondence' module will be accessible from the Occupational Health menu.
    • As long as the user has access to each individual source (see the list of supported sources below) through security configuration, he or she will be able to access the 'Medical Correspondence' module. The module does not get granted explicitly, because it is comprised of several independent components.
  • The module has the 'All Medical Correspondence' list view.
  • If a Global Employee is selected, the list view will be filtered by that employee.
  • The list view has the 'Email' and 'Export List to Excel' actions, and the Create/Clone View functionality.
  • By default, and for filtering, the list view has the following columns:
    • Employee - the employee to whom the record belongs
    • Created Date - the date the record was created (and the column by which the view is sorted when first opened)
    • Source (read-only) - the type/origin of the record (Medical Note, Case Note, Medical Document, Case Document, Medical Questionnaire, saved PDF Form, non-draft Medical Letter, non-draft Case Letter, or Email Log)
    • Summary (read-only) - a summary of the record, if provided (for a Case Document, for example, this will be the 'Document Type' description)
  • The following columns can be added to custom versions of the list view:
    • GDDLOFB - the GDDLOFB (both code and description) of the parent record (for example, of the Clinic Visit)
    • Source ID - the record's ID
    • Global Passport ID - the ID of the Global Passport record for the employee
  • A user can select one or more medical correspondence items from the view and execute the 'Email' action to email the items to specified recipients.
  • When the 'Email' action is selected, the 'Email' dialog box opens.
    • The dialog box is then used to provide 'To' and 'CC' recipients, a subject, and body content.
    • On the dialog box, when the user clicks Send, two emails are generated and sent:
      • The first email will have the subject and body provided on the 'Email' dialog box, and a password-protected zip file containing all of the selected medical correspondence items.
        • Output for Notes: A Clinic Visit / Case Progress report for the selected notes in a single file named MedicalNotes / CaseNotes
        • Output for Questionnaires: One PDF that includes all of the questionnaire responses, each separated by a report header
        • Output for Forms : An individual PDF file for each form, named the same as the form
        • Output for Letters: An individual PDF file for each letter, named using the letter code
        • Output for Documents: An individual file for each selected document in its original format
          • Note: If a document is a hyperlink (not an import file), it will not be included in the zip file
        • Output for Email Logs: One PDF for each log with file name EmailMessageId.PDF
        • Output for attachments in the Email Log: A separate file for each email attachment with part of the file name EmailAttachmentMessageId.pdf so that the Message ID field can be used to identify the email that goes with the attachment
      • The second email will provide each recipient with a system-generated password for accessing the content in the zip file sent in the first email.
        • The subject of the second email will be Password.
  • For medical correspondence Emails ('Email Log' records):
    • 'My Email Log' has been implemented to ensure the list is restricted to only those from the logged in user's email log.
    • Emails sent out from the 'Medical Correspondence' module are logged under the 'My Email Log' with 'Medical Correspondence' as the listed module.
    • The Passwords can be retrieved from the Email Log if they need to be re-shared with the recipient(s) of the email.
  • On the new 'All Medical Correspondence' list view, for a record (for example, a Case Note record), the user can click the employee's name to open the record in the appropriate, related layout. For example, when the user clicks the employee's name for a Medical 'Note' record, the 'Note' record will open in the layout that corresponds to where the note was created/generated.
    • Note: For a Form record, the PDF will either open in a new tab or be downloaded, depending on the browser's configuration.

Impact to Existing Users:

  • Occupational Health users now have a central location for easily viewing and assessing all of an employee's medical correspondence.
  • A practitioner can now email one or more of the medical correspondence items for an employee to specified recipients in an easy and efficient way.

Additional Configuration Considerations:

  • To experience all of the benefits of the module, the user's role will have to be granted access to all of the module's components.
  • Beyond what is described above, no additional configuration is required.
