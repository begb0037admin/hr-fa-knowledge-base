CCC-1727: A new system setting can ensure that duplicate child records are not created when an event is posted to an Incident record

  • The new setting is global, grouped under the Event Reporting module, and it is named 'Duplicate child records on posting an Event to an Incident'.
  • The setting is a check box. It is selected by default, therefore when an event is posted to an Incident record, the event's Findings & Actions, Questionnaire, and Document records are duplicated and posted to that Incident record.
  • When the setting is not selected, the event's Findings & Actions, Questionnaire, and Document records are not duplicated and posted to the Incident record. They remain with the Event Report record only.

Impact on Existing Users:

  • For all events that get posted to Incident records, an administrator can now control whether or not their child records get duplicated and posted to the Incident record.
  • If the new setting is not selected, Incident Investigators will not have to manage duplicate child records.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
