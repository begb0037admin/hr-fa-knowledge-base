CCC-1380: The Appointments module has been enhanced

Availability Finder

  • The module now has an 'Availability Finder' tab for locating the first available timeslot, or any open timeslot, for:
    • An individual user within a defined date range
    • A group of users within a defined date range
    • An individual or group of users for one or more specified activities
  • To enable the 'Availability Finder' tab, a new 'Display Availability Finder in the Appointments Module' system setting has been added.
    • The setting is a check box and is categorized under the Scheduling module.
    • By default, the check box is not selected.
    • The setting is global, but it can be changed by an Administrator to a user setting.
  • The 'Availability Finder' tab has an 'Availability' panel and a 'Finder' side bar.
    • The side bar is open by default, and is expandable and collapsible.
    • The side bar has the following settings:
      • Health Center (Required) - a picklist field for specifying the health center you want (by default, the health center specified in the user's 'Health Center' system setting is populated)
      • Date Range (Required) - two date fields for specifying a date range (by default, they are set to today's date and seven days from today's date)
        • The Date Range can be changed, but we recommend you keep it to something manageable (for example, a week in total).
      • Activities - a picklist for selecting one or more activities, if you want the availability displayed to be specific to certain activities
      • Scheduling Users - a list of active scheduling users (with check box for each) linked to the specified health center, for narrowing down the available timeslots to those of just certain users
        • Note: This is list is generated from the specified health center and is not synced in any way to the list of users selected for display in Appointments. The two work independently.
        • To keep the 'Availability' panel manageable, we recommend you select (narrow to) only the users you need.
  • On the 'Availability' panel, the days shown are arranged in order vertically. Each day is collapsed by default and can be expanded.
  • If you select a user and he or she does not have any available time, that user will not display at all in the 'Availability' panel.
  • If you specify an activity (such as Audiogram) and a selected user has availability associated with another activity (such as EKG) for the health center within the selected date range, then the user will not be displayed in the 'Availability' panel.  
  • If no activity is specified in the selected user's availability configuration, then the user will display in the 'Availability' panel.
  • If a selected user or users have scheduled availability for the single specified activity (for example, Mondays 9-12 for the Audiometric activity) and the duration specified for that activity on its 'Schedule Activities' look-up table record is 20 minutes, the slots rendered on the 'Availability' panel will all be for 20 minutes.
  • It is best practice to ensure that in the 'Schedule Activities' look-up table each activity has a specified duration, because when one or more activities is selected, their duration(s) will drive the length of the available timeslots and the overall availability that is shown. For example, if the duration of an Audiogram is 20 minutes, the duration of Drug Testing is 30 minutes, and you specify both for 'Activities', the timeslots of availability shown will all be for 50 minutes. Note: If a duration is not defined for an activity on its 'Schedule Activities' look-up table record, then the 'Availability Finder' will assign a default duration of 30 minutes to that activity.
  • If you select one or more activities and book a timeslot, then extend the duration value for any of those activities on the schedule entry / appointment record using the Duration field, the booked timeslot will then extend into the slot following it (and the slot following that, etc., if long enough), reserving each and removing each from availability. This is the case even if, for example, only 5 minutes of the last timeslot required is needed. Conversely, if you reduce the duration value for an activity manually on the schedule entry / appointment record using the Duration field, therefore a full timeslot is no longer required, the full timeslot will still remain booked. This logic was implemented to eliminate confusion that might occur if after the change some timeslots would otherwise have odd times that would affect adjacent timeslots. Note: It is best practice to set up the duration for each activity in the 'Schedule Activities' look-up table before using the new 'Availability Finder' tab and to not change those durations after you start using it. You might want to consider making it a policy to lock the duration on the schedule entry / appointment record.
  • It is best practice to ensure availability is configured properly (completely) for each user at each health center. If no availability is configured for a user, then all of that user's time will be available (from 12:00 am to 11:59 pm, every day). This follows the overall design of the Appointments module. Even if just one timeframe is configured (for example, one hour on a Monday, one hour each Monday, or all day each Monday), then only timeslots during that timeframe will be considered / shown as available. The user will not be available during any other timeslots.
  • For a timeslot for a particular user that is booked already (in the Appointments module), regardless of health center, that timeslot is considered unavailable and will not be shown/offered in the 'Availability' panel. With the 'Availability Finder' tab, you are looking for availability at a particular health center, but if the user is busy at another health center, he or she is of course considered busy regardless.
  • If you are planning to use the 'Availability Finder' tab for finding timeslots that can accommodate more than one activity, the 'Schedule Entry' layout used in the Appointments module must have multi-chip functionality. This means that either a clone of the 'Schedule Entry' (ML-000658) layout or a clone of your current layout with multi-select (multiple values) functionality enabled for the 'Activity' field must be used. Otherwise, you will lose any current multi-activity selections upon opening a time slot and the Schedule Entry layout would only render the first selected Activity in the Side bar menu.
  • Any timeslots booked using the 'Availability Finder' will apply in myCority. myCority will not display a timeslot as available if it been scheduled.

New Fields

  • The following two fields can be added to custom versions of the 'Schedule Entry' layout:
    • Equipment - a picklist to the 'Equipment' look-up table
    • Room - a picklist to the new 'Appointment Rooms' look-up table
    • Both picklists have the All Active (default), All Inactive, and All list views, and the list views for the Rooms look-up table have the Code, Description, and Health Center columns.
  • The look-up table has a new 'Appointment Room' layout with the standard look-up table layout functionality.
  • On the 'Health Center' look-up table layout, there is a new 'Linked Rooms' tab for linking rooms to the health center so the center filters on just those rooms. The rooms can be added from the 'Appointment Rooms' look-up table.
  • When scheduling an appointment and using the 'Schedule Entry' layout, once a health center is specified, the 'Rooms' picklist will show just the items linked to that health center. If no health center is selected, the picklist will show all Rooms depending on the view.
  • Note: You cannot reserve a piece of equipment or room using the Appointments functionality or 'Availability Finder' tab. The Equipment and Rooms functionality related to schedule entries is simply for recording purposes. You can however create a user in the Appointments module for a piece of equipment or room and reserve them that way. If you want help configuring that, contact your Cority Professional Services Representative for assistance.
  • The following standard user-defined fields (UDFs) can now be added to custom versions of the 'Schedule Entry' layout:
    • 6 new alphanumeric UDF fields
    • 6 new date/time UDF fields
    • 6 new flag (check box) fields
    • 6 new look-up table UDF fields
  • For each new look-up table field, an accompanying LU_SCH_UDF look-up table has been created.
  • These new fields are all configurable using the standard UDF field functionality. For information on working with UDF fields, see the Cority User Guide.

Bulk Cancellation of Appointments

  • The actions menu in the Appointments module has a new 'Cancel Multiple Appointments' option.
    • To use this, the user's role must be granted the scheduleentry.multicancel security action.
    • When the action is selected, a dialog box will open. The dialog box will allow the user to specify a time period during which all appointments will be cancelled.
  • Important: Appointments scheduled during the specified time frame that have multiple activities (for example, both Consultation and Scrum) cannot be cancelled by the 'Cancel Multiple Appointment' action. Such appointments have to be cancelled individually.

Multi-Select Support and Enhanced Completion Logic

  • On a custom version of the 'Schedule Entry' layout (ML-000658), the 'Activity' field can now be configured to support multi-select of up to 30 activities.
    • Simply open the custom layout in layout configuration, and for the 'Activity' field, click the 'Enable Multi Select' check box.
  • Important: For customers who will have more than one activity for one or more schedule entries, we strongly recommend configuring and using a custom 'Schedule Entry' layout with:
    • Multi-select enabled for the 'Activity' field
    • An 'Additional Activities' tab (sublist) added
  • There is a new global 'Mark schedule entries complete only if all linked activities are complete' system setting, categorized under the Scheduling module.
  • By default, the setting is not selected.
  • For a schedule entry, when the check box is selected and more than one activity is specified:
    • If all the selected activities are linked activities, the entry is marked 'Complete' once each single activity is complete (that is, for the employee there is a corresponding record for each activity with Test Date = scheduled date).
    • If one or more of the selected activities are non-linked, the entry must manually be marked 'Complete' by the user.

New BRA for Configuring Appointment Emails

  • There is a new business rule email action BRA-100542 that uses the 'Schedule Entry' entity.
  • This BRA enables you to change the hard-coded message that is emailed when an appointment is scheduled and emailed whenever the appointment is updated.
  • The BRA supports the use of merge fields, a single letter attachment, and additional recipients.
  • To support the use of this BRA, there is also a new global system setting named 'Define Appointments Email Notification Template', a new option in the 'Send Email' drop-down on the 'Schedule Entry' layout named 'Use Email Template', and a new action in the Actions menu of the 'Schedule Entry' layout named 'Send Email Template'.
  • The new system setting provides a picklist filtered to any active BRAs that use the 'Schedule Entry' entity and have 'Email' as their BRA type.
  • To use the new BRA:
  1. Clone, configure, and save a version of the BRA.
  2. Specify the BRA for the value of the new 'Define Appointments Email Notification Template' system setting.
  3. Select the 'Use Email Template' option from the 'Send Email' field drop-down on your Schedule Entry layout.
  • For more information on working with business rules and business rule actions, see the Cority User Guide.
  • Notes:
    • The hard-coded email message for 'Schedule Entry To-Dos' cannot yet be changed by a BRA.
    • When using this BRA, although the letter and PDF fields appear to be available, attachments are not supported. The .ics calendar file will continue to be sent with the email as an attachment, but it is the only attachment currently supported by this BRA logic.
      • In an upcoming release, we will add support for attaching letters and PDF forms to this BRA.
    • Similar to other business rule background email actions, the 'Send in Background' check box will remain editable by the user on cloned BRAs, even though if unchecked, the corresponding email prompt will not display on the front-end UI.

GDDLOFB Added to Schedule Entries

  • The standard GDDLOFB fields can now be added to cloned versions of the 'Schedule Entry' layout.
    • The values for the 'Schedule Entry' GDDLOFB fields will populate/update automatically when a value is provided for the record's 'Employee' field (or when the value for that field is updated).
  • Note: As always, any manual update(s) made by a user to GDDLOFB will override the previous value(s).
  • The addition of the GDDLOFB fields allows 'Schedule Entry' records to be site secured. To enable site security on 'Schedule Entry' records, the new schedule.applysitesecuritytoschedulentry security action must be granted to the user's role.

Impact to Existing Users:

  • The Appointments module is now more flexible and powerful.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
  • For specific information on working with the Appointments module, business rules and business rule actions, list view and layout configuration, or security roles and permissions, see the Cority User Guide.
