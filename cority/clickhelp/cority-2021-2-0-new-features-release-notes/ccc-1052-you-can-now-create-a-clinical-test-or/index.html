CCC-1052: You can now create a Clinical Test or Drug Test record using the Cority RESTful API and an HL7 file

  • The Cority RESTful API has two new post endpoints:
    • ClinicalTestImport
    • DrugTestImport
  • To access the desired endpoint, the user's role has to be granted the corresponding security action:
    • ClinicalTestSample.apiwrite
    • DrugTestSample.apiwrite
  • For the import, the following parameters will be accepted in the URL:
    • Clinical Test Standard - required, if not providing a Drug Test standard
      • Labcorp
      • Oxford
      • SourceHL7v23LabFile
      • Gamma Dyna Care
      • ASTM88
      • ASTM94
      • HL7v22
    • Drug Test Standard - required, if not providing a Clinical Test standard
      • Quest
      • SourceHL7v23LabFile
      • ASTM
      • Labcorp
      • Medtox
    • Laboratory (Look-up Table) - required
    • Health Center (Look-up Table) - required
    • Practitioner (Data Table)
  • Once an HL7 file has been provided to one of the two new endpoints, the following will occur:
    • The data will be delivered to the appropriate service (ClinicalTestImport or DrugTestImport).
    • A response with the results of the import (number of records added/updated/rejected) will be sent.
    • The results will be logged in the corresponding section (Clinical Test Import View or Drug Test Import View) of the Process Status and Log.
    • If the import is successful, the record(s) will be present in the corresponding module (Clinical Testing or Drug Testing).

Impact to Existing Users:

  • If HL7 files are available, this is a more efficient and convenient way to create Clinical Test and/or Drug Test records within Cority.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
