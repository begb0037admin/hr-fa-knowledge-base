CCC-2217: The Migrate Config functionality has been enhanced

  • When using the Migrate Config module to export or import layout configurations, that now includes:
    • Field labels
    • Default look-up table values for fields
    • Any corresponding translations for those items
  • For default look-up table values, when importing, if the look-up table entry does not exist in the target system and 'Update Existing Records' is specified, the entry will be created automatically.
  • If a custom layout has the dynamic field feature (through the 'Form Condition' entity) configured for one or more subsections or tabs (sublists), and Migrate Config is used to export or import the layout's configuration, that dynamic field configuration will be retained.
    • Example of the dynamic field feature: On a custom Clinic Visit layout, for the Discharge subsection, the Display Preferences are set to 'Visible' and the 'Unless Clinic Visit Status Field Value' option is set to 'Arrived'.
  • The Migrate Config module can now be used to export or import look-up tables.
  • Migrate Config will now successfully export or import dashboards, business rules, and questionnaires that have dependent subqueries.
    • For business rules (BRs) and business rule actions (BRAs):
      • If a BRA uses a distribution list, the distribution list and the BRA's use of it will have to be built independently of the export/import.
      • If a BR has an 'is contained in' condition that is dependent on the results of a subquery, the subquery and BR condition will have to be rebuilt after import.
      • If a 'Create Record' BRA is dependent on the results of a subquery, the subquery and dependency will have to be rebuilt after import.
      • If a 'Bulk Update' BRA is dependent on the results of a subquery, the subquery and dependency will have to be rebuilt after import.
  • Migrate Config can now be used to export and import Workflow configurations.
    • If 'Update Existing Records' is specified, any required statuses, look-up table entries, groups and teams, and layouts will all be created in the target environment if they do not already exist there. Note: For any 'Groups and Teams' records created this way, the employees will have to be added after import.
    • For Query Builder to successfully report on Workflows (using the Workflow look-up table entity), the ID column must be selected within the query.
  • Migrate Config can now be used to export users' settings configurations, including any assigned myCority modules and myCority questionnaires.
    • If a questionnaire does not exist in the target environment, and 'Update Existing Records' is specified, the questionnaire will be created in that environment.

Impact to Existing Users:

  • This will help administrators quickly and successfully:
    • Recreate these items (without having to rebuild them) in target environments
    • Sync all of their environments in an efficient manner
  • Note: The 2021.2 Migrate Config functionality is not compatible with reports or queries created prior to 2021.2. If you want to use the functionality with such reports, you will have to recreate them first.

Additional Configuration Considerations:

  • Beyond what is described above, no new configuration is required.
  • For more information on working with the Migrate Config module, see the Cority User Guide.
