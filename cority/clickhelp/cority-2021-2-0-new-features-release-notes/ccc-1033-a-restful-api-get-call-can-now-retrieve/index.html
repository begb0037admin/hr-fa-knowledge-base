CCC-1033: A RESTful API GET call can now retrieve data within a record that is two levels down

  • A RESTful API GET call can now retrieve data from a record's sublists. For examples: Findings & Actions and Questionnaires.
  • Also, the GET call can retrieve sublist data from two levels down. For example: Clinical Test Sample > Battery > Results.
  • The GET call must query for only one record and must specify the sublist(s).
    • For example, if the current call without requesting sublist data is [http://client.cority.com/api/clinicvisit/]<ID>, the new call could be [http://client.cority.com/api/clinicvisit/]<ID>?Sublists=vitalsigns,riskassessments&Fields=clinicalTests.sampledate,RiskAssessment.RiskAssessmentId.
  • In order for records to be returned, the GET call must specify the desired fields from each sublist.
    • For example: [http://client.cority.com/api/clinicvisit/]<ID>?Sublists=audiometricTests,riskAssessments,clinicalTests&Fields=Id,TreatmentDate&SublistFields=clinicalTests.sampledate,RiskAssessment.RiskAssessmentId.
  • The data that is populated will depend on the user's currently pinned view. The columns in the pinned view for the sublist will be populated with the requested, returned data.
  • To request a sublist within a GET call, the sublist must be specified using FormList.Name from the FormDto of the parent record. That is the default name of the sublist, with the spaces removed.
    • The same identifier must be used in GetOptions (url param) to specify that the sublist should be included, and the node must have the same format.
      • For example: [http://client.cority.com/api/clinicvisit/|http://client.cority.com/api/clinicvisit/]<ID>?Sublists=audiometricTests,riskAssessments,clinicalTests...
  • In the GET call's response, the list properties will be appended to the main record, with all of the sublist records. For example:

{code:java}

{

audiometricTests: [

{

Id: ..,

}],

riskAssessments: [

{

Id: ..,

}],{code}

  • Note: In a GET call, you cannot filter by a sublist field.
  • The following scenarios will generate an error, instead of returning data:
    • The request for sublist fields when the query is not for just a single record.
      • Error: "You can only request sublists or sublist fields when querying for a single record."
    • The request for a sublist that is incorrectly named or does not exist.
      • Error: "The following sublist names are invalid: CaseList."
    • The request for a sublist field that is incorrectly named or does not exist.
      • Error: "The following field names are invalid: CaseNumber."

Impact to Existing Users:

  • A RESTful API user can now make a GET call for a record requesting data that is one and/or two levels down.

Additional Configuration Considerations:

  • Beyond what is described above, no additional configuration is required.
