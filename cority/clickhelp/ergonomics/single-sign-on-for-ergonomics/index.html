Single Sign-On for Ergonomics

Single Sign-On (SSO) is a service that allows users to have one set of login credentials to access multiple web applications without the need to re-enter login credentials at each application. 

Cority uses the Security Assertion Markup Language (SAML) 2.0 protocol to enable applications to provide single sign-on for their users. The protocol  allows identity providers (IdP) to pass authorization credentials to service providers (SP). All communications between components are secured. Using SAML, your Active Directory or other internal security authority can serve as the identity provider when employees want to login to EMS. Once setup, the SAML SSO integration allows your employees to use Cority EMS applications without any authentication steps other than what they do every day to authenticate to their corporate network.

Currently, EMS supports SSO for the following applications: 

  • Management System
  • Chemical Management
  • Office Ergonomics Solution (OES)

How Single Sign-On Works

The following diagram illustrates how EMS authenticates users via Customer's Identity Provider.

Identity federation standards identify two operational roles in an Internet SSO transaction:

  • Identity Provider (IdP): An IdP, the Customer in this context, is the organization that provides user authentication service and the user information service utilizing the Customer’s corporate directory.
  • Service Provider (SP): An SP, EMS in this context, is referred to a vendor that hosts applications and accepts claims authorized by IdP. It provides software as a service to the users authenticated by IdP. EMS uses OpenAM, an open source software provided by ForgeRock, for its federated single sign-on solution.


  1. The user requests access to a protected resource and is directed to the Customer’s federation system.
  2. The system validates if the user is already authenticated or not. If the user is not already logged in, then the user is asked for credentials and then authenticated.
  3. This step is optional, and can be set to the user’s first, or given name. Assigned attributes can be included with assertion. See the table below.
  4. After successful authentication, Customer’s federation system prepares a SAML assertion with agreed upon attribute and sends it across to Cority’s SP for consumption. Cority’s SP consumes this SAML assertion and converts it into the tokens that the protected applications can understand.

SSO Login Methods

The user may log into the EMS system using any of the following methods, if methods are allowed and supported by Customer network security policies:

  1. SSO from inside the Customer network. The user logs into the Customer network when starting up the desktop computer that is connected to the network. Once authenticated by the network, those credentials are used to automatically log into the EMS system.  
  2. SSO from outside the Customer network using a VPN. When the user is outside the physical Customer network, the user can authenticate into the network through a VPN, if  the VPN is supported by the Customer network. Once authenticated by the network, those credentials are used to automatically log into the EMS system.
  3. SSO from outside the Customer network using a web page to authenticate into the network. When the user is outside the physical Customer network, a web page can be provided by the Customer SSO Solution to allow these remote users to authenticate into the network. This assumes the Customer network security policies allow such access, and the web page has been provided by the Customer for this use. Once authenticated by the network, those credentials are used to automatically log into the EMS system. 
  4. Bypassing SSO. Direct login to the EMS system from outside the Customer network. When users are physically outside the Customer network, they can use their EMS username and password to log directly into the EMS system. Bypassing the SSO method can be restricted by not providing EMS passwords to the users. 

Troubleshooting 

Problem Suggested solution
An error message "User does not exist in the system"  is displayed when trying to log in using SSO. Ensure that the user is added to the EMS system.
